# Роли администраторов

Когда в админку входит больше одного человека, а видеть всё должен не каждый (регистратор не открывает настройки, редактор не удаляет, наблюдатель только читает), включите **роли**. Они работают поверх [Policy](authorization.md) и построены на [spatie/laravel-permission](https://spatie.be/docs/laravel-permission) — пакет подключать необязательно, он нужен только сайтам с ролями.

Роли выключены по умолчанию: без них админка работает как раньше (нет Policy — можно всё).

## Как работает

Действие разрешено, только если разрешают **все три слоя**: роли администратора, метод ресурса [`can()`](authorization.md#ограничение-без-policy-can) и Policy модели. Запрет любого из них — запрет.

- Права называются `fastleo.{раздел}.{группа}`, например `fastleo.articles.update`. `{раздел}` — адрес раздела в админке (`/fastleo/articles`).
- Четыре группы:

| Группа | Что открывает |
|---|---|
| `view` | список, просмотр, [экспорт](import-export.md) (выгружаются все поля формы, не только столбцы списка) |
| `create` | «Создать», [импорт](import-export.md#импорт) |
| `update` | изменение, ручной порядок, восстановление из корзины, свои [действия](actions.md) |
| `delete` | удаление, удаление из корзины навсегда |

- Любая группа требует ещё и `view`: право на изменение без просмотра ничего не даёт.
- Права и роли — **только под guard `fastleo`**. Одноимённая роль или право сайта (guard `web`) в админке не действуют.
- **Владелец** — роль `fastleo-owner` (имя — `fastleo.roles.owner`) проходит все проверки ролей. Только владелец открывает «Администраторов», настройки, свои страницы, файловый менеджер, журнал ошибок, очистку кеша и страницу SoftNetica. Если сайт описал для них свой Gate (`manageFastleoFiles`, `viewFastleoLogs`, `clearFastleoCache`, `manageFastleoSoftNetica`) или метод `canAccess()` страницы — решает он, как и без ролей.
- Загрузка файлов в формах (картинки, файлы) и окно выбора файла в полях доступны тем, у кого есть просмотр и создание (или изменение) хотя бы в одном разделе; «Наблюдатель» файлы выбрать не сможет.
- Администратор без ролей ничего не может: пустая матрица — запрет.

## Как включить

1. Установите пакет и выполните его миграции:

```bash
composer require spatie/laravel-permission
php artisan vendor:publish --provider="Spatie\Permission\PermissionServiceProvider"
php artisan migrate
```

2. Добавьте трейт `HasRoles` в модель пользователя (у модели остаются роли и права сайта — fastleo трогает только guard `fastleo`):

```php
// app/Models/User.php
use Spatie\Permission\Traits\HasRoles;

class User extends Authenticatable implements FastleoUser
{
    use HasFastleoAccess;
    use HasRoles;
}
```

Режим `teams` в `config/permission.php` fastleo не поддерживает — оставьте `'teams' => false`.

3. Создайте роль-владельца и выдайте её себе — **до** включения ролей, чтобы не закрыть админку от самого себя (пока роли выключены, команда напомнит об этом предупреждением — так и должно быть):

```bash
php artisan fastleo:roles --owner=admin@site.ru --presets
```

Команда создаёт роль `fastleo-owner` (guard `fastleo`) и выдаёт её администратору. Без `--owner` она никого не повышает — запускайте её сколько угодно раз. Если владельцев не осталось, доступ возвращает запуск с `--owner=email`.

`--presets` создаёт готовые роли по разделам, которые есть на сайте сейчас: «Администратор» (все права), «Редактор» (просмотр, создание, изменение — без удаления) и «Наблюдатель» (только просмотр). Разделы доставки сообщений («Каналы», «Уведомления», «Публикации») получает только «Администратор»: с правом изменения там можно подставить свой бот или чат, и заявки с данными клиентов пойдут к нему. Роль ищется по названию: если она уже есть, команда её не трогает, и изменённые права не пропадут. Переименованная роль будет создана заново, поэтому `--presets` обычно запускают один раз; права на новые разделы ставятся в разделе «Роли».

4. Включите роли:

```php
// config/fastleo.php
'roles' => [
    'enabled' => true,
    'owner' => 'fastleo-owner',   // имя роли-владельца
],
```

Сбросьте кеш конфигурации, иначе включённые роли не подхватятся: `php artisan optimize:clear`.

5. Проверьте: `php artisan fastleo:doctor` покажет, чего не хватает (нет владельца, администраторы без ролей, нет прав у разделов).

Выключить роли — `'enabled' => false`: ограничения перестают действовать, все администраторы снова могут всё (`doctor` напомнит, если роли в базе остались).

## Раздел «Роли»

При включённых ролях в меню появляется раздел «Роли» (`/fastleo/roles`, только владельцу). У роли два поля:

- **Название.** Уникально среди ролей guard `fastleo`. Роли `web` вашего сайта раздел не показывает и не меняет.
- **Права по разделам.** Таблица: строки — разделы сайта, столбцы — «Просмотр», «Создание», «Изменение», «Удаление». Право на создание, изменение или удаление требует просмотра: галочка ставит его сама, а снятие просмотра убирает остальные права строки. Щелчок по названию раздела отмечает всю строку, по названию столбца — весь столбец. У раздела «только для чтения» бывает один просмотр.

В таблицу не входят «Администраторы» и «Роли» — ими управляет только владелец. Роль-владелец в разделе можно только посмотреть: изменить или удалить её нельзя. Права, которые вы завели сами (`fastleo.reports.export` для своего кода), раздел не трогает.

Выдать роль администратору — в разделе «Администраторы» (поле «Роли»). Удалённая роль пропадает у всех администраторов.

Раздел подключается ключом `roles.resource` ([конфигурация](configuration.md)): свой класс-наследник `Fastleo\Resources\RoleResource` или `null`, чтобы раздела не было и роли заводились только кодом. Свой класс подключайте именно настройкой, а не просто кладите в папку разделов: иначе у сайта окажутся два раздела с адресом `roles` и будет ошибка о повторном адресе. То же, если у вас уже есть свой раздел с адресом `roles`, — задайте `'resource' => null`.

## Роли из кода

Роли и права можно создавать и средствами spatie — например, сидером (guard — всегда `fastleo`):

```bash
php artisan make:seeder FastleoRolesSeeder
```

```php
// database/seeders/FastleoRolesSeeder.php
use Spatie\Permission\Models\Permission;
use Spatie\Permission\Models\Role;

public function run(): void
{
    $editor = Role::findOrCreate('editor', 'fastleo');
    $editor->syncPermissions(array_map(
        fn (string $name): Permission => Permission::findOrCreate($name, 'fastleo'),
        ['fastleo.articles.view', 'fastleo.articles.create', 'fastleo.articles.update', 'fastleo.categories.view'],
    ));

    $observer = Role::findOrCreate('observer', 'fastleo');
    $observer->syncPermissions(array_map(
        fn (string $name): Permission => Permission::findOrCreate($name, 'fastleo'),
        ['fastleo.articles.view', 'fastleo.categories.view'],
    ));
}
```

Редактор из примера видит статьи и категории, создаёт и меняет статьи, но не удаляет их и не открывает остальные разделы. Если у раздела есть связь с чужой таблицей (категория статьи), нужно и `view` этого раздела: иначе поле связи только для чтения — вариантов в форме и фильтре нет, под полем написано «Нет доступа к разделу …», новую запись выбрать нельзя, а привязанная раньше остаётся как есть. Если у модели несколько разделов (например, «Статьи» и «Новости» на одной модели), связь открыта, когда администратору открыт хотя бы один из них, а ссылка на связанную запись ведёт в первый открытый раздел (порядок — по имени файла ресурса; встроенные «Администраторы» идут последними). Надпись «Нет доступа к разделу …» называет первый раздел модели.

В форме администратора поле «Роли» — список галочек; в нём только роли guard `fastleo`, роли `web` оно не трогает. Нельзя оставить сайт без владельца: у последнего владельца не получится снять роль, отключить доступ в админку или удалить его — даже если два владельца делают это одновременно (владельцем считается тот, у кого есть и роль, и доступ в админку).

После смены прав перезапустите воркеры очереди (`php artisan queue:restart`): они держат кеш прав в памяти. Импорт и MCP-сервер сами перечитывают роли перед каждым запуском.

## Что не закрывают роли

- **Подписи связанных записей в списке и в экспорте** выводятся без проверки прав связанного раздела: закрыты варианты выбора в форме и фильтрах, а подпись уже привязанной записи видна. Не хотите, чтобы подпись была видна, — не показывайте столбец связи этой роли (`hideInList()`; `hidden()` убрало бы поле и из формы).
- **Вложенные записи** (`HasMany`, `HasOne`, блоки) пишутся правами родительского раздела, права на дочерний раздел при записи не спрашиваются.
- **Свой раздел или связь на таблицы ролей и прав** (`roles`, `permissions`, `model_has_roles`) обходит раздел «Роли»: роли должен менять только он. Не заводите такие связи и разделы, если раздел «Роли» включён.
- **Виджеты дашборда** — код сайта: проверяйте права внутри (`Authorization::allows('viewAny', $resource)`) или скрывайте виджет `->visible(fn ($user) => ...)`.
- Свой класс [действия](actions.md), переопределивший `allows()` без `parent::allows()`, обходит матрицу.
- MCP-сервер ([claude.md](claude.md#mcp-сервер)) работает от имени администратора и подчиняется тем же ролям.

## «Только свои записи»

Роль решает, в каких **разделах** администратор может что-то делать. Чтобы редактор видел только свои записи, ограничьте выборку раздела и поставьте автора при создании:

```php
// app/Fastleo/ArticleResource.php
public function query(Builder $query): Builder
{
    $user = Fastleo::guard()->user();

    return RoleMatrix::isOwner() ? $query : $query->where('author_id', $user?->getAuthIdentifier());
}
```

```php
// app/Observers/ArticleObserver.php — автор ставится при создании
public function creating(Article $article): void
{
    $article->author_id ??= Fastleo::guard()->id();
}
```

Запись вне выборки открыть, изменить или удалить нельзя (404) — подробнее [ограничение записей](authorization.md#ограничение-записей).
