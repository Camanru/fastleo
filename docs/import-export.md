# Экспорт и импорт

Раздел можно выгрузить в Excel (xlsx) или CSV и загрузить записи обратно из такого файла. Работают те же поля, что и в форме: выгружаются значения полей, а загруженные значения проходят те же проверки, что и при сохранении формы.

## Экспорт

Кнопка «Экспорт» в списке — выбрать xlsx или csv. Выгружается то, что сейчас показывает список (поиск, фильтры, сортировка, корзина), на всех страницах. Файл скачивается сразу, записи читаются из базы по 500 (подробнее про большие таблицы — [ниже](#большие-таблицы)).

Выключить экспорт раздела:

```php
protected static bool $exportable = false;
```

**Столбцы.** Первый — ключ записи (`id`), дальше поля формы и списка (в том числе `onlyInList()`) в порядке `fields()`. Заголовок столбца — подпись поля. Не выгружаются:

- вложенные блоки (`HasMany`, `HasOne`), JSON-поля (`Repeater`, `KeyValue`, `Blocks`) и пароль;
- поле, скрытое для этого администратора (`hidden()`);
- поле с `->exportable(false)`:

```php
Textarea::make('admin_note', 'Заметка для админов')->exportable(false),
```

**Значения.**

| Поле | В ячейке |
|---|---|
| `Text`, `Textarea`, `Email`, `Url`, `Slug`, `Code`, `Markdown`, `RichText` (HTML) | Текст как есть |
| `Number` | Число |
| `Checkbox`, `Toggle` | «Да» / «Нет» |
| `Select`, `Radio`, `Enum` | Подпись варианта («Опубликовано»); несколько — через запятую |
| `Date` | `2026-03-08` |
| `DateTime` | `2026-03-08 14:30` в часовом поясе админки |
| `Time` | `14:30` |
| `BelongsTo` | Ключ связанной записи |
| `BelongsToMany` | Ключи через запятую |
| `Tags` | Метки через запятую |
| `Image`, `File` | Путь на диске (`uploads/doctors/ivanov.jpg`) |
| `Color` | Код цвета (`#1e90ff`) |
| `Range` | Число |
| `Hidden` | Выгружается как есть — не храните в скрытых полях секреты |
| `Gallery` | Пути, каждый с новой строки |
| [Многоязычное](translations.md) (`translatable()`) | Столбец на язык: «Заголовок (RU)», «Заголовок (EN)» |

**CSV** — для русского Excel: UTF-8 с BOM, разделитель «;».

**Безопасность.**

- Значение, которое начинается с `=`, `+`, `-`, `@`, табуляции или перевода строки, не станет формулой: в xlsx текст всегда пишется текстовой ячейкой, в csv перед ним ставится `'`.
- Текст, похожий на число («007», «12.50» в текстовом поле), остаётся текстом.
- Право — метод `export` Policy модели, если он есть, иначе `viewAny` ([authorization.md](authorization.md)). Метод `export` заменяет `viewAny` целиком; для импорта нужны оба права (`import` и `viewAny`).
- Policy `view` по каждой записи при выгрузке не проверяется (как в Nova и Filament): ограничивайте выборку в [`query()`](resources.md#query). Замыкание `hidden(fn ($record) => …)` при выгрузке получает `null` вместо записи.

Столбцы `onlyInList()` (например `created_at`) в файле есть, но при загрузке файла обратно попадают в список «неизвестных» столбцов — их значения не записываются.

Ячейка Excel вмещает не больше 32 767 символов — более длинный текст обрезается в файле.

### Большие таблицы

Сначала читаются ключи записей в порядке списка, затем сами записи порциями по 500 по ключам — без смещения, поэтому порция из конца таблицы в 200 тысяч строк читается так же быстро, как первая. Лимит времени PHP на выгрузку не действует (`set_time_limit(0)`).

- **Формат.** csv отдаётся браузеру по мере записи, xlsx — только после сборки файла целиком (внутри это zip, он закрывается в конце). Для таблиц в сотни тысяч строк выбирайте csv: ответ не ждёт таймаута веб-сервера. Если нужен именно xlsx, поднимите таймаут для адресов админки: `fastcgi_read_timeout` в nginx и `request_terminate_timeout` у PHP-FPM.
- **Память.** Список ключей держится в памяти: около 80 МБ на миллион числовых ключей и около 200 МБ на миллион UUID (список строится в несколько проходов). Для ещё больших таблиц выгрузку делают командой по расписанию, а не из админки.
- **Свой `query()` ресурса.** Если запрос раздела соединяет таблицы (`join`), запись попадёт в файл один раз. Сортировка по столбцу, который `query()` задаёт сам через `select()` с псевдонимом, при выгрузке даёт ошибку SQL: читаются только ключи. Сортируйте по столбцам таблицы.

## Импорт

Включается в ресурсе:

```php
protected static bool $importable = true;
```

В списке появляется кнопка «Импорт»: выбрать файл xlsx или csv — и откроется страница загрузки с прогрессом и отчётом «создано / обновлено / пропущено» и списком пропущенных строк с причиной («Строка 12 — Заполните поле «Заголовок».»). В отчёте показаны первые 100 ошибок, а кнопка «Скачать все пропущенные строки (xlsx)» отдаёт файл со всеми: столбцы исходного файла и последний столбец «Ошибка». Исправьте строки и загрузите этот файл снова (столбец «Ошибка» при загрузке игнорируется, как любой неизвестный). Отчёт и файл видит только тот, кто загрузил импорт.

**Файл.** Первая строка — названия столбцов: подпись поля («Заголовок») или его имя (`title`), регистр не важен. Удобнее всего взять файл экспорта, поправить и загрузить обратно. Столбцы, которых нет среди полей, не загружаются (их список — в отчёте). Если нет ни одного известного столбца, импорт не выполняется. Читается только первый лист xlsx.

**Создание и обновление.**

- Строка со значением в столбце `id` обновляет запись с этим ключом; записи нет (или она не видна в разделе по `query()`) — строка пропускается. Пустой `id` или нет такого столбца — создаётся новая запись.
- Свой столбец сопоставления — `$importKey`: найдена запись с таким значением — обновляется, нет — создаётся. Столбец в файле называется как колонка (`sku`) или как подпись поля с этим именем; поле может быть `readonly()` (или его нет в `fields()`) — тогда значение только ищется и не меняется, а строка с ненайденным значением пропускается («Записи с ключом … нет»): новая запись осталась бы без ключа. Без такого столбца каждая строка создаёт новую запись. Столбец `id` при своём ключе не используется.

```php
protected static bool $importable = true;
protected static ?string $importKey = 'sku';   // артикул товара
```

- При обновлении меняются только поля, чьи столбцы есть в файле. При создании отсутствующие столбцы получают значение по умолчанию поля (`default()`), а без него — значение базы.
- Новая запись встаёт в конец [ручного порядка](resources.md#ручной-порядок).

**Проверки — как в форме.** Загружаются только поля, которые администратор может менять в форме (не `readonly()`, не скрытые, не `exportable(false)`, не вложенные блоки и JSON-поля и не пароль). Значения проходят правила полей (`required()`, `rules()`, автоматические) и ту же обработку, что в форме: HTML поля `RichText` очищается так же (`script`, `on*`, `javascript:` удаляются; у наследника работает его `sanitize()`), запись — через Eloquent (`fill()` → `save()`, observers работают), каждая строка — в своей транзакции. Строка с ошибкой (проверка, ошибка базы, отмена сохранения моделью) пропускается, остальные сохраняются. Пустые строки пропускаются молча.

**Значения в ячейках** — как при экспорте, плюс:

| Поле | Понимает |
|---|---|
| `Checkbox`, `Toggle` | «Да» / «Нет», `1` / `0`, `true` / `false`, `yes` / `no`, «+» / «-»; пусто — «Нет» |
| `Select`, `Radio`, `Enum` | Подпись или значение варианта, без учёта регистра; несколько — через запятую |
| `Date` | Дата Excel, `2026-03-08`, `08.03.2026` |
| `DateTime` | Дата Excel, `2026-03-08 14:30`, `08.03.2026 14:30` (время в поясе админки) |
| `Time` | Время Excel, `14:30`, `14:30:00` |
| `Tags`, `BelongsToMany`, `Select::multiple()` | Значения через запятую |
| `Gallery` | Пути с новой строки или через запятую |

Значение вне вариантов или неверная дата — ошибка строки.

**CSV.** Кодировка UTF-8 (с BOM или без) или Windows-1251 — так сохраняет русский Excel; разделитель «;», «,» или табуляция — определяется по первой строке. `'` перед формулой, который ставит экспорт, снимается.

**Длинный текст.** Excel обрезает ячейку до 32 767 символов. Если загружается такой обрезанный текст, а в записи — более длинный, начинающийся с него, значение записи не меняется (выгрузили, поправили другое поле, загрузили — текст не потерян).

**Права.** Загрузить файл можно с правом `import(User $user)` Policy, если такой метод есть, иначе с `viewAny`. Каждая строка дополнительно проверяет `create` (новая запись) или `update` (существующая) — как форма ([authorization.md](authorization.md)). Строка без права пропускается. В разделе [только для просмотра](resources.md#только-просмотр) импорта нет.

**Очередь.** Импорт выполняется задачей `Fastleo\Imports\ImportRecords`: с очередью — в фоне (страница показывает прогресс), без неё (`sync`) — сразу при загрузке. Ориентир скорости — 400–700 строк в секунду (раздел на 30 полей, MySQL или PostgreSQL): файл на 50 000 строк загружается 1,5–2 минуты. Без очереди это дольше обычных лимитов времени запроса (`max_execution_time` PHP, `fastcgi_read_timeout` nginx), и импорт оборвётся на середине — для файлов больше нескольких тысяч строк включите очередь ([installation.md](installation.md#очередь-на-хостинге-с-одним-cron): там же рецепт для хостинга только с cron). `retry_after` соединения очереди должен быть больше `3600` с — иначе файл, который грузится дольше полутора минут (у `database` по умолчанию `retry_after` 90 с), очередь отдаст второму обработчику, и импорт упадёт; `fastleo:doctor` предупреждает об этом.

**Безопасность.**

- Принимаются только `.xlsx` и `.csv` не больше `fastleo.import.max_size` (10 МБ). Файл сохраняется на закрытый диск `fastleo.import.disk` (`local`) под случайным именем и удаляется после импорта.
- Обрабатывается не больше `fastleo.import.max_rows` (50 000) строк — остальные не загружаются, отчёт об этом говорит.
- Файл xlsx после распаковки не больше `fastleo.import.max_unpacked` (200 МБ): маленький архив, который разворачивается в гигабайты, отклоняется.
- Если воркер оборвал задачу (время, память, остановка), импорт получает статус «ошибка», файл удаляется, администратор видит уведомление.
- Задача в очереди перед запуском проверяет, что у загрузившего всё ещё есть доступ в админку; иначе импорт завершается ошибкой.
- Строка, в которой есть только свой ключ (`importKey`) записи, которой нет, не создаёт пустую запись — это ошибка строки.
- Отчёты хранятся `fastleo.import.keep_days` (30) дней и удаляются при следующем импорте вместе с файлом пропущенных строк.
- В модель попадают только поля ресурса: столбец `internal_code` или `parent_id` без поля в ресурсе не загрузится.

Ограничения: вложенные блоки (`HasMany`, `HasOne`) и JSON-поля (`Repeater`, `KeyValue`, `Blocks`) не выгружаются и не загружаются.
