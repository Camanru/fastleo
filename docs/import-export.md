# Экспорт и импорт

Раздел можно выгрузить в CSV и загрузить записи обратно из такого файла. Работают те же поля, что и в форме: выгружаются значения полей, а загруженные значения проходят те же проверки, что и при сохранении формы.

**Excel (xlsx) отключён.** Сейчас выгрузка, загрузка и файл пропущенных строк работают только с CSV — он открывается в Excel (см. [CSV](#csv)). Формат xlsx дорабатывается, поэтому настройка `fastleo.xlsx` по умолчанию `false`, и включать её не нужно.

## Экспорт

Кнопка «Экспорт» в списке выгружает CSV. Выгружается то, что сейчас показывает список (поиск, фильтры, сортировка, корзина), на всех страницах. Файл скачивается сразу, записи читаются из базы по 500 (подробнее про большие таблицы — [ниже](#большие-таблицы)).

Выключить экспорт раздела:

```php
protected static bool $exportable = false;
```

### Столбцы

Первый — ключ записи (`id`), дальше поля формы и списка (в том числе `onlyInList()`) в порядке `fields()`. Заголовок столбца — подпись поля. Не выгружаются:

- вложенные блоки (`HasMany`, `HasOne`), JSON-поля (`Repeater`, `KeyValue`, `Blocks`, `Seo`), пароль и секрет (`Password`, `Secret`);
- поле, скрытое для этого пользователя (`hidden()`);
- поле с `->exportable(false)`:

```php
Textarea::make('admin_note', 'Заметка для пользователей')->exportable(false),
```

### Значения

| Поле | В ячейке |
|---|---|
| `Text`, `Textarea`, `Email`, `Url`, `Slug`, `Code`, `Markdown`, `RichText` (HTML) | Текст как есть |
| `Number` | Число |
| `Checkbox`, `Toggle` | «Да» / «Нет» |
| `Select`, `Radio`, `Enum` | Подпись варианта («Опубликовано»); несколько — через запятую |
| `Date` | `2026-03-08` |
| `DateTime` | `2026-03-08 14:30` в часовом поясе панели |
| `Time` | `14:30` |
| `BelongsTo` | Ключ связанной записи |
| `BelongsToMany` | Ключи через запятую |
| `MorphTo` | `адрес-раздела:ключ` (`articles:5`) |
| `Tags` | Метки через запятую |
| `Image`, `File` | Путь на диске (`uploads/products/kettle.jpg`) |
| `Color` | Код цвета (`#1e90ff`) |
| `Range` | Число |
| `Hidden` | Выгружается как есть — не храните в скрытых полях секреты |
| `Gallery` | Пути, каждый с новой строки |
| [Многоязычное](translations.md) (`translatable()`) | Столбец на язык: «Заголовок (RU)», «Заголовок (EN)» |

### CSV

Для русского Excel: UTF-8 с BOM, разделитель «;».

### Безопасность и права

- Значение, которое начинается с `=`, `+`, `-`, `@`, табуляции или возврата каретки, не станет формулой: перед ним ставится `'` (при загрузке этого файла обратно он снимается).
- В xlsx текст, похожий на число («007», «12.50» в текстовом поле), остаётся текстом. В csv типов ячеек нет: Excel при открытии файла прочтёт «007» как число 7, длинный артикул — как «4,6E+12», а «12.50» — как дату, и сохранённый им csv вернёт уже испорченные значения. Чтобы не потерять нули, открывайте csv через «Данные → Из текста/CSV» с типом столбца «Текст» или правьте файл в LibreOffice и Google Таблицах.
- Право — метод `export` Policy модели, если он есть, иначе `viewAny` ([authorization.md](authorization.md)). Метод `export` заменяет `viewAny` целиком; для импорта нужны оба права (`import` и `viewAny`).
- Policy `view` по каждой записи при выгрузке не проверяется: ограничивайте выборку в [`query()`](resources.md#query). Замыкание `hidden(fn ($record) => …)` при выгрузке получает `null` вместо записи.

Столбцы `onlyInList()` (например `created_at`) в файле есть, но при загрузке файла обратно попадают в список «неизвестных» столбцов — их значения не записываются.

Ячейка Excel вмещает не больше 32 767 символов: более длинный текст из csv Excel при открытии обрежет (сам файл ничего не обрезает).

### Большие таблицы

Сначала читаются ключи записей в порядке списка, затем сами записи порциями по 500 по ключам — без смещения, поэтому порция из конца таблицы в 200 тысяч строк читается так же быстро, как первая. Лимит времени PHP на выгрузку не действует (`set_time_limit(0)`).

- **Формат.** csv отдаётся браузеру по мере записи, поэтому ответ не ждёт таймаута веб-сервера. (xlsx, если его включить, собирается целиком до отправки; тогда поднимите таймаут для адресов панели: `fastcgi_read_timeout` в nginx и `request_terminate_timeout` у PHP-FPM.)
- **Память.** Список ключей держится в памяти: около 80 МБ на миллион числовых ключей и около 200 МБ на миллион UUID (список строится в несколько проходов). Для ещё больших таблиц выгрузку делают командой по расписанию, а не из панели.
- **Свой `query()` ресурса.** Если запрос раздела соединяет таблицы (`join`), запись попадёт в файл один раз. Сортировка по столбцу, который `query()` задаёт сам через `select()` с псевдонимом, при выгрузке даёт ошибку SQL: читаются только ключи. Сортируйте по столбцам таблицы.

## Импорт

Включается в ресурсе:

```php
protected static bool $importable = true;
```

В списке появляется кнопка «Импорт». Выберите файл csv — откроется страница загрузки с прогрессом, а в конце отчёт: «создано / обновлено / пропущено» и пропущенные строки с причиной («Строка 12 — Заполните поле «Заголовок».»).

- В отчёте видны первые 100 ошибок. Кнопка «Скачать все пропущенные строки (csv)» отдаёт файл со всеми: столбцы исходного файла и последний столбец «Ошибка». В файле не больше 5 000 000 ячеек (строка файла занимает столько ячеек, сколько столбцов в заголовке); если пропущенных строк больше, файл обрывается, а его последняя строка говорит об этом.
- Исправьте строки в этом файле и загрузите его снова — столбец «Ошибка» при загрузке игнорируется, как любой неизвестный.
- Отчёт и файл видит только тот, кто загрузил импорт.

### Файл

Удобнее всего взять файл экспорта, поправить и загрузить обратно.

- Первая строка — названия столбцов: подпись поля («Заголовок») или его имя (`title`), регистр не важен.
- Столбцы, которых нет среди полей, не загружаются (их список — в отчёте). Если нет ни одного известного столбца, импорт не выполняется.

### Новая запись или обновление

По умолчанию запись ищется по столбцу `id`:

| В файле | Что произойдёт |
|---|---|
| в `id` есть ключ, запись найдена | запись обновляется |
| в `id` есть ключ, записи нет (или она не видна в разделе по `query()`) | строка пропускается |
| `id` пустой или такого столбца нет | создаётся новая запись |

Искать по своему столбцу (артикулу, коду) — `$importKey`:

```php
protected static bool $importable = true;
protected static ?string $importKey = 'sku';   // артикул товара
```

| В файле | Что произойдёт |
|---|---|
| запись с таким `sku` найдена | запись обновляется |
| записи с таким `sku` нет | создаётся новая запись |
| записи нет, а поле ключа не загружается (`readonly()`, скрыто, `exportable(false)` или его нет в `fields()`) | строка пропускается с ошибкой «Записи с ключом … нет»: новая запись осталась бы без ключа |
| запись с таким ключом есть, но раздел её не показывает (она в корзине или вне `query()`) | строка пропускается с ошибкой «Запись с ключом … есть, но раздел её не показывает»: новая стала бы дублем |
| записи нет, а в строке, кроме ключа, ничего не заполнено | строка пропускается с той же ошибкой: пустая запись не создаётся |
| ячейка `sku` пустая | создаётся новая запись |
| столбца `sku` в файле нет | каждая строка создаёт новую запись |

- **Ключ должен быть уникальным в разделе.** Если у двух записей одинаковый `sku` (один артикул у разных поставщиков), строка обновит одну из них, и чужая запись изменится молча. Составной ключ («поставщик + артикул») храните отдельной уникальной колонкой (`import_key` = `{supplier_id}:{sku}`, заполняет observer модели) и укажите её в `$importKey`.
- Столбец ключа называется как колонка (`sku`) или как подпись поля с этим именем. Поле ключа `readonly()` (или его нет в `fields()`) значение только ищет и не меняет.
- Столбец `id` при своём ключе не используется.
- При обновлении меняются только поля, чьи столбцы есть в файле.
- При создании отсутствующие столбцы получают значение по умолчанию поля (`default()`), а без него — значение базы.
- Новая запись встаёт в конец [ручного порядка](resources.md#ручной-порядок).

### Проверки — как в форме

Каждая строка записывается так же, как форма: те же поля, те же правила, через Eloquent.

- Загружаются только поля, которые пользователь может менять в форме. Не загружаются: `readonly()`, скрытые, `exportable(false)`, вложенные блоки, JSON-поля и пароль.
- Значения проходят правила полей (`required()`, `rules()`, автоматические).
- HTML поля `RichText` очищается так же, как в форме (`script`, `on*`, `javascript:` удаляются; у наследника работает его `sanitize()`).
- Запись — через `fill()` → `save()`, observers работают; каждая строка — в своей транзакции.
- Строка с ошибкой (проверка, ошибка базы, отмена сохранения моделью) пропускается, остальные сохраняются. Пустые строки пропускаются молча, но номера строк в отчёте считаются по файлу, как в Excel.
- В модель попадают только поля ресурса: столбец `internal_code` или `parent_id` без поля в ресурсе не загрузится.

### Значения в ячейках

Как при экспорте, плюс:

| Поле | Понимает |
|---|---|
| `Checkbox`, `Toggle` | «Да» / «Нет», `1` / `0`, `true` / `false`, `yes` / `no`, «+» / «-»; пусто — «Нет» |
| `Select`, `Radio`, `Enum` | Подпись или значение варианта, без учёта регистра; несколько — через запятую |
| `Date` | Дата Excel (в xlsx), `2026-03-08`, `08.03.2026` |
| `DateTime` | Дата Excel (в xlsx), `2026-03-08 14:30`, `08.03.2026 14:30` (время в поясе панели) |
| `Time` | Время Excel (в xlsx), `14:30`, `14:30:00` |
| `Tags`, `BelongsToMany`, `Select::multiple()` | Значения через запятую |
| `MorphTo` | `адрес-раздела:ключ`; делится по первому двоеточию |
| `Gallery` | Пути с новой строки или через запятую |

Значение вне вариантов или неверная дата — ошибка строки.

- **CSV:** кодировка UTF-8 (с BOM или без) или Windows-1251 — так сохраняет русский Excel; разделитель «;», «,» или табуляция определяется по первой строке. `'` перед формулой, который ставит экспорт, снимается.
- **Длинный текст:** Excel обрезает ячейку до 32 767 символов. Если загружается такой обрезанный текст, а в записи — более длинный, начинающийся с него, значение записи не меняется (выгрузили, поправили другое поле, загрузили — текст не потерян).

### Права

- Загрузить файл можно с правом `import(User $user)` Policy, если такой метод есть, иначе с `viewAny`; открыть раздел (`viewAny`) нужно в любом случае, поэтому `import` не заменяет `viewAny` ([authorization.md](authorization.md)).
- Каждая строка дополнительно проверяет `create` (новая запись) или `update` (существующая) — как форма. Строка без права пропускается.
- В разделе [только для просмотра](resources.md#только-просмотр) импорта нет.

### Большие файлы и очередь

Импорт выполняется задачей `Fastleo\Imports\ImportRecords`: с очередью — в фоне (страница показывает прогресс), без неё (`sync`) — сразу при загрузке. Скорость — 400–700 строк в секунду (раздел на 30 полей, MySQL или PostgreSQL): файл на 50 000 строк грузится 1,5–2 минуты.

Для файлов больше нескольких тысяч строк:

1. **Включите очередь.** Без неё загрузка длится дольше обычных лимитов запроса (`max_execution_time` PHP, `fastcgi_read_timeout` nginx), и импорт оборвётся на середине. Хостинг только с cron — [рецепт](installation.md#очередь-на-хостинге-с-одним-cron).
2. **Поставьте `retry_after` соединения очереди больше `3600` с.** У `database` по умолчанию 90 с: файл, который грузится дольше полутора минут, очередь отдаст второму обработчику, и импорт упадёт. `fastleo:doctor` предупреждает об этом.

### Безопасность

- Принимаются только `.csv` не больше `fastleo.import.max_size` (10 МБ). Файл сохраняется на закрытый диск `fastleo.import.disk` (`local`) под случайным именем и удаляется после импорта.
- Обрабатывается не больше `fastleo.import.max_rows` (50 000) строк — остальные не загружаются, отчёт об этом говорит.
- В csv в записи не больше ячеек, чем столбцов в Excel (16 384): запись из миллиона запятых исчерпала бы память воркера. Запись считается так, как её читает читалка: перевод строки внутри кавычек не заканчивает запись, поэтому запись, растянутая на много строк файла, тоже проверяется целиком; длинный текст в кавычках с запятыми и переводами строк пределу не мешает.
- Пока xlsx отключён (`fastleo.xlsx` = `false`), следующие пределы не действуют; они защищают чтение xlsx, если формат включить. Файл xlsx после распаковки не больше `fastleo.import.max_unpacked` (200 МБ): маленький архив, который разворачивается в гигабайты, отклоняется. В каждой строке листа не больше 1000 ячеек, столбец (в `dimension` листа, `spans` строки и адресе ячейки) не дальше последнего столбца Excel (XFD), а строк не больше, чем вмещает Excel (1 048 576), и ни одна не стоит дальше последней. Кроме того, ограничена общая нагрузка на чтение: читалка xlsx на каждой строке заводит массив ячеек во всю ширину листа и копирует его на каждую ячейку, поэтому тысячи узких строк с одной ячейкой в последнем столбце так же тяжелы, как тысяча широких. Нагрузка оценивается по всему файлу (ячейки считаются и вне `<row>`, как их считает читалка; у ячейки без адреса `r` столбец на единицу правее предыдущей, как у читалки; в оценку входят и вставки текста `<t>` внутри одной ячейки или общей строки: читалка перебирает их за время, которое растёт как квадрат их числа) и не должна занимать воркер дольше примерно двух минут; таблица в 50 000 строк по 100 столбцов проходит. Файл тяжелее отклоняется с понятной ошибкой, до чтения. В архиве не больше 1000 записей, в книге не больше 256 листов и 1000 связей (читалка перечитывает связи книги для каждого листа, а защита открывает архив заново для каждой записи). Проверяются все файлы архива, какое бы имя и расширение они ни имели (в том числе с «#»); если в оглавлении архива имя повторяется, читается первая запись, как это делает читалка.
- Оценка знает не всё (например, при большом числе общих строк читалка держит их во временных файлах и открывает нужный на каждую ячейку), поэтому в самом импорте время чтения ещё и складывается: больше `fastleo.import.max_read_seconds` (600 с) — импорт останавливается с ошибкой, уже записанные строки остаются. Время записи в базу в эту сумму не входит.
- Выгрузка и загрузка — не чаще 10 раз в минуту на пользователя.
- Если воркер оборвал задачу (время, память, остановка), импорт получает статус «ошибка», файл удаляется, пользователь видит статус в отчёте импорта и уведомление в колокольчике (если он включён).
- Задача в очереди перед запуском проверяет, что у загрузившего всё ещё есть доступ в панель; иначе импорт завершается ошибкой.
- Отчёты хранятся `fastleo.import.keep_days` (30) дней и удаляются при следующем импорте вместе с файлом пропущенных строк.

## Ограничения

Вложенные блоки (`HasMany`, `HasOne`) и JSON-поля (`Repeater`, `KeyValue`, `Blocks`) не выгружаются и не загружаются.
