# Заявки

Встроенный раздел «Заявки»: форма на сайте (компонент `lead-form`) и приём заявок с других сайтов по API с ключами. Код лежит в пакете и обновляется вместе с ним, таблицы — `fastleo_leads` и `fastleo_lead_api_keys`. По умолчанию выключено, как [боты уведомлений](notifications.md#боты-telegram-и-max) и [публикации](publishing.md).

## Как включить

Таблицы создаёт `php artisan migrate` (они есть и при выключенном разделе). Включите раздел в `config/fastleo.php` (при закешированном конфиге и маршрутах — `php artisan config:cache` и `php artisan route:cache`: без этого новые адреса не появятся):

```php
'leads' => [
    'resource' => Fastleo\Leads\LeadResource::class,
],
```

Что появится:

- в меню — раздел **«Заявки»** (без группы, в верхней части меню рядом с «Дашбордом»; своя группа — `$group` в наследнике) с числом непросмотренных заявок; заявка считается просмотренной, когда её открыли;
- раздел **«Доступы для сайтов»** (группа «Настройки») и приём по API на `POST /api/leads`;
- обработчик формы сайта `POST /leads`.

Блок `leads` в вашем `config/fastleo.php` можно писать только с нужными ключами: недостающие берутся по умолчанию (в том числе `keys`). Выключить — вернуть `'resource' => null`: раздела, обработчиков и адресов нет (таблицы и заявки остаются). Остальные ключи блока:

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `leads.resource` | `null` | Класс раздела «Заявки»: `Fastleo\Leads\LeadResource::class` или ваш наследник; `null` — заявок нет совсем |
| `leads.keys` | `Fastleo\Leads\LeadApiKeyResource::class` | Раздел «Доступы для сайтов» и приём по API. Действует, только когда включён `resource`; `null` — приёма по API нет |
| `leads.form` | `true` | Принимать заявки с формы сайта (`POST path`); `false` — только API и раздел (тогда `<x-fastleo::lead-form />` работать не будет: нет адреса) |
| `leads.path` | `leads` | Адрес обработчика формы |
| `leads.api_path` | `api/leads` | Адрес приёма по API |

Только форма без API — `'keys' => null`; только API без формы — `'form' => false`:

```php
'leads' => [
    'resource' => Fastleo\Leads\LeadResource::class,
    'keys' => null,   // без «Доступов для сайтов» и приёма по API
    // 'form' => false, // без формы на сайте
],
```

Свой наследник раздела (например, другая группа в меню):

```php
// app/Fastleo/LeadResource.php
final class LeadResource extends \Fastleo\Leads\LeadResource
{
    protected static ?string $group = 'Продажи';
}

// config/fastleo.php: 'leads' => ['resource' => App\Fastleo\LeadResource::class]
```

Раздел «Заявки» не выгружается и недоступен через MCP: в заявках телефоны и почты посторонних людей. Права — как у остальных разделов: [Policy](authorization.md) модели `Fastleo\Leads\Lead` и [роли](roles.md).

## Форма на сайте

Положите на страницу компонент, он рисует поля, скрытую метку времени, поле-ловушку для ботов, ошибки и «Спасибо!». Он работает, пока заявки и форма включены (`leads.resource` и `leads.form`): иначе адрес формы не зарегистрирован и страница упадёт с ошибкой маршрута:

```blade
<x-fastleo::lead-form />
<x-fastleo::lead-form :with-email="true" button="Заказать звонок" />
```

Разметка без оформления — стилизуйте своим CSS (`class` и другие атрибуты передаются на `<form>`). Подписи по умолчанию русские; свои — атрибутами `button`, `sent`, `name-label`, `phone-label`, `email-label`, `message-label`. Поле почты по умолчанию скрыто (`:with-email="true"` покажет), поле сообщения показано (`:with-message="false"` уберёт). Страница с формой должна быть в группе `web` (сессия и CSRF).

Своя разметка — те же поля `name`, `phone`, необязательные `email` и `message`, `@csrf`, скрытое поле `form_token` и ловушка `leave_empty`:

```blade
<form method="post" action="{{ route('fastleo-leads.store') }}">
    @csrf
    <input type="hidden" name="form_token" value="{{ \Fastleo\Leads\FormToken::make() }}">
    <div style="position: absolute; left: -9999px;" aria-hidden="true"><input type="text" name="leave_empty" tabindex="-1" autocomplete="off"></div>
    <input name="name" value="{{ old('name') }}" required>
    <input name="phone" value="{{ old('phone') }}" required>
    <button>Отправить</button>
    @error('form_token') {{ $message }} @enderror
    @if (session('lead_sent')) Спасибо! @endif
</form>
```

После отправки посетитель возвращается на ту же страницу (`back()`); успех — `session('lead_sent')`, ошибки — стандартные `@error`.

- **Защита от ботов без внешних сервисов.** Скрытое поле-ловушка и зашифрованная метка времени показа формы, привязанная к сессии посетителя: метку, снятую с другой сессии, форма не принимает. Бот получает тот же ответ «Спасибо», но заявка не сохраняется. Форма, отправленная быстрее чем через 3 секунды или спустя больше суток, ботом не считается: живой посетитель видит ошибку и может повторить. Страница с формой не должна целиком кешироваться (CDN, «полностраничный кеш»): метка привязана к сессии посетителя, и общая метка на всех выдаст «слишком быстро». Нужна капча — сделайте свой обработчик формы (форма пакета её не проверяет).
- **Лимит:** не больше 5 заявок за 10 минут с одного адреса (`throttle:5,10,leads`, потом 429). **За прокси** (Cloudflare, nginx, tunnel) настройте `trustProxies` ([безопасность](security.md)), иначе лимит станет общим для всего сайта.
- **Что приходит с формы.** Только имя, телефон, почта и сообщение; статус, отметка «просмотрено», сайт и источник задаются кодом. Источник — путь страницы из заголовка `Referer`.

## Заявки с других сайтов по API

Лендинг, форма подрядчика или другой сервис отправляют заявку на `POST /api/leads` со своим ключом. Ключи выдаёт пользователь панели.

1. Откройте **«Настройки → Доступы для сайтов» → Создать**: название сайта («Лендинг про шины») и, по желанию, адрес сайта (`https://shiny.example`).
2. Откройте созданный доступ: там ключ и готовая **инструкция для разработчика сайта** (адрес, заголовки, поля, ответы, примеры) — скопируйте её целиком и отправьте разработчику.
3. Разработчик шлёт заявки с сервера сайта:

```bash
curl -X POST https://ваш-сайт.ru/api/leads \
  -H "Authorization: Bearer fllead_…" -H "Accept: application/json" \
  -d phone="+7 900 123-45-67" -d name="Иван" -d message="Нужны зимние шины" \
  -d form="Обратный звонок" -d page="https://shiny.example/zimnie"
```

Ответ `201 {"status": "created", "result": 57}` — в разделе «Заявки» появилась строка с названием сайта, формой и ссылкой на страницу.

| Код | Когда |
|---|---|
| 201 | заявка создана (`result` — её номер) |
| 200 `{"status": "duplicate"}` | такая же заявка (тот же ключ, телефон, сообщение и форма; имя и страница не считаются) пришла за последние 10 минут: новая не создана, повтор можно считать успешным |
| 401 `{"status": "unauthorized"}` | ключа нет, он неверный или выключен (ответ один и тот же, с заголовком `WWW-Authenticate: Bearer`) |
| 403 `{"status": "forbidden"}` | запрос из браузера с чужого сайта |
| 413 `{"status": "too_large"}` | тело запроса больше 16 КБ |
| 422 | поля не прошли проверку (в ответе `errors`) |
| 429 `{"status": "too_many_requests"}` | слишком много запросов с ключа или слишком много неверных ключей с адреса: `Retry-After` — через сколько секунд повторить |
| 503 | сайт закрыт для посетителей ([закрытие сайта](site-closing.md)): ответ `{"message": …}` без `status`, `Retry-After: 3600` |

Во всех ответах, кроме 201 и 200, есть `message` — причина простыми словами.

Поля: `phone` (обязательно), `name` (пусто — «Без имени»), `email`, `message` (до 2000 знаков), `page` (адрес страницы, `http(s)`), `form` (название формы). Значения — строки; лишние поля игнорируются, статус и название сайта ставит код.

- **Ключ** передаётся только в заголовке `Authorization: Bearer`, не в адресе и не в теле (они попадают в журналы). Утёк — «Перевыпустить ключ» в карточке доступа: старый перестаёт работать сразу. Выключить доступ — снять галочку «Принимать заявки». Ключ хранится зашифрованным (его видно в карточке) и с хешем для поиска; после смены `APP_KEY` его не расшифровать — перевыпустите.
- **Ключ в браузерном JavaScript виден любому посетителю** — шлите заявки с сервера сайта. Поле «Адрес сайта» делает так: запрос из браузера (с заголовком `Origin`) принимается только с этого сайта (хост без `www`). Это не защита: заголовок подделывается вне браузера, запросы с сервера проходят по одному ключу.
- **Лимиты.** С одним ключом — не больше 30 запросов в минуту и 1000 в сутки (потом 429). Неверные ключи с одного адреса — не больше 20 попыток в минуту; настоящие ключи эти попытки не затрагивают. **За прокси** настройте `trustProxies` ([безопасность](security.md)).
- **Без сессии.** Маршрут стоит в группе `api`: ни сессии, ни cookie, ни CSRF; закрытый сайт отвечает 503 JSON. Браузерным формам с другого домена нужен CORS: добавьте `api/*` в `paths` файла `config/cors.php`, если вы его публиковали. Если вы меняли группу `api` в `bootstrap/app.php`, проверьте, что в ней нет middleware с сессией.
- **Размер.** Тело больше 16 КБ отклоняется; на сервере задайте `client_max_body_size` (nginx) или `LimitRequestBody` (Apache). Если `Authorization` не доходит до PHP (Apache + FastCGI), добавьте в `.htaccess`: `RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]`.
- **Кто видит ключи.** Раздел «Доступы для сайтов» открыт только владельцу, когда сайт его знает (включены [роли](roles.md) или задан `Fastleo::resolveOwnerUsing()` — [права](authorization.md#владелец-и-owneronly)). **Без ролей и владельца ключи видят все пользователи панели**, как файлы и настройки. Раздел не выгружается, не импортируется и не виден MCP.
- **Хранение.** Заявки лежат в таблице, пока вы их не удалите: там телефоны и почты. Настройте очистку по расписанию и срок хранения, например в `routes/console.php`: `Schedule::call(fn () => \Fastleo\Leads\Lead::query()->where('created_at', '<', now()->subMonths(12))->delete())->daily();`.

## Уведомления

О каждой новой заявке `Fastleo::notifyAdmins()` сообщает пользователям панели во включённых [каналах](notifications.md): колокольчик, почта, боты Telegram/Max (**по умолчанию выключены**). Не больше 20 уведомлений в минуту на источник (форма и API считаются отдельно: утёкший ключ не заглушит форму): сверх лимита заявка сохраняется и видна в разделе, но без уведомления. В текст для бота попадают только имя (одной строкой, до 60 знаков) и телефон: сообщение и адрес страницы приходят от посторонних и в бота не идут. Сбой почты или бота не мешает принять заявку.

`fastleo:doctor` предупредит, если раздел «Заявки» включён, а колокольчик, почта и боты выключены (`leads_unnoticed`).

## Переход с копируемого модуля

До 4.10.0 заявки были готовым модулем `fastleo:module leads`: файлы копировались в `app/`, таблица называлась `leads`. Теперь модуля нет. Если он у вас стоит, он продолжает работать как код вашего сайта, но **не включайте `leads.resource`, пока он стоит**: раздел и адрес `/leads` у модуля и пакета совпадут. Чтобы перейти на встроенную часть:

1. Выполните `php artisan migrate` (появятся `fastleo_leads` и `fastleo_lead_api_keys`).
2. Перенесите данные вместе с номерами (`id`), чтобы старые ссылки на заявки в уведомлениях, письмах и Telegram вели на те же заявки: `INSERT INTO fastleo_leads (id, name, phone, email, message, source, status, read_at, created_at, updated_at) SELECT id, name, phone, email, message, source, status, read_at, created_at, updated_at FROM leads;` На PostgreSQL после этого сдвиньте счётчик номеров: `SELECT setval(pg_get_serial_sequence('fastleo_leads', 'id'), (SELECT max(id) FROM fastleo_leads));` (MySQL и SQLite делают это сами).
3. Проверьте, что заявки на месте (`SELECT count(*) FROM fastleo_leads`), и удалите файлы модуля: `app/Models/Lead.php`, `app/Enums/LeadStatus.php`, `app/Fastleo/LeadResource.php`, `app/Http/Controllers/LeadController.php`, `app/Http/Requests/StoreLeadRequest.php`, `database/factories/LeadFactory.php`, `routes/site/leads.php`, `tests/Feature/Site/LeadsTest.php`, виджеты в `app/Fastleo/Dashboard.php`. Миграцию `*_create_leads_table.php` можно оставить (на уже мигрированных сайтах она не запустится), а таблицу `leads` удалить позже, когда убедитесь, что всё перенесено.
4. Включите `leads.resource`. Форму замените на `<x-fastleo::lead-form />` либо в своей разметке поправьте адрес `route('site.leads.store')` → `route('fastleo-leads.store')` и метку `\App\Http\Requests\StoreLeadRequest::token()` → `\Fastleo\Leads\FormToken::make()`.

Если сама панель стоит на корне сайта (`fastleo.path` пустой), её адреса вида `POST /{раздел}` перехватят `POST /leads`: смените `leads.path`. Если на сайте уже есть **свой** приём заявок по API на адресе `/api/leads` (например, по [рецепту](recipes.md#заявки-с-сайта-и-из-телефонии)), встроенный приём и он не совмещаются: оставьте `leads.keys` равным `null` или смените `leads.api_path`.

## Классы

| Класс | Что |
|---|---|
| `Fastleo\Leads\LeadResource` | Раздел «Заявки» |
| `Fastleo\Leads\LeadApiKeyResource` | Раздел «Доступы для сайтов» |
| `Fastleo\Leads\Lead`, `LeadApiKey`, `LeadStatus` | Модели и статус (новая, в работе, выполнена, спам) |
| `Fastleo\Leads\FormToken` | Метка формы для своей разметки |
| `Fastleo\Leads\LeadNotifier` | Уведомление о заявке: `LeadNotifier::send($lead)` для формы, `LeadNotifier::send($lead, 'leads-notify-api')` для API (у каждого источника свой счётчик лимита) |
