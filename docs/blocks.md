# Конструктор страниц (Blocks)

Поле `Blocks` собирает страницу из блоков разных типов: текст, картинка, галерея, цитата, кнопка… Пользователь добавляет блоки из меню «Добавить блок» (в конец списка) или кнопкой «+» в шапке любого блока (сразу после него), заполняет, сворачивает, перетаскивает и удаляет. Сайт выводит блоки по порядку своими шаблонами.

## Поле

```php
use Fastleo\Fields\Block;
use Fastleo\Fields\Blocks;
use Fastleo\Fields\Gallery;
use Fastleo\Fields\Image;
use Fastleo\Fields\RichText;
use Fastleo\Fields\Text;
use Fastleo\Fields\Textarea;

Blocks::make('content', 'Содержимое')->blocks([
    Block::make('text', 'Текст')->icon('text')->fields([
        RichText::make('body', 'Текст')->required(),
    ]),
    Block::make('image', 'Картинка')->icon('image')->fields([
        Image::make('src', 'Картинка')->directory('pages')->variants('card')->required(),
        Text::make('caption', 'Подпись'),
    ]),
    Block::make('gallery', 'Галерея')->icon('images')->fields([
        Gallery::make('photos', 'Фотографии')->directory('pages')->variants('card'),
    ]),
    Block::make('quote', 'Цитата')->icon('quote')->fields([
        Textarea::make('text', 'Цитата')->required(),
        Text::make('author', 'Автор'),
    ]),
]),
```

**Колонка:** `$table->json('content')->nullable()` и **обязательно** каст в модели `'content' => 'array'`. Без каста сохранение остановится с понятной ошибкой.

**Хранение** — список блоков в порядке формы:

```json
[
    {"type": "text", "data": {"body": "<p>Магазин работает с 2005 года.</p>"}},
    {"type": "quote", "data": {"text": "Лучшие цены города.", "author": "Покупатель"}}
]
```

| Метод | Что делает |
|---|---|
| `blocks([...])` | Типы блоков (`Block::make()`) |
| `min(1)` | Не меньше стольких блоков (с `min` ≥ 1 поле обязательное) |
| `max(30)` | Не больше стольких блоков (по умолчанию 100) |

**Тип блока** — `Block::make('имя', 'Подпись')`:

| Метод | Что делает |
|---|---|
| `icon('image')` | [Иконка Lucide](https://lucide.dev/icons) в меню и заголовке блока |
| `fields([...])` | Поля и раскладка (`Grid`, `Section`) блока |

Имя типа — латиница в нижнем регистре, цифры и `_`, первой — буква (`text`, `photo_gallery`); оно же — имя шаблона на сайте. Повтор имени — ошибка описания.

**Список внутри блока** (тарифы, шаги «как снять», пункты преимуществ) — поле `Repeater` (или `Blocks`) среди полей блока: один уровень вложенности. Подробности и ограничения — в [Repeater](fields/repeater.md#список-внутри-элемента).

```php
Block::make('plans', 'Тарифы')->icon('list')->fields([
    Text::make('title', 'Название')->required(),
    Repeater::make('items', 'Что входит')->fields([
        Text::make('name', 'Пункт')->required(),
        Number::make('price', 'Цена, ₽'),
    ])->max(10),
]);
```

Данные блока — `{"title": "Базовый", "items": [{"name": "Осмотр", "price": "500"}]}`; шаблон блока на сайте получает `$items` обычным массивом.

**В блоке работают** простые поля (текст, числа, даты, списки, галочки, Tags, Code, Markdown, Color, Video), файлы (`Image`, `File`, `Gallery`), `RichText` и один вложенный `Repeater`/`Blocks`, а также `visibleWhen()` по полю того же блока. Не работают: связи, `HasMany`/`HasOne`, `KeyValue`, `Seo`, `Slug`, `Password`, `dependsOn()`, `hideOnCreate()`/`hideOnEdit()`/`hidden()`, `readonly()`/`disabled()` (блок сохраняется заново из формы — скрытое значение стёрлось бы), `translatable()`.

**Поведение и проверка.**

- Поля блока проверяются своими правилами («Заполните поле «Цитата».» под полем блока); заголовок блока с ошибкой — красный.
- Тип не из списка — ошибка. В блок попадают только поля его типа — лишние ключи из запроса отбрасываются.
- HTML полей `RichText` чистится, как в обычном поле ([rich-text.md](fields/rich-text.md)); для новых картинок `Image`/`Gallery` с `variants()` создаются варианты.
- Блок без полей (например, «Разделитель») — допустим.

**В форме** рядом с названием типа блока серым выводится его заголовок — поле `title` (или `name`), а если такого нет, первое простое текстовое поле типа (`Text`; `RichText`, `Textarea` и `Tel`/`Email` не берутся). Он обновляется при вводе и помогает найти нужный блок на длинной странице: «Преимущества — Почему с нами спокойно».

**В списке** поле не показывается; на странице просмотра — блоки по порядку с подписями. В Excel/CSV не выгружается.

## Вывод на сайте

```blade
{{-- resources/views/pages/show.blade.php --}}
<h1>{{ $page->title }}</h1>
<x-fastleo::blocks :blocks="$page->content" />
```

Каждый блок выводится шаблоном сайта `resources/views/blocks/{тип}.blade.php` (готовый модуль «Страницы» с публичной частью кладёт шаблоны `text`, `image`, `gallery` и `cta`, [модули](modules.md#публичная-часть)). Шаблон получает поля блока переменными, а также `$block` (все поля массивом) и `$type`:

```blade
{{-- resources/views/blocks/text.blade.php --}}
<div class="prose">{!! $body ?? '' !!}</div>

{{-- resources/views/blocks/image.blade.php --}}
<figure>
    <x-fastleo::picture :src="$src ?? null" preset="card" :alt="$caption ?? ''" />
    @if (! empty($caption))<figcaption>{{ $caption }}</figcaption>@endif
</figure>

{{-- resources/views/blocks/quote.blade.php --}}
<blockquote>{{ $text ?? '' }} @if (! empty($author)) — {{ $author }} @endif</blockquote>
```

- `{!! $body !!}` безопасен только для `RichText`: его HTML очищен при сохранении. Остальные поля выводите через `{{ }}`.
- Пишите `?? ''`/`?? []`: в блоках, сохранённых до добавления нового поля, его ещё нет.
- Блок типа без шаблона, с неверным именем типа или испорченными данными пропускается без ошибки — так старый тип, который убрали из ресурса, не ломает страницу.
- Имя типа — до 50 символов, не `type`. Не называйте подполя `type`, `block`, `__env`, `slot`, `errors`: эти имена перекрываются переменными шаблона. В шаблон блока попадают и служебные переменные (`$data`, `$view`, `$item`, `$prefix`), не называйте так поля. Поле, имя которого не начинается с латинской буквы (`_x`, `1a`) или занято Blade (`errors`, `obLevel`), в переменную не попадает: оно доступно только через `$block['имя']`.
- Блок известного типа собирается заново из формы: ключ, которого больше нет среди его подполей, при следующем сохранении записи стирается. Переименовали или убрали подполе — сначала перенесите данные миграцией. `emptyValue()` на подполе блока не поддерживается (ошибка при открытии раздела).
- Блоки типа, которого больше нет в `blocks()`, форма не показывает, но и не стирает: при сохранении записи в панели они остаются нетронутыми после остальных блоков (на сайте их по-прежнему пропускает `<x-fastleo::blocks>`). Вернёте тип в ресурс — блоки снова появятся в форме; убрать их совсем можно только миграцией данных.
- Готовый лендинг из 19 типов блоков — модуль `landing` ([лендинг](modules.md#лендинг)); он берёт папку `landing/sections`, а не `landing/blocks` из примера ниже: это разные папки, свои шаблоны с `prefix="landing.blocks"` им не мешают.
- Свои папки шаблонов — `prefix`: `<x-fastleo::blocks :blocks="$page->content" prefix="landing.blocks" />` → `resources/views/landing/blocks/{тип}.blade.php`.
