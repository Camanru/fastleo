# Безопасность

Панель открыта в интернет, поэтому пакет защищает вход, права, запись данных и файлы сам, без настройки. На этой странице — что именно защищено и что стоит сделать на сервере. Подробности — по ссылкам.

## Вход

- **Отдельный guard `fastleo`** (драйвер `session`) поверх пользователей сайта. Пускает только тех, у кого `canAccessFastleo()` возвращает `true` (по умолчанию — колонка `fastleo_admin`). Проверка идёт на **каждом** запросе: снятый флаг закрывает доступ сразу, без выхода ([установка](installation.md#2-модель-пользователя)).
- **Лимиты попыток**: 5 в минуту на пару «аккаунт + IP», 20 в минуту с IP, 50 в час на аккаунт. Одинаковый ответ для неверного пароля, несуществующего email и пользователя без доступа; время ответа тоже одинаковое: пароль хешируется и для несуществующего email. Попытка засчитывается до проверки пароля (одновременные запросы не проходят сверх лимита); успешный вход сбрасывает счётчики аккаунта, но не счётчик IP. Счётчики лежат в кеше приложения — на нескольких серверах нужен общий кеш (Redis, база).
  Счётчик «50 в час на аккаунт» защищает от перебора с многих адресов, но им же можно закрыть вход владельцу: пока лимит не истёк, не войти и с верным паролем (помогает cookie «Запомнить меня»). Часовую блокировку аккаунта (и ввода пароля, и шага кода 2FA) снимает `php artisan fastleo:unlock admin@site.ru`. Блокировку ввода пароля снимает и сброс пароля по ссылке из письма («Забыли пароль?»): письмо дойдёт только до владельца почты, так что вход можно вернуть без доступа к серверу; счётчик кода 2FA сброс не трогает; счётчики IP закончатся сами в течение минуты (или сбросьте всё `php artisan cache:clear`).
- **Точное совпадение email.** Варианты адреса, которые база считает равными («ádmin@» и «admin@» в MySQL), не входят: пароль для них не проверяется. Счётчик попыток у такого адреса свой, по хешу введённого текста, и по ответу «слишком много попыток» нельзя узнать, есть ли настоящий аккаунт.
- **Заголовки безопасности** ставятся на все ответы панели, включая перенаправление гостя на вход и ответ 401: `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `X-Robots-Tag: noindex, nofollow`, `Cache-Control: no-store, private` (переход на миниатюру в менеджере файлов браузер помнит 5 минут: он ведёт на публичный файл). Заголовков нет на ответах, которые Laravel отдаёт до маршрута панели: несуществующий адрес (404), неверный метод (405), слишком большой запрос (413).
- **«Запомнить меня»** держит вход `auth.remember_days` дней (30): срок задан только в сроке жизни cookie (так устроен Laravel), поэтому украденное значение cookie работает, пока пользователь не выйдет или не сменит пароль — оба действия отменяют его.
- **Новая сессия** после входа, выход — только POST с CSRF-токеном. После входа панель возвращает только на свои страницы: адрес возврата, который записал сайт (`url.intended`), другая страница сайта или чужой домен игнорируются. Ошибка хеширования (пароль длиннее предела `hashing.bcrypt.limit`, хеш чужого алгоритма) для входа — обычный «неверный пароль», а не ошибка 500.
- **Смена пароля завершает вход на всех устройствах** (middleware `AuthenticateSession`), кнопка «Выйти на других устройствах» — в профиле.
- **Двухфакторная защита** (TOTP + резервные коды): секрет зашифрован `APP_KEY`, коды хранятся хешами, код принимается один раз, у ввода кода свои лимиты. Можно сделать обязательной для всех: `auth.two_factor_required` ([вход и профиль](auth.md#двухфакторная-защита-2fa)).
- **Восстановление пароля** и действия профиля с проверкой пароля ограничены по частоте; ссылка сброса живёт `auth.reset_minutes` минут. Запрос ссылки и ввод нового пароля считаются отдельно, поэтому поток запросов на адрес владельца не закрывает ему ввод нового пароля по уже полученной ссылке; ответ на оба запроса занимает не меньше секунды (или `auth.timebox_duration`, если вы задали больше) и для существующего пользователя, и для неизвестного адреса, и для неверной ссылки, поэтому по скорости не узнать, есть ли такой пользователь. Секунда с запасом больше хеша пароля на обычном сервере (0,2–0,4 с); если хеш считается дольше секунды (стоимость bcrypt выше 14), увеличьте `auth.timebox_duration`.
- **Загрузка и выгрузка таблиц** (импорт, экспорт) — не чаще 10 раз в минуту на пользователя; в csv в записи не больше 16 384 ячеек (xlsx отключён, а его пределы описаны в разделе про импорт) ([импорт](import-export.md#безопасность)).
- **Письмо о входе с нового устройства** и история входов в профиле ([вход и профиль](auth.md#история-входов)).

## Права

- **Роли пользователей** (необязательные, [roles.md](roles.md)) проверяются на каждом действии раньше Policy: раздел «Пользователи», настройки, файлы и журнал ошибок — только владельцу (то же даёт `Fastleo::resolveOwnerUsing()` без ролей); права и роли — только guard `fastleo`; включено без трейта `HasRoles` — запрет.
- Права spatie гарда `web` с именами вроде `viewAny` или `delete` обходят Policy через его `Gate::before`; матрица ролей и `can()` остаются в силе, но Policy «только владелец» на таком сайте не сработает — не заводите права `web` с такими именами.
- **Policies моделей** проверяются на каждом действии: список, просмотр, создание, изменение, удаление, восстановление, порядок, экспорт, импорт, свои действия. Нет Policy — разрешено всё любому пользователю ([права](authorization.md)).
- Права на **вложенные записи** (HasMany, HasOne) и **варианты связей** (BelongsTo, BelongsToMany, MorphTo — у последнего ещё и `viewAny` раздела каждого типа) проверяются так же: в форму нельзя подставить чужую запись или запись, которой нет в списке вариантов ([права](authorization.md#связи-и-вложенные-записи)).
- **Ограничение записей** (`query()` ресурса) действует и в списке, и при открытии записи по адресу, и в поиске Ctrl+K.
- Встроенный раздел «Пользователи» не даёт снять доступ с себя и удалить последнего пользователя.
- **«Войти как»** (необязательно, выключено, [auth.md](auth.md#войти-как)): начинает только владелец, под пользователем без прав владельца; профиль, 2FA и «выйти на других устройствах» закрыты, подмена длится не дольше часа и перепроверяется на каждом запросе (владелец на месте, пароль не менялся); вход не пишется в историю входов.

## Запись данных

- В модель попадают **только поля из `fields()` ресурса**, видимые и не `readonly()`. Лишние поля запроса (`fastleo_admin`, `is_paid` и т. п.) отбрасываются ещё до `fill()`, `$fillable` модели — вторая линия защиты ([ресурсы](resources.md)).
- Запись идёт через Eloquent в транзакции: работают касты, мутаторы, observers и `SoftDeletes` сайта.
- Каждое значение проверяется правилами поля; часть правил поле ставит само (длина, формат, существование связанной записи).
- Все изменяющие запросы — POST/PUT/DELETE с CSRF-токеном.
- **Длинные списки в запросе.** Поля-списки принимают не больше своего предела: `Repeater`, `Blocks`, `KeyValue` и `Gallery` — 100 (меняется `max()`), `HasMany` — 200 (`max()`), `Tags` — 100, `BelongsToMany` и `Select::multiple()` — 1000 (фиксированные). Тело JSON не ограничено `max_input_vars`, а Laravel разворачивает правила `поле.*` по всему поддереву поля раньше проверки `max`, поэтому присланное значение ограничивается ещё до проверки: список обрезается до «предел + 1» (лишний элемент даёт ошибку `max`), то же внутри элементов `Repeater`, `Blocks`, `HasMany` и `HasOne`; массив там, где нужно простое значение, заменяется пустым (правило типа его отклонит), лишние ключи элемента сплющиваются. То же делают настройки, формы действий и ввод, который форма получает назад после ошибки (иначе следующее открытие формы рисовало бы все присланные блоки). Своё поле-список обязано переопределить `listLimit()` ([свои поля](fields/custom.md)).
- **Пароли** (поле `Password`) пишутся хешем; хеш не выводится в форму, список, просмотр и выгрузку ([Password](fields/password.md)).
- **Секреты в настройках** (метод `encrypted()` страницы настроек) хранятся зашифрованными и не выводятся в форму ([настройки](settings.md#секреты)).

## HTML и вывод на сайте

- **RichText** чистится при сохранении (symfony/html-sanitizer): скрипты, обработчики событий и опасные ссылки удаляются, поэтому на сайте его можно выводить как есть — `{!! $post->body !!}` ([RichText](fields/rich-text.md)).
- **Markdown** хранится как текст: на сайте превращайте его в HTML с безопасными настройками ([Markdown](fields/markdown.md)).
- **Code** не чистится вовсе — это поле для кода, который сайт выводит сознательно (счётчики, вставки). Давайте его только тем, кому доверяете ([Code](fields/code.md)).
- Всё остальное в панели и в `<x-fastleo::*>` компонентах выводится с экранированием Blade.
- **Публичная часть готовых модулей** ([модули](modules.md#публичная-часть)) открыта без входа, и заготовки пишутся с этой оглядкой: скрытое отвечает 404, адрес в маршруте — только слаг, весь вывод экранирован, ссылки из панели (блок «Призыв», кнопки лендинга, меню) печатаются, только если это адрес сайта или `http(s)://`, изменения корзины магазина идут только POST, PATCH и DELETE с токеном формы. Оформление заказа защищено меткой времени формы (одноразовой), полем-ловушкой и лимитом 5 отправок формы за 10 минут с адреса: за прокси (Cloudflare, nginx) настройте `trustProxies`, иначе лимит станет общим для всего сайта; метка и лимит хранятся в кеше сайта, поэтому драйвер `CACHE_STORE` не должен быть `null` или `array`. Адреса в ссылках публичной части (меню, пагинация, `url()`) Laravel строит от заголовка `Host` запроса: если сайт отвечает на любой `Host`, а страницы кешируются без `Host` в ключе (CDN, кеш страниц), в кеш может попасть чужой адрес — ограничьте допустимые домены (`$middleware->trustHosts(at: ['example\.com'])` в `bootstrap/app.php`). Заголовки безопасности пакет ставит только на панель: для публичной части добавьте свои (`X-Frame-Options`, `Content-Security-Policy`).

## Файлы

- Пути из запроса проверяются по частям: `..`, `\`, скрытые файлы (`.env`, `.htaccess`) и всё вне корня отклоняются.
- Загружать можно только расширения из `files.extensions`; исполняемые и опасные форматы (`php`, `phtml`, `phar`, `html`, `svg`, `js`, `xml`, `htaccess` и другие) запрещены всегда, даже если вписать их в конфиг. В списке по умолчанию есть `doc`, `xls` и `ppt`: старые форматы Office могут нести макросы. Если файлы открывает кто-то кроме вас, уберите их из `files.extensions` и оставьте `docx`, `xlsx`, `pptx`.
- Папки, которых ещё нет, создаются только с именем из строчной латиницы, цифр и дефиса (`directory('products')`, а не `directory('Мои фото')` или `directory('product_photos')`): `?`, `#` и пробелы в имени ломали бы ссылки на файлы. Другое имя в `directory()` сразу даёт `LogicException`.
- Картинки проверяются по заголовку (не больше `files.max_pixels`) и пересохраняются без метаданных, в том числе без координат GPS ([файлы](files.md#картинки), [безопасность файлов](files.md#безопасность)).

## Импорт и экспорт

- Экспорт не превращает значения в формулы Excel (`=`, `+`, `-`, `@` в начале).
- Импорт проверяет право на каждую строку (`create`/`update`), значения — правилами полей, пишет только поля ресурса ([импорт и экспорт](import-export.md)).

## Ответы сервера

На всех страницах панели:

```
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
Referrer-Policy: same-origin
X-Robots-Tag: noindex, nofollow
Cache-Control: no-store, private
```

Панель не индексируют поисковики, её не встроить в чужой сайт, а браузер не хранит страницы с данными в кеше.

`Content-Security-Policy` пакет не ставит: интерфейс работает на Alpine, а его стандартная сборка вычисляет выражения из атрибутов (`unsafe-eval`), поэтому строгая политика сломала бы панель. Защита от внедрения скриптов — экранирование всего вывода и очистка HTML полей `RichText`; свою политику сайт может добавить для публичной части, а для адресов панели оставить `script-src 'self' 'unsafe-eval'`.

## Claude и MCP

MCP-сервер `fastleo:mcp` запускается только локально (stdio), по сети не открывается и работает от имени одного пользователя с его Policies и правилами полей. Агенту открыты все разделы сайта, кроме «Пользователей», «Ролей», каналов и ботов уведомлений и тех, что закрыты `protected static bool $mcp = false` (разделы с чужими данными и адресами получателей заявок закрывайте так). Удаление выключено, пока не передан `--allow-delete` ([Claude](claude.md#mcp-сервер)).

## Что сделать на сайте

**Настройки Laravel** для боевого сайта:

```dotenv
APP_DEBUG=false
APP_ENV=production
SESSION_SECURE_COOKIE=true   # cookie только по HTTPS
SESSION_SAME_SITE=lax
```

- `APP_KEY` — задан и не меняется без нужды: им зашифрованы секреты 2FA и настроек, от него считаются резервные коды 2FA. Если ключ нужно сменить, сохраните старый в `APP_PREVIOUS_KEYS` — Laravel расшифрует им секреты 2FA и настроек. Резервные коды при этом перестанут подходить: выдайте новые в профиле. Без старого ключа секреты не расшифровать: каждому пользователю с 2FA выполните `php artisan fastleo:user admin@site.ru --reset-two-factor` (пароль оставьте пустым), а секреты настроек (токены) введите заново. До этого шаг кода у такого пользователя покажет понятное сообщение об этом, а не ошибку 500.
- За балансировщиком или Cloudflare настройте доверенные прокси (`trustProxies` в `bootstrap/app.php`), иначе лимиты входа будут считать все запросы с одного IP. Если прокси не настроены, виджет «Состояние сервера» на дашборде покажет строку «Адрес посетителя» с предупреждением (строка появляется только при заходе через прокси, которому Laravel не доверяет).
- Если включены [заявки](leads.md): приём по API стоит в группе `api` (без сессии и CSRF) и защищён ключом в заголовке `Authorization: Bearer` (ключ хранится зашифрованным, хеш для поиска; неверный ключ — один и тот же 401; лимиты 30 запросов в минуту и 1000 в сутки на ключ, 20 неудач в минуту на адрес), тело ограничено 16 КБ. Проверка `Origin` у ключа не защита. Без ролей и владельца раздел «Доступы для сайтов» видят все пользователи панели.
- На нескольких серверах лимиты входа хранятся в кеше приложения — нужен общий кеш (Redis, база).
- Поставьте `composer audit` в CI сайта.

**Адрес панели.** Путь `fastleo` можно сменить (`path`) или вынести панель на отдельный домен (`domain`) — [настройки](configuration.md#адрес). Это не защита сама по себе, но убирает часть автоматических переборов.

**nginx.** Запретите выполнение PHP в папке загрузок и ограничьте размер запроса:

```nginx
# Загрузки: никакого PHP, даже если файл туда попадёт
location ^~ /storage/ {
    location ~ \.php$ { return 403; }
}

# Не больше лимита загрузки файлов (files.max_size) с запасом
client_max_body_size 32m;
```

Если панелью пользуются из известных мест, ограничьте доступ по IP на стороне приложения: правило nginx `location /fastleo { allow …; deny all; }` обходится адресом `/index.php/fastleo/login`, потому что PHP обрабатывается в другом `location`. Надёжнее — свой middleware в `fastleo.middleware`; он проверяет все страницы панели и работает вместе с отдельным доменом:

```bash
php artisan make:middleware AllowOfficeOnly       # app/Http/Middleware/AllowOfficeOnly.php
```

```php
// app/Http/Middleware/AllowOfficeOnly.php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

final class AllowOfficeOnly
{
    public function handle(Request $request, Closure $next): Response
    {
        abort_unless(in_array($request->ip(), ['203.0.113.10'], true), 404);

        return $next($request);
    }
}

// config/fastleo.php
'middleware' => ['web', App\Http\Middleware\AllowOfficeOnly::class],
```

За балансировщиком или Cloudflare сначала настройте доверенные прокси, иначе `ip()` вернёт адрес прокси. Если панель на отдельном домене (`domain`), можно ограничить по IP весь server-блок этого домена в nginx.

Не открывайте наружу `storage/`, `.env` и каталог `vendor/` — в стандартной настройке Laravel корень сайта `public/`, и они недоступны.
