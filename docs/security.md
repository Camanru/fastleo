# Безопасность

Админка открыта в интернет, поэтому пакет защищает вход, права, запись данных и файлы сам, без настройки. На этой странице — что именно защищено и что стоит сделать на сервере. Подробности — по ссылкам.

## Вход

- **Отдельный guard `fastleo`** (драйвер `session`) поверх пользователей сайта. Пускает только тех, у кого `canAccessFastleo()` возвращает `true` (по умолчанию — колонка `fastleo_admin`). Проверка идёт на **каждом** запросе: снятый флаг закрывает доступ сразу, без выхода ([установка](installation.md#2-модель-пользователя)).
- **Лимиты попыток**: 5 в минуту на пару «аккаунт + IP», 20 в минуту с IP, 50 в час на аккаунт. Одинаковый ответ для неверного пароля, несуществующего email и пользователя без доступа; время ответа тоже одинаковое: пароль хешируется и для несуществующего email. Попытка засчитывается до проверки пароля (одновременные запросы не проходят сверх лимита); успешный вход сбрасывает счётчики аккаунта, но не счётчик IP. Счётчики лежат в кеше приложения — на нескольких серверах нужен общий кеш (Redis, база).
  Счётчик «50 в час на аккаунт» защищает от перебора с многих адресов, но им же можно закрыть вход владельцу: пока лимит не истёк, не войти и с верным паролем (помогает cookie «Запомнить меня»). Часовую блокировку аккаунта (и ввода пароля, и шага кода 2FA) снимает `php artisan fastleo:unlock admin@site.ru`; счётчики IP закончатся сами в течение минуты (или сбросьте всё `php artisan cache:clear`).
- **Точное совпадение email.** Варианты адреса, которые база считает равными («ádmin@» и «admin@» в MySQL), не входят и не получают свой счётчик попыток.
- **Заголовки безопасности** ставятся на все ответы админки, включая перенаправление гостя на вход и ответ 401: `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `X-Robots-Tag: noindex, nofollow`, `Cache-Control: no-store, private`.
- **«Запомнить меня»** держит вход `auth.remember_days` дней (30); выход и смена пароля отменяют его.
- **Новая сессия** после входа, выход — только POST с CSRF-токеном. После входа админка возвращает только на свои страницы: адрес возврата, который записал сайт (`url.intended`), другая страница сайта или чужой домен игнорируются. Ошибка хеширования (пароль длиннее предела `hashing.bcrypt.limit`, хеш чужого алгоритма) для входа — обычный «неверный пароль», а не ошибка 500.
- **Смена пароля завершает вход на всех устройствах** (middleware `AuthenticateSession`), кнопка «Выйти на других устройствах» — в профиле.
- **Двухфакторная защита** (TOTP + резервные коды): секрет зашифрован `APP_KEY`, коды хранятся хешами, код принимается один раз, у ввода кода свои лимиты. Можно сделать обязательной для всех: `auth.two_factor_required` ([вход и профиль](auth.md#двухфакторная-защита-2fa)).
- **Восстановление пароля** и действия профиля с проверкой пароля ограничены по частоте; ссылка сброса живёт `auth.reset_minutes` минут.
- **Письмо о входе с нового устройства** и история входов в профиле ([вход и профиль](auth.md#история-входов)).

## Права

- **Policies моделей** проверяются на каждом действии: список, просмотр, создание, изменение, удаление, восстановление, порядок, экспорт, импорт, свои действия. Нет Policy — разрешено всё любому администратору ([права](authorization.md)).
- Права на **вложенные записи** (HasMany, HasOne) и **варианты связей** (BelongsTo, BelongsToMany) проверяются так же: в форму нельзя подставить чужую запись или запись, которой нет в списке вариантов ([права](authorization.md#связи-и-вложенные-записи)).
- **Ограничение записей** (`query()` ресурса) действует и в списке, и при открытии записи по адресу, и в поиске Ctrl+K, и в журнале изменений.
- Встроенный раздел «Администраторы» не даёт снять доступ с себя и удалить последнего администратора.

## Запись данных

- В модель попадают **только поля из `fields()` ресурса**, видимые и не `readonly()`. Лишние поля запроса (`fastleo_admin`, `is_paid` и т. п.) отбрасываются ещё до `fill()`, `$fillable` модели — вторая линия защиты ([ресурсы](resources.md)).
- Запись идёт через Eloquent в транзакции: работают касты, мутаторы, observers и `SoftDeletes` сайта.
- Каждое значение проверяется правилами поля; часть правил поле ставит само (длина, формат, существование связанной записи).
- Все изменяющие запросы — POST/PUT/DELETE с CSRF-токеном.
- **Пароли** (поле `Password`) пишутся хешем; хеш не выводится в форму, список, просмотр и выгрузку, а в журнал изменений не попадает, если колонка `password` или внесена в `$hidden` модели ([Password](fields/password.md), [журнал](activity.md#пароли-и-скрытые-поля)).
- **Секреты в настройках** (метод `encrypted()` страницы настроек) хранятся зашифрованными и не выводятся в форму ([настройки](settings.md#секреты)).

## HTML и вывод на сайте

- **RichText** чистится при сохранении (symfony/html-sanitizer): скрипты, обработчики событий и опасные ссылки удаляются, поэтому на сайте его можно выводить как есть — `{!! $post->body !!}` ([RichText](fields/rich-text.md)).
- **Markdown** хранится как текст: на сайте превращайте его в HTML с безопасными настройками ([Markdown](fields/markdown.md)).
- **Code** не чистится вовсе — это поле для кода, который сайт выводит сознательно (счётчики, вставки). Давайте его только тем, кому доверяете ([Code](fields/code.md)).
- Всё остальное в админке и в `<x-fastleo::*>` компонентах выводится с экранированием Blade.

## Файлы

- Пути из запроса проверяются по частям: `..`, `\`, скрытые файлы (`.env`, `.htaccess`) и всё вне корня отклоняются.
- Загружать можно только расширения из `files.extensions`; исполняемые и опасные форматы (`php`, `phtml`, `phar`, `html`, `svg`, `js`, `xml`, `htaccess` и другие) запрещены всегда, даже если вписать их в конфиг.
- Папки, которых ещё нет, создаются только с именем из строчной латиницы, цифр и дефиса (`directory('doctors')`, а не `directory('Мои фото')` или `directory('doctor_photos')`): `?`, `#` и пробелы в имени ломали бы ссылки на файлы. Другое имя в `directory()` сразу даёт `LogicException`.
- Картинки проверяются по заголовку (не больше `files.max_pixels`) и пересохраняются без метаданных, в том числе без координат GPS ([файлы](files.md#картинки), [безопасность файлов](files.md#безопасность)).

## Импорт и экспорт

- Экспорт не превращает значения в формулы Excel (`=`, `+`, `-`, `@` в начале).
- Импорт проверяет право на каждую строку (`create`/`update`), значения — правилами полей, пишет только поля ресурса ([импорт и экспорт](import-export.md)).

## Ответы сервера

На всех страницах админки:

```
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
Referrer-Policy: same-origin
X-Robots-Tag: noindex, nofollow
Cache-Control: no-store, private
```

Админку не индексируют поисковики, её не встроить в чужой сайт, а браузер не хранит страницы с данными в кеше.

## Claude и MCP

MCP-сервер `fastleo:mcp` запускается только локально (stdio), по сети не открывается и работает от имени одного администратора с его Policies и правилами полей. Агенту открыты все разделы сайта, кроме «Администраторов», каналов и ботов уведомлений и тех, что закрыты `protected static bool $mcp = false` (разделы с чужими данными и адресами получателей заявок закрывайте так). Удаление выключено, пока не передан `--allow-delete` ([Claude](claude.md#mcp-сервер)).

## Что сделать на сайте

**Настройки Laravel** для боевого сайта:

```dotenv
APP_DEBUG=false
APP_ENV=production
SESSION_SECURE_COOKIE=true   # cookie только по HTTPS
SESSION_SAME_SITE=lax
```

- `APP_KEY` — задан и не меняется без нужды: им зашифрованы секреты 2FA и настроек, от него считаются резервные коды 2FA. Если ключ нужно сменить, сохраните старый в `APP_PREVIOUS_KEYS` — Laravel расшифрует им секреты 2FA и настроек. Резервные коды при этом перестанут подходить: выдайте новые в профиле. Без старого ключа секреты не расшифровать: каждому администратору с 2FA выполните `php artisan fastleo:user admin@site.ru --reset-two-factor` (пароль оставьте пустым), а секреты настроек (токены) введите заново. До этого шаг кода у такого администратора покажет понятное сообщение об этом, а не ошибку 500.
- За балансировщиком или Cloudflare настройте доверенные прокси (`trustProxies` в `bootstrap/app.php`), иначе лимиты входа будут считать все запросы с одного IP.
- На нескольких серверах лимиты входа хранятся в кеше приложения — нужен общий кеш (Redis, база).
- Поставьте `composer audit` в CI сайта.

**Адрес админки.** Путь `fastleo` можно сменить (`path`) или вынести админку на отдельный домен (`domain`) — [настройки](configuration.md#адрес). Это не защита сама по себе, но убирает часть автоматических переборов.

**nginx.** Запретите выполнение PHP в папке загрузок и ограничьте размер запроса:

```nginx
# Загрузки: никакого PHP, даже если файл туда попадёт
location ^~ /storage/ {
    location ~ \.php$ { return 403; }
}

# Не больше лимита загрузки файлов (files.max_size) с запасом
client_max_body_size 32m;
```

Если админкой пользуются из известных мест, ограничьте доступ по IP на стороне приложения: правило nginx `location /fastleo { allow …; deny all; }` обходится адресом `/index.php/fastleo/login`, потому что PHP обрабатывается в другом `location`. Надёжнее — свой middleware в `fastleo.middleware`; он проверяет все страницы админки и работает вместе с отдельным доменом:

```bash
php artisan make:middleware AllowOfficeOnly       # app/Http/Middleware/AllowOfficeOnly.php
```

```php
// app/Http/Middleware/AllowOfficeOnly.php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

final class AllowOfficeOnly
{
    public function handle(Request $request, Closure $next): Response
    {
        abort_unless(in_array($request->ip(), ['203.0.113.10'], true), 404);

        return $next($request);
    }
}

// config/fastleo.php
'middleware' => ['web', App\Http\Middleware\AllowOfficeOnly::class],
```

За балансировщиком или Cloudflare сначала настройте доверенные прокси, иначе `ip()` вернёт адрес прокси. Если админка на отдельном домене (`domain`), можно ограничить по IP весь server-блок этого домена в nginx.

Не открывайте наружу `storage/`, `.env` и каталог `vendor/` — в стандартной настройке Laravel корень сайта `public/`, и они недоступны.
