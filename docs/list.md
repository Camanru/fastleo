# Список записей

Список раздела строится из тех же полей, что и форма. Столбец — каждое поле, видимое в списке.

## Какие поля видны

- Видны все поля, кроме длинного текста (`Textarea`, `Markdown`, `Code`, `RichText`), `Hidden`, `Password`, вложенных блоков и JSON-полей (`HasMany`, `HasOne`, `Repeater`, `Blocks`, `KeyValue`, `Seo`) и `BelongsToMany` — они скрыты по умолчанию.
- `hideInList()` — убрать столбец, `showInList()` — показать скрытый по умолчанию.
- `onlyInList()` — столбец есть, а в форме поля нет (например, `created_at`).
- Первый столбец — ссылка на запись: если её можно менять, на форму правки, иначе на страницу просмотра. Это обычная страница, а не окно; клик по строке ведёт туда же. Окно с карточкой записи открывают кнопка «глаз», ссылка связи `BelongsTo` и строка виджета «Таблица» ([настройки просмотра](configuration.md#страница-просмотра-записи)). Без страницы просмотра ([`record_view` = false](configuration.md#страница-просмотра-записи)) запись, которую нельзя менять, остаётся текстом.
- `->hideWhenEmpty()` — столбец исчезает, пока на показанной странице у всех записей значение пустое (второй телефон, менеджер, комментарий) и появляется, как только у одной записи оно есть. Первый столбец, столбец текущей сортировки, пустая страница и поле с правкой на месте (`inlineEditable()`) или своим шаблоном (`listView()`) не скрываются; число столбцов может меняться от страницы к странице.
- `Image::make('cover')->inTitle()` — обложка не отдельным столбцом, а миниатюрой перед заголовком в первой ячейке; сортировки по такой картинке нет — столбца у неё нет ([image.md](fields/image.md)).
- Связь `BelongsTo` (категория, менеджер) в списке — ссылка на просмотр связанной записи в её разделе: по умолчанию карточка в окне, при `record_view` (или `$recordView` раздела) = `'page'` — страница (без страницы просмотра — [`record_view` = false](configuration.md#страница-просмотра-записи) — на форму правки, если запись можно менять). Ссылки нет, если у модели нет раздела, администратору не разрешён просмотр записи (Policy `view`, `Resource::can()`), поле `inlineEditable()` (там выпадающий список) или `formatUsing()` вернул HTML (`Htmlable`): вложенных ссылок не бывает. Если у модели несколько разделов, берётся первый зарегистрированный. В корзине, на странице записи и в первом столбце связь остаётся обычным текстом.

```php
Text::make('title', 'Заголовок')->searchable()->sortable(),
Textarea::make('excerpt', 'Анонс')->showInList(),          // первые 100 символов
DateTime::make('created_at', 'Создано')->onlyInList()->sortable(),
```

Как поле выглядит в списке, меняют `formatUsing()` и `listView()` — [fields/README.md](fields/README.md). Статусы `Select`/`Enum` можно показать цветными метками: `->badges([...])` ([select.md](fields/select.md)). Столбец с подсчётом (число заявок, сумма продаж) — `->fromQuery()`, см. [«Вычисляемые столбцы»](#вычисляемые-столбцы).

## Выбор столбцов

Над списком — кнопка «Столбцы» (значок колонок рядом с «Плотностью таблицы»): администратор снимает галочки с лишних столбцов, и они пропадают и в таблице, и в карточках на телефоне. Выбор запоминается в браузере (`localStorage`, отдельно для каждого раздела и каждого браузера) и действует на следующих страницах и после перезагрузки; «Показать все» возвращает всё. Первый столбец (название) скрыть нельзя; кнопки нет, если в списке один столбец. Это настройка просмотра: что видно в списке по умолчанию, решает код ресурса (`hideInList()`, `hideWhenEmpty()`).

## Поиск

Строка поиска появляется, если хотя бы одно поле отмечено `searchable()`. Ищется подстрока в любом из этих полей; символы `%` и `_` ищутся как обычные. Поле, скрытое только у некоторых записей (`hidden(fn ($record) => …)`), при поиске получает `null` вместо записи и ищется по всем записям: не отмечайте `searchable()` такие поля, если значение нельзя раскрывать подбором.

Ищется сохранённое значение: у `Select` — значение варианта (`published`), а не подпись; у дат — `2026-03-08`; у [многоязычного поля](translations.md) — текст на любом языке.

Регистр букв не важен во всех базах: «чайник» найдёт «Чайник». В MySQL это даёт обычная `_ci`-сортировка колонки (с бинарной `_bin` поиск различает регистр).

Для больших таблиц поиск по подстроке не использует индекс — отмечайте `searchable()` только нужные поля.

## Глобальный поиск

Кнопка «Поиск» в шапке или **Ctrl+K** (⌘+K на Mac) открывает окно поиска по всей админке. Он ищет:

- **пункты меню** — разделы, настройки, свои страницы — по названию;
- **записи разделов** — по тем же полям `searchable()`, что и поиск в списке. До пяти записей на раздел, в том порядке, в каком они идут в списке раздела.

Стрелки выбирают результат, Enter открывает его, Esc закрывает окно. Запись открывается на форме редактирования, а если менять её нельзя (Policy `update`, раздел только для просмотра) — на странице просмотра; при `fastleo.record_view = false` (и без `$recordView` у раздела) страницы просмотра нет, и такая запись открывает список раздела.

Что видит администратор, определяют права: раздел участвует, только если доступно `viewAny`, а каждая найденная запись проходит Policy `view`. Раздел можно исключить из глобального поиска, оставив поиск в его собственном списке:

```php
protected static bool $globallySearchable = false;
```

Строка поиска — от 2 до 100 символов; запросов не больше 60 в минуту. Адрес для своих клиентов: `GET /fastleo/search?q=…` (JSON `{groups: [{label, items: [{title, hint, url}]}]}`), доступен только вошедшему администратору.

## Фильтры

Фильтры описываются в методе `filters()` ресурса. Над списком появляется кнопка «Фильтры», под ней — панель: выбор сразу применяет фильтр, «Сбросить» убирает фильтры и поиск. Фильтры работают вместе друг с другом и с поиском.

```php
use Fastleo\Filters\BelongsToFilter;
use Fastleo\Filters\BelongsToManyFilter;
use Fastleo\Filters\BooleanFilter;
use Fastleo\Filters\DateRangeFilter;
use Fastleo\Filters\NumberRangeFilter;
use Fastleo\Filters\SelectFilter;
use Illuminate\Database\Eloquent\Builder;

public function filters(): array
{
    return [
        SelectFilter::make('status'),                    // варианты и подпись — из поля status
        BelongsToFilter::make('category_id'),            // рубрика — из поля BelongsTo
        BelongsToManyFilter::make('topics'),             // тема — из поля BelongsToMany
        BooleanFilter::make('is_published', 'Опубликовано'),
        DateRangeFilter::make('published_on', 'Дата публикации'),
        DateRangeFilter::make('created_at', 'Создано'),  // колонка без поля в форме
        NumberRangeFilter::make('price', 'Цена'),        // «от … до …» для чисел
    ];
}
```

| Фильтр | Что делает |
|---|---|
| `SelectFilter` | Записи с выбранным вариантом. Варианты — из поля `Select`, `Enum` или `Radio` с тем же именем либо свои: `->options([...])` (массив, PHP enum или замыкание). Для `Select::multiple()` (json-массив) — записи, в массиве которых есть вариант |
| `BooleanFilter` | «Все / Да / Нет». «Нет» показывает и записи без значения (`NULL`) |
| `BelongsToManyFilter` | Записи, у которых среди связанных есть выбранная (темы статьи, метки товара). Имя фильтра — имя поля `BelongsToMany` (метод связи модели); варианты, подписи и `query()` — из него, поиск по серверу — как у `BelongsToFilter` |
| `BelongsToFilter` | Записи, связанные с выбранной. Нужно поле `BelongsTo` с тем же именем: варианты, подписи и `query()` — из него (`dependsOn()` не учитывается). Если записей больше `fastleo.relations.preload`, список ищет по серверу |
| `DateRangeFilter` | Даты «с … по …», обе границы включительно, любую можно не указывать. У даты со временем (`DateTime`, `created_at`) день считается в часовом поясе админки |
| `NumberRangeFilter` | Числа «от … до …» (цена, год, наработка), обе границы включительно, любую можно не указывать. Границы — целые или десятичные числа (точка или запятая); не число пакет отбрасывает, а без единой границы фильтр выключен. Подходит к любой числовой колонке, поля с тем же именем не нужно |

Подпись — вторым аргументом `make()` или `->label()`; по умолчанию — подпись одноимённого поля.

Детали:

- `using()` у `DateRangeFilter` получает массив `['from' => ?string, 'to' => ?string]` (даты `Y-m-d`), а не строку; у `NumberRangeFilter` — такой же массив с числами строкой (`'100'`, `'2.5'`).
- Дробная граница `NumberRangeFilter` у целой колонки (`views`, `year`) округляется внутрь диапазона: «от 99,5» значит «от 100», «до 500,5» — «до 500». Граница шире типа колонки (`integer` — до ±2,1 млрд) сжимается до значений типа, а диапазон целиком за пределами типа ничего не находит: база не получает число, которое не может сравнить. У `decimal`-колонки граница сравнивается как есть.
- `SelectFilter` из `Select` с `dependsOn()` получает варианты для пустой зависимости.
- `DateRangeFilter` по колонке, которой нет среди полей и у которой нет каста `date`, считает значение датой со временем: границы дня сдвигаются на часовой пояс админки.

**Значение по умолчанию** — `default()`: список открывается уже отфильтрованным, например «только открытые», «менеджер — я», «вчера — сегодня». Значение — то, что выбрал бы администратор: вариант `Select`, `true`/`false` у `BooleanFilter`, id у `BelongsToFilter`, у дат `['from' => 'ГГГГ-ММ-ДД', 'to' => 'ГГГГ-ММ-ДД']`, у чисел `['from' => 2020, 'to' => null]`. Число, `BackedEnum` и `bool` пакет приводит к виду из адреса сам (`auth()->id()` → `'5'`, `Status::New` → его значение); замыкание вычисляется при каждом показе списка:

```php
SelectFilter::make('status')->default('new'),
BelongsToFilter::make('manager_id', 'Менеджер')->default(fn () => auth()->id()),
DateRangeFilter::make('created_at', 'Создано')->default(fn () => [
    'from' => today()->subDay()->toDateString(),
    'to' => today()->toDateString(),
]),
```

- Умолчание применяется, пока в адресе нет `filter[имя]`. Администратор выбирает «Все» (у дат — стирает обе границы): в адресе остаётся пустой `filter[имя]=`, и умолчание не действует. Кнопка «Сбросить» появляется, только когда вид списка отличается от того, что открывается без параметров (есть поиск, выбрано «Все» или другое значение); она ведёт на адрес без параметров, то есть возвращает умолчание.
- Фильтр в панели показывает значение по умолчанию выбранным; пока оно действует, список идёт простой таблицей — без дерева и ручного порядка, как при любом фильтре.
- Экспорт из списка берёт те же фильтры, что и сам список. В глобальном поиске (Ctrl+K) и в [MCP](claude.md#mcp-сервер) умолчания не применяются: они видят все записи.
- Значение не из вариантов не применяется, как и в адресе. Ничего не запоминается: ссылка на раздел всегда открывает одно и то же.

**Свой запрос** — `using()`: замыкание получает запрос и проверенное значение фильтра.

```php
SelectFilter::make('popular', 'Популярность')
    ->options(['yes' => 'Больше 1000 просмотров'])
    ->using(fn (Builder $query, string $value) => $query->where('views', '>', 1000)),

BooleanFilter::make('has_photo', 'С фото')
    ->using(fn (Builder $query, bool $value) => $value ? $query->whereNotNull('photo') : $query->whereNull('photo')),
```

**Свой тип фильтра** — наследник `Fastleo\Filters\Filter` с методами `value()` (проверить значение из адреса, `null` — фильтр выключен), `query()` (условие) и `view()` (Blade-шаблон: получает `$filter`, `$value`, `$form` — id формы списка для атрибута `form` — и `$auto`: `false`, если раздел применяет фильтры кнопкой, тогда шаблон не отправляет форму сам; заготовка `fastleo:make-filter` это уже учитывает).

Заготовка класса и шаблона (подключается в `filters()` ресурса как `ByCity::make('city', 'Город')` и `use App\Fastleo\Filters\ByCity;`):

```bash
php artisan fastleo:make-filter ByCity            # app/Fastleo/Filters/ByCity.php + resources/views/fastleo/filters/by-city.blade.php
```

**Безопасность.** Применяются только фильтры из `filters()`: колонка из адреса без фильтра игнорируется. Значение не из вариантов, массив вместо строки, несуществующая дата — фильтр не применяется, ошибки нет. Фильтр по полю, скрытому от этого администратора (`hidden()` или `hidden(fn …)`), не показывается и не применяется, в том числе со значением по умолчанию: иначе по числу найденных записей и по вариантам можно было бы подобрать значение скрытого поля. Фильтр без одноимённого поля (например, `NumberRangeFilter` по колонке без поля) это не касается.

Пока включён фильтр, список идёт простой таблицей: без дерева и ручного порядка (как при поиске).

### Фильтры по кнопке и свёрнутая панель

По умолчанию фильтр применяется сразу, как только выбрано значение. Если значений несколько (период и менеджер, статус и город), список при каждом выборе перезагружается, и спокойно выставить их нельзя. Тогда включите применение по кнопке:

```php
protected static bool $filtersApplyOnChange = false; // фильтры уходят кнопкой «Фильтровать»
protected static bool $filtersCollapsed = true;      // панель свёрнута, пока её не откроют
```

- **`$filtersApplyOnChange = false`** — выбор значения список не перезагружает. В панели в одном ряду с полями стоят кнопка «Фильтровать» и «Сбросить» — она видна, если поиск или фильтры отличаются от значений по умолчанию, и возвращает список к ним (вместе с сортировкой и числом строк на странице); когда места не хватает, кнопки переносятся на следующую строку. Enter в строке поиска отправляет форму как раньше. Работает для всех готовых фильтров, включая свои на шаблонах пакета.
- **`$filtersCollapsed = true`** — панель закрыта, даже если фильтры применены или заданы по умолчанию ([`default()`](#фильтры)): число применённых видно на кнопке «Фильтры». Открытое или закрытое состояние помнится на время вкладки браузера (`sessionStorage`; если он недоступен, панель просто закрыта). Без свойства панель открывается сама, когда фильтры применены.

Свойства независимы: можно свернуть панель и оставить применение при выборе, и наоборот.

## Сортировка

Клик по заголовку столбца с `sortable()` сортирует по возрастанию, повторный — по убыванию. По остальным столбцам сортировать нельзя — имя колонки из адреса без `sortable()` игнорируется.

Порядок по умолчанию — новые записи сверху. Свой — в ресурсе:

```php
protected static ?array $defaultOrder = ['name', 'asc'];
```

## Страницы

По 25 записей на странице (`fastleo.list.per_page` в [настройках](configuration.md) или `$perPage` в ресурсе). Кнопка «Все» показывает весь раздел одной страницей, но не больше `fastleo.list.max_all` (1000) записей.

Под списком — выбор «На странице»: 25, 50 или 100 записей (`fastleo.list.per_page_options` или `$perPageOptions` в ресурсе, `[]` — выбора нет). В выбор всегда входит обычное число записей раздела (`$perPage`); число вне списка, например `?per_page=7`, игнорируется. Выбор появляется, когда записей больше, чем в самом малом варианте; он сохраняется при поиске, фильтрах и сортировке. В [связанных таблицах](related.md) выбор тот же (размеры берутся из дочернего раздела); при `Related::perPage()` первая страница — с этим числом, пока администратор не выбрал другое.

Поиск, фильтры, сортировка и страница хранятся в адресе (`?q=…&filter[status]=published&sort=title`) — ссылку на отфильтрованный список можно отправить коллеге.

## Ручной порядок

С `$sortColumn` в ресурсе ([resources.md](resources.md#ручной-порядок)) у строк появляются:

- стрелки «выше» / «ниже» — работают и на границе страницы (запись меняется местами с соседом с другой страницы);
- ручка для перетаскивания (в таблице; на телефоне — только стрелки).

Пока список отсортирован по столбцу, ищется, отфильтрован или открыта корзина, стрелок и ручки нет — порядок там другой.

## Дерево

С `$treeColumn` ([resources.md](resources.md#дерево)) список — дерево: отступы, сворачивание веток, число вложенных у записи (ссылка на ветку), кнопка «+» для вложенной записи. Перетаскивание в дереве — только внутри своего уровня; перенос в другую ветку — полем «Родитель» в форме. Ветка `?parent=ID` хранится в адресе.

**Страницы дерева считают записи одного уровня** (как список страниц в WordPress): «25 на странице» значит 25 записей верхнего уровня, каждая со всеми вложенными, а в открытой ветке — 25 её прямых детей со всеми вложенными. Свёрнутые ветки не растягивают число страниц, а запись не отрывается от своих вложенных. Подпись под списком — «Записи верхнего уровня 1–25 из 80 (со всеми вложенными)», в ветке — «Записи ветки …», счётчик в заголовке — все записи раздела. Кнопка «Все» показывает до `fastleo.list.max_all` (1000) записей верхнего уровня.

Строк на странице дерева не больше `fastleo.list.max_all` (1000): у очень большой ветки (тысячи вложенных) хвост не показывается, под списком появляется пояснение, а ветку открывают ссылкой с числом вложенных у записи (`?parent=`). Записи верхнего уровня при этом остаются на странице все.

## Действия над записью

Кнопка «Плотность таблицы» над списком переключает строки между обычными (52 px) и компактными (40 px); выбор запоминается в браузере администратора. Справа в строке (на телефоне — внизу карточки): открыть, изменить, удалить и меню «…» со [своими действиями](actions.md). Галочки слева выбирают записи для массовых действий: «Удалить», в корзине — «Восстановить» и «Удалить навсегда», и свои. Кнопки, на которые у администратора нет прав, не показываются — [authorization.md](authorization.md). В корзине — восстановить и удалить навсегда ([resources.md](resources.md#корзина)).

### Главная кнопка строки

Когда у записи есть одно главное действие («Взять в работу», «Обработать заявку»), его выносят в строку заметной кнопкой с подписью, а остальные оставляют в меню «…». Метод `primaryRowAction()` возвращает ключ действия из `actions()` и подпись, которая может зависеть от записи:

```php
use Illuminate\Database\Eloquent\Model;

public function primaryRowAction(Model $record): ?array
{
    return $record->manager_id === null
        ? ['key' => (new TakeLead)->key(), 'label' => 'Обработать заявку', 'primary' => true]
        : ['key' => (new OpenClient)->key(), 'label' => 'Обрабатывает '.$record->manager->name];
}
```

- `primary => true` — залитая кнопка цвета бренда, без него — контурная.
- Кнопка рисуется, только если действие с таким ключом доступно этой записи (права, `visibleFor()`); нет действия — нет кнопки, ошибки не будет. В корзине кнопки нет.
- Действие запускается так же, как из меню: окно подтверждения и результат ([actions.md](actions.md)).
- Та же кнопка стоит в строках [связанной таблицы](related.md) этого раздела (например, сообщения во вкладке карточки клиента).

## Подсветка строк

Непросмотренные записи раздела с `$readColumn` выделены жирным сами — [отметка «просмотрено»](resources.md#отметка-просмотрено).


Строку списка можно подкрасить по состоянию записи: просроченная задача — красным, выполненная — зелёным. Метод `rowTone()` ресурса возвращает тон — `success`, `warning`, `danger`, `info`, `neutral` — или `null` (без цвета). Те же цвета у строк связанных таблиц ([related.md](related.md)).

```php
use Illuminate\Database\Eloquent\Model;

public function rowTone(Model $record): ?string
{
    // done_at и due_at — колонки с кастом `datetime` в модели
    return match (true) {
        $record->done_at !== null => 'success',
        $record->due_at?->isPast() => 'danger',
        default => null,
    };
}
```

Цвет виден и в таблице, и в карточках списка на телефоне. Цвет — только подсказка: статус должен быть виден и текстом (`->badges()` у `Select`/`Enum`). Неизвестный тон — `LogicException`, а не молчаливый пропуск.

## Правка в ячейке

Цена, статус, количество меняются прямо в списке, без открытия формы: `->inlineEditable()`. Щёлкнули по ячейке, изменили, ушли из поля (или нажали Enter) — значение сохранилось; Escape возвращает прежнее. Ошибка проверки показывается под полем, а в нём остаётся прежнее значение.

```php
Number::make('price', 'Цена')->min(0)->inlineEditable(),
Enum::make('status', 'Статус')->enum(OfferStatus::class)->inlineEditable(),
BelongsTo::make('manager_id', 'Менеджер')->inlineEditable(),
```

- Подходят однострочный текст (`Text`, `Email`, `Tel`, `Url`; `Slug`, `Textarea`, `Markdown` и `RichText` — нет, поле бросит ошибку описания), число, список с одиночным выбором (`Select`, `Enum`, `Radio`) и `BelongsTo`; для галочки есть [быстрый переключатель](fields/toggle.md#быстрый-переключатель-в-списке). У `BelongsTo` вариантов должно быть не больше `fastleo.relations.preload`, иначе ячейка остаётся обычным текстом.
- Запись идёт так же, как из формы: право `update` на запись, поле видно и не `readonly()`, правила поля (`required()`, `min()`, `maxLength()`, свои `rules()` — с остальными значениями записи в данных), Eloquent и observers. Правила других полей не проверяются: старая запись, не проходящая чужое правило, не мешает править ячейку.
- Поле не должно зависеть от других полей формы (`dependsOn()`, `visibleWhen()`) и они — от него; также нельзя вместе с `multiple()`, `translatable()` и `fromQuery()`. Иначе при описании раздела будет ошибка: значения полей разошлись бы.
- Работает в списке, на телефоне (карточки) и в [связанных таблицах](related.md). В корзине и без права `update` ячейка — обычный текст. У первого столбца пропадает ссылка на запись.
- Список с цветными метками (`badges()`, `Enum` с `tone()`) красится в цвет метки выбранного варианта.
- После сохранения [вычисляемые столбцы](#вычисляемые-столбцы) этой строки (маржа, сумма заявки) пересчитываются и обновляются на странице сами; итоги и порядок сортировки обновит перезагрузка (или [автообновление](#автообновление-списка)).

## Вычисляемые столбцы

Число заявок клиента, выручка, дата последнего заказа берутся не из колонки таблицы, а из запроса. Посчитайте их в `query()` ресурса (`withCount`, `withSum`, `withMax` или подзапрос с псевдонимом) и опишите поле с этим именем и `fromQuery()`:

```php
public function query(Builder $query): Builder
{
    return $query->withCount('offers')->withSum('soldItems as revenue', 'price');
}

public function fields(): array
{
    return [
        Text::make('title', 'Клиент')->searchable()->sortable(),
        Number::make('offers_count', 'Заявок')->fromQuery()->sortable(),
        Number::make('revenue', 'Выручка')->fromQuery()->sortable()->formatUsing(fn ($v) => number_format((float) $v, 0, ',', ' ').' ₽'),
    ];
}
```

Такое поле только для показа: оно есть в списке, на странице просмотра, в выгрузке и в ответах MCP; в форме, импорте и записи через MCP его нет, а `fastleo:doctor` не ищет для него колонку (но предупредит, если `query()` не отдаёт значение с таким именем). По заголовку можно сортировать — сортировка идёт по псевдониму. Искать (`searchable()`) и фильтровать по такому столбцу нельзя: поиск и фильтры работают по колонкам таблицы. Подходят простые типы: текст, число, дата, время, список, галочка, цвет; связи, файлы и визуальный редактор (`RichText`) — нет; `Markdown` и `Code` подходят как текст.

### Столбец, который считается в PHP по записи

Когда значение складывается из нескольких полей записи или состоит из ссылок (телефон, имя и сайт в одной ячейке; «Клиент и заявка» ссылками), SQL не нужен: опишите столбец методом `computed()`. Замыкание получает запись и возвращает текст, число или `HtmlString`:

```php
Text::make('contact', 'Контакт')->computed(fn (Lead $lead) => new HtmlString(
    '<b>'.e($lead->phone).'</b><br><small>'.e($lead->name).'</small>',
)),
```

Колонки в таблице у такого поля нет, поэтому оно только для показа: есть в списке, на странице просмотра, в выгрузке (теги убираются) и в ответах MCP; в форме, импорте и записи его нет, `fastleo:doctor` колонку не ищет. По нему нельзя сортировать, искать и фильтровать: `sortable()` и `searchable()` вместе с `computed()` — ошибка описания. Нужна сортировка по числу из SQL — берите `fromQuery()`; нужен поиск по телефону — оставьте настоящее поле `phone` с `searchable()` (его можно скрыть из списка `hideInList()`), а «Контакт» добавьте рядом. После правки в ячейке ([выше](#правка-в-ячейке)) значение пересчитывается.

## Автообновление списка

Входящие заявки, заказы, очередь задач: чтобы новые записи появлялись без перезагрузки страницы, задайте разделу период в секундах:

```php
protected static ?int $poll = 10; // от 5 до 3600; null — не обновлять
```

Раз в `$poll` секунд страница запрашивается заново, и таблица подменяется, если в ней что-то изменилось (поиск, сортировка, страница и фильтры сохраняются). Обновление пропускается, пока:

- вкладка не видна;
- выбраны записи или открыто окно действия, меню записи;
- администратор печатает в ячейке ([правка в ячейке](#правка-в-ячейке)) или в поле поиска;
- идёт сохранение ячейки;
- в связанной таблице раскрыта строка ([related.md](related.md#раскрывающиеся-строки)) — такая таблица остаётся как есть, пока строку не закроют.

Так что набранное не пропадёт, а выбор записей не собьётся. [Связанные таблицы](related.md) на странице записи обновляются с периодом `$poll` своего (дочернего) раздела.

Каждое обновление — обычный запрос к странице (с запросом списка), поэтому не ставьте секунды без нужды; открытая и видимая вкладка продлевает сессию администратора, как и опрос колокольчика уведомлений (если он включён).

## Большие таблицы

Страница списка — это HTML со всеми строками и иконками: 50 строк с кнопками весят порядка мегабайта без сжатия и десятки килобайт после gzip. Включите gzip или brotli на веб-сервере (в nginx — `gzip on;`, при Cloudflare это уже включено), и размер страницы перестанет быть проблемой.

Список рассчитан на сотни тысяч записей: страница — несколько запросов к базе, их число не растёт с размером таблицы. Чтобы так и оставалось:

- добавьте индексы на колонки, по которым сортируют (`sortable()`) и фильтруют, и на внешние ключи (`fastleo:doctor` предупредит о внешнем ключе без индекса в таблице от 1000 строк; `foreignId()->constrained()` создаёт индекс сам только на MySQL и MariaDB, на PostgreSQL и SQLite добавьте `->index()`):

  ```php
  $table->string('status', 20)->default('draft')->index();
  $table->date('published_on')->nullable()->index();
  ```

- поиск `searchable()` ищет подстроку (`like '%…%'`) и индексом не ускоряется — на таблицах в сотни тысяч строк отмечайте `searchable()` одно-два коротких поля (заголовок, email), а не тексты;
- кнопка «Все» на 1000 записей рисует страницу заметно дольше обычной (секунды) — `fastleo.list.max_all` можно уменьшить.
