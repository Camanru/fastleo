# HasMany

Список вложенных записей прямо в форме родителя: цены услуг, пункты меню, полезные ссылки.

```php
use Fastleo\Fields\HasMany;
use Fastleo\Fields\Number;
use Fastleo\Fields\Text;
use Fastleo\Layout\Grid;

HasMany::make('prices', 'Цены')
    ->fields([
        Grid::make(2, [
            Text::make('title', 'Услуга')->required(),
            Number::make('price', 'Цена')->min(0),
        ]),
    ])
    ->orderColumn('sort')
    ->max(50);
```

Каждая запись — блок формы. Выбрать запись другого раздела можно полем `BelongsTo` ([ниже](#выбор-записи-в-блоке)); зависимый список (`dependsOn()`) в блоке не работает — если нужен и он (позиция заказа: товар и его вариант), делайте запись отдельным разделом и показывайте [`Related` во вкладке](../recipes.md#позиции-заказа-и-строки-документа). Правило `unique` в блоке не знает `id` соседней вложенной записи — для уникальности внутри блоков ставьте уникальный индекс в базе. Блоки можно добавлять и удалять, а с `orderColumn()` — ещё и перетаскивать. Имя поля — **метод связи** `HasMany` модели.

**Колонка:** своей колонки нет — записи блоков лежат в своей таблице с внешним ключом на родителя:

```bash
php artisan make:model Price -m                   # модель блока и миграция таблицы prices
```

```php
// Миграция
Schema::create('prices', function (Blueprint $table) {
    $table->id();
    $table->foreignId('product_id')->constrained()->cascadeOnDelete();
    $table->string('title');
    $table->decimal('price', 10, 2)->nullable();
    $table->unsignedInteger('sort')->default(0);
    $table->timestamps();
});

// Модель родителя
public function prices(): HasMany
{
    return $this->hasMany(Price::class);
}

// Модель блока
#[Fillable(['title', 'price'])]
class Price extends Model {}
```

Поля блока должны быть в `$fillable` модели блока; внешний ключ (`product_id`) и колонку порядка (`sort`) в `$fillable` добавлять не нужно — их пишет пакет.

**Проверка:**

- правила полей блока действуют для каждого блока, ошибка видна под полем своего блока (`prices.0.title`);
- `min()`/`max()` — число блоков; с `min()` поле обязательно: убрать все блоки нельзя, а пустой список (форма создания) сразу открывается с `min()` пустыми блоками;
- `required()` — хотя бы один блок;
- пустой новый блок не сохраняется: в `min()` он не засчитывается (добавить пустой блок и убрать остальные нельзя), а в `max()` и `required()` засчитывается.

**В списке:** скрыто. На странице просмотра — таблица блоков.

**Сколько записей.** Каждая запись — блок формы, и форма отправляет их все разом: поле рассчитано на десятки (ссылки статьи, цены услуги, пункты меню). Для сотен записей (отзывы, заказы, комментарии) опишите их отдельным разделом и покажите таблицей [`Related`](../related.md#таблица-во-вкладке-формы): с поиском, страницами и правкой записи в окне или на странице раздела.

**Поведение при сохранении** (после записи родителя, в той же транзакции, через Eloquent — observers модели блока работают):

- блок с `id` своей записи обновляется; `id` чужой записи игнорируется;
- новый блок создаётся; новый блок без единого заполненного значения пропускается;
- блок, убранный из формы, удаляется (`delete()`; с SoftDeletes — в корзину), но только тот, что был в форме при открытии (скрытое поле `{поле}__seen` хранит их `id`): строку, которую другой пользователь добавил за время правки, устаревшая форма не стирает. Без этого поля (MCP, импорт) список заменяется целиком;
- с `orderColumn('sort')` порядок блоков = порядок в форме (1, 2, 3…), появляется ручка для перетаскивания;
- поле, которого нет в запросе, ничего не меняет.

**Внутри блока** работают:

- простые поля: текст, числа, даты, списки, галочки, Tags, Markdown, Code, Color, KeyValue;
- выбор записи другого раздела: BelongsTo;
- файлы: Image, File, Gallery;
- RichText.

**Внутри блока нельзя** (ошибка описания):

- поле с именем внешнего ключа связи (`product_id` у `bundleItems()`): родитель ставит его сам;
- связь BelongsToMany (BelongsTo можно, но без `dependsOn()`);
- вложенные блоки: HasMany, HasOne, Repeater, Blocks;
- Slug, Password, многоязычные поля (`translatable()`);
- `hideOnCreate()`, `hideOnEdit()` и `hidden(fn ...)` — правила общие для всех блоков. Скрыть поле блока для части пользователей можно логическим значением: `->hidden(! auth()->user()->isAdmin())`.

**Зависимости внутри блока:**

- подполя с `visibleWhen()` должны зависеть от поля того же блока, которое доступно всем пользователям (без `readonly()`, `disabled()`, `hidden()`);
- свои правила, ссылающиеся на соседнее поле (`required_if`), пишите с полным путём: `required_if:prices.*.type,video`.

## Выбор записи в блоке

`BelongsTo` в блоке — товар в составе комплекта, товар в заказе, автор в списке участников. Так же описываются **колонки связи «многие ко многим»** (количество, «главная», порядок): промежуточная таблица получает свой `id` и модель, а родитель — `HasMany` на неё. Поле `BelongsToMany` таких колонок не редактирует.

```bash
php artisan make:model ProductBundleItem -m    # модель строки комплекта и миграция
```

```php
// database/migrations/…_create_product_bundle_items_table.php
Schema::create('product_bundle_items', function (Blueprint $table) {
    $table->id();
    $table->foreignId('product_id')->constrained()->cascadeOnDelete();
    $table->foreignId('item_id')->nullable()->constrained('products')->nullOnDelete();
    $table->unsignedInteger('qty')->default(1);
    $table->unsignedInteger('sort')->default(0);
    $table->timestamps();
});

// app/Models/ProductBundleItem.php
use Illuminate\Database\Eloquent\Attributes\Fillable;
use Illuminate\Database\Eloquent\Relations\BelongsTo;

#[Fillable(['item_id', 'qty'])]
class ProductBundleItem extends Model
{
    public function item(): BelongsTo
    {
        return $this->belongsTo(Product::class, 'item_id');
    }
}

// app/Models/Product.php
public function bundleItems(): HasMany
{
    return $this->hasMany(ProductBundleItem::class)->orderBy('sort');
}

// app/Fastleo/ProductResource.php — в fields(); здесь BelongsTo — поле fastleo, а не связь Eloquent
use Fastleo\Fields\BelongsTo;

HasMany::make('bundleItems', 'Состав комплекта')
    ->orderColumn('sort')
    ->max(20)
    ->fields([
        BelongsTo::make('item_id', 'Товар')->required(),
        Number::make('qty', 'Количество')->integer()->min(1)->default(1),
    ]);
```

- Метод связи (`item()`) — в модели блока; имя поля — колонка внешнего ключа (`item_id`), как у обычного [BelongsTo](belongs-to.md). Сузить выбор — `->query(fn ($query) => ...)`, название — `titleColumn()`.
- Варианты в блоке всегда ищутся по серверу (поиск по названию), список не повторяется в каждом блоке. Подписи выбранных записей всех блоков загружаются одним запросом.
- Запись, которая уже стоит в блоке, но вышла из вариантов (в корзине, скрыта `query()`), остаётся выбранной и не мешает сохранить форму; выбрать такую запись заново в форме нельзя.
- Выбранная запись проверяется так же, как в обычной форме: запись вне `query()` и несуществующая отклоняются; записи всех блоков проверяются одним запросом.
- Один и тот же товар в двух блоках по умолчанию допустим (две строки заказа с одним товаром). Если нужен только один раз, добавьте полю правило `->rules(['distinct'])`; с уникальным индексом базы `unique(product_id, item_id)` форма тоже сохранится: убранные блоки удаляются до записи остальных.
- Поле нельзя сделать зависимым (`dependsOn()`), а в `Repeater` и `Blocks` (JSON) выбор записи не работает: нужны блоки `HasMany`/`HasOne`.

**Права:** блоки меняются в рамках права `update` родителя ([authorization.md](../authorization.md#связи-и-вложенные-записи)).

| Метод | Что делает |
|---|---|
| `fields([...])` | Поля и раскладка блока (`Grid`, `Section`) |
| `orderColumn('sort')` | Колонка порядка, перетаскивание блоков |
| `min(1)` / `max(20)` | Наименьшее и наибольшее число блоков (без `max()` — 200) |

Общие методы — [README](README.md#общие-методы).

Одна вложенная запись — [HasOne](has-one.md).

## Размер формы

PHP принимает не больше `max_input_vars` полей формы (по умолчанию 1000) и молча отбрасывает остальные. Пакет это замечает: форма раздела отправляет метки начала и конца, и если конец не пришёл, сохранение отказывает («Сервер получил форму не целиком») — блоки не удаляются.

`php artisan fastleo:doctor` предупреждает, если раздел при заполнении всех `max()` может превысить предел; тогда уменьшите `max()` или увеличьте `max_input_vars`.

**Как считается:**

- берётся наибольшее число блоков (без `max()` у HasMany — 200);
- множественные списки (`BelongsToMany`, `Select::multiple()`) считаются по числу вариантов;
- добавляются служебные поля формы;
- при трёх и более подполях блока без `max()` предупреждение появляется уже при стандартных `max_input_vars=1000`.
