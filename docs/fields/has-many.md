# HasMany

Список вложенных записей прямо в форме родителя: цены услуг, пункты меню, полезные ссылки. Блоки можно добавлять и удалять, а с `orderColumn()` — ещё и перетаскивать.

```php
use Fastleo\Fields\HasMany;
use Fastleo\Fields\Number;
use Fastleo\Fields\Text;
use Fastleo\Layout\Grid;

HasMany::make('prices', 'Цены')
    ->fields([
        Grid::make(2, [
            Text::make('title', 'Услуга')->required(),
            Number::make('price', 'Цена')->min(0),
        ]),
    ])
    ->orderColumn('sort')
    ->max(50);
```

Имя поля — **метод связи** `HasMany` модели:

```php
// Миграция
Schema::create('prices', function (Blueprint $table) {
    $table->id();
    $table->foreignId('doctor_id')->constrained()->cascadeOnDelete();
    $table->string('title');
    $table->decimal('price', 10, 2)->nullable();
    $table->unsignedInteger('sort')->default(0);
    $table->timestamps();
});

// Модель родителя
public function prices(): HasMany
{
    return $this->hasMany(Price::class);
}

// Модель блока
#[Fillable(['title', 'price'])]
class Price extends Model {}
```

Поля блока должны быть в `$fillable` модели блока; внешний ключ (`doctor_id`) и колонку порядка (`sort`) в `$fillable` добавлять не нужно — их пишет пакет.

**Поведение при сохранении** (после записи родителя, в той же транзакции, через Eloquent — observers модели блока работают):

- блок с `id` своей записи обновляется; `id` чужой записи игнорируется;
- новый блок создаётся; новый блок без единого заполненного значения пропускается;
- блок, убранный из формы, удаляется (`delete()`; с SoftDeletes — в корзину);
- с `orderColumn('sort')` порядок блоков = порядок в форме (1, 2, 3…), появляется ручка для перетаскивания;
- поле, которого нет в запросе, ничего не меняет.

**Размер формы.** PHP принимает не больше `max_input_vars` полей формы (по умолчанию 1000) и молча отбрасывает остальные. Форма раздела поэтому отправляет метки начала и конца: если конец не пришёл, сохранение отказывает («Сервер получил форму не целиком»), и блоки не удаляются. `php artisan fastleo:doctor` предупреждает, если раздел при заполнении всех `max()` может превысить предел; тогда уменьшите `max()` или увеличьте `max_input_vars`. Для подсчёта берётся наибольшее число блоков (без `max()` у HasMany — 200), множественные списки (`BelongsToMany`, `Select::multiple()`) считаются по числу вариантов и добавляются служебные поля формы; при трёх и более подполях блока без `max()` предупреждение появляется уже при стандартных `max_input_vars=1000`.

Подполя блока с `visibleWhen()` должны зависеть от поля того же блока, которое доступно всем администраторам (без `readonly()`, `disabled()`, `hidden()`).

**Проверка:** правила полей блока действуют для каждого блока, ошибка видна под полем своего блока (`prices.0.title`); `min()`/`max()` — число блоков (с `min()` поле обязательно: убрать все блоки нельзя); `required()` — хотя бы один блок. Пустой новый блок не сохраняется, но учитывается в этих правилах.

| Метод | Что делает |
|---|---|
| `fields([...])` | Поля и раскладка блока (`Grid`, `Section`) |
| `orderColumn('sort')` | Колонка порядка, перетаскивание блоков |
| `min(1)` / `max(20)` | Наименьшее и наибольшее число блоков (без `max()` — 200) |

**Внутри блока** работают простые поля (текст, числа, даты, списки, галочки, Tags, Markdown, Code, Color, KeyValue), файлы (Image, File, Gallery) и RichText. Нельзя: связи (BelongsTo, BelongsToMany), вложенные блоки (HasMany, HasOne, Repeater, Blocks), Slug, Password, многоязычные поля (`translatable()`), а также `hideOnCreate()`, `hideOnEdit()` и `hidden(fn ...)` (правила общие для всех блоков) — ошибка описания. Скрыть поле блока для части админов можно логическим значением: `->hidden(! auth()->user()->isAdmin())`. Свои правила, ссылающиеся на соседнее поле (`required_if`), пишите с полным путём: `required_if:prices.*.type,video`.

**В списке:** скрыто. На странице просмотра — таблица блоков.

**Права:** блоки меняются в рамках права `update` родителя ([authorization.md](../authorization.md#связи-и-вложенные-записи)).
