# RichText

Текст с оформлением в визуальном редакторе.

```php
use Fastleo\Fields\RichText;

RichText::make('content', 'Текст')->height(500);
```

Редактор — [HugeRTE](https://github.com/hugerte/hugerte) (MIT-форк TinyMCE 6): заголовки, жирный и курсив, выравнивание, списки, ссылки, картинки из [файлового менеджера](../files.md), таблицы, цитаты, видео. Редактор на русском, в тёмной теме — тёмный. Ctrl/Cmd+S внутри редактора сохраняет запись.

**Колонка:** `$table->longText('content')->nullable()` (`text` в MySQL — до 64 КБ, для статей с таблицами мало).

**Проверка:** строка до 1 000 000 символов. У поля с `required()` текст, пустой после чистки (`<p><br></p>`, `<p>&nbsp;</p>`), не проходит проверку.

**В списке:** по умолчанию столбца нет (как у [Textarea](textarea.md)); `showInList()` возвращает его — тогда начало текста без тегов (100 символов). **На просмотре:** оформленный текст (очищается ещё раз — в базе мог оказаться HTML не из админки).

При сохранении HTML очищается, поэтому на сайте его можно выводить как есть — подробно в разделе [«Чистка HTML»](#чистка-html):

```blade
<div class="prose">{!! $article->content !!}</div>
```

**Картинки и файлы.** Кнопка «Изображение» → значок папки открывает окно менеджера. Выбранная картинка вставляется адресом от корня сайта (`/storage/uploads/...`), поэтому текст не привязан к домену. В диалоге ссылки тот же значок выбирает любой файл. Вставка картинок из буфера обмена (`data:`) выключена — загрузите картинку в менеджер.

**Стили сайта в редакторе.** По умолчанию область редактирования без стилей сайта: картинки и шрифты выглядят не так, как у посетителя. Настройки на весь сайт (см. [конфигурацию](../configuration.md#чистка-html-редактора)):

- `rich_text.content_css` подключает таблицы стилей сайта;
- `rich_text.content_style` добавляет свои правила.

```php
'rich_text' => [
    'content_css' => ['/css/app.css'],
    'content_style' => 'img { max-height: 4rem; }',
],
```

**Где работает.** Редактор (1,4 МБ) загружается только на формах, где есть RichText. Работает и внутри блоков — [HasMany и HasOne](has-many.md), [Repeater](repeater.md), [Blocks](../blocks.md): редактор запускается в добавленном блоке и сохраняет текст при перетаскивании блока.

| Метод | Что делает |
|---|---|
| `height(500)` | Высота редактора в пикселях (по умолчанию 400, не меньше 150) |
| `sanitizeUsing(fn ($config) => ...)` | Дополнить профиль чистки HTML у одного поля ([подробнее](#свой-профиль-у-одного-поля)) |

Общие методы — [README](README.md#общие-методы).

## Чистка HTML

При сохранении HTML очищается (symfony/html-sanitizer). После ошибки проверки в редактор возвращается уже очищенный HTML.

**Остаётся:**

| Что | Теги |
|---|---|
| Текст | `p`, `br`, `h2`, `h3`, `h4`, `strong`, `b`, `em`, `i`, `u`, `s`, `sub`, `sup`, `blockquote`, `hr`, `pre`, `code` |
| Списки | `ul`, `ol` (`start`), `li` |
| Ссылки | `a` (`href` — http, https, mailto, tel или адрес на сайте; `title`, `target`), всем ссылкам добавляется `rel="noopener"` |
| Картинки | `img` (`src` — http, https или адрес на сайте; `alt`, `title`, `width`, `height`, `loading`), `figure`, `figcaption` |
| Таблицы | `table`, `caption`, `thead`, `tbody`, `tfoot`, `tr`, `th`, `td` (`colspan`, `rowspan`) |
| Видео | `iframe` только с плеерами по https: `www.youtube.com/embed/`, `www.youtube-nocookie.com/embed/`, `rutube.ru/play/embed/`, `vk.com/video_ext.php`, `vkvideo.ru/video_ext.php` |
| Оформление | из атрибута `style` — только `text-align` (у абзацев, заголовков, цитат, пунктов, ячеек); всё `style` целиком — настройкой `rich_text.styles` (кроме того, чем текст ложится поверх страницы: `position` не `static`, `z-index`, `transform` и родственные, в том числе с префиксом браузера, `offset-*`; `margin`, `inset`, `top`, `right`, `bottom`, `left` принимают только простые неотрицательные длины — без минуса, `calc()` и `var()`) |

**Сложность разметки** — форма отклоняет текст ошибкой «слишком сложная разметка», если в нём:

- больше 199 вложенных тегов (200 уровней вместе с самим блоком текста; в живом тексте их единицы): иначе тысячи вложенных `<b>` роняли бы процесс PHP при очистке;
- больше 30 000 открывающих тегов (таблица 400 × 6 — около трёх тысяч, правильно закрытая таблица на 4999 строк по пять столбцов — около 30 000, абзац из Word — четыре): разбор такого текста, особенно с закрывающими тегами, которым нечего закрывать, занимает десятки секунд: воркер занят до таймаута PHP, а потом отвечает ошибкой 500. Закрывающих тегов тоже не больше 30 000;
- больше 1000 атрибутов в одном теге (в живом тексте их единицы): разбор времени растёт с квадратом числа атрибутов — 40 000 имён в `<p a1 a2 …>` разбираются две секунды, 160 000 — около минуты. Значение в кавычках, даже огромное (картинка `data:`), считается одним атрибутом;
- много незакрытого форматирования (`<b>`, `<i>`, `<a>`, `<font>`…) и после него много блоков: разбор создаёт форматирование заново в каждом блоке, и 190 открытых `<b>` с тремя тысячами абзацев (25 КБ) съедают 128 МБ памяти.

Текст проверяется до разбора, по числу тегов и атрибутов, а не по тому, как он закрыт, поэтому разметкой проверку не обойти. Текст длиннее 1 000 000 знаков отклоняется по длине и дальше не разбирается.

**Уже сохранённый текст.** Если текст в базе (старый HTML, сидер, импорт прошлой версии) не проходит эту проверку, редактор его не получает: вместо поля форма показывает предупреждение и не отправляет поле, поэтому сохранение записи оставляет текст как был (пустой редактор стёр бы его). Чтобы заменить такой текст, упростите разметку в базе или загрузите текст импортом. У [многоязычного поля](../translations.md) и у подполя элемента [Repeater](repeater.md), [Blocks](../blocks.md) или дочерних записей [HasMany](has-many.md) поле так пропустить нельзя (значение собирается из присланного, и пропущенное исчезло бы): там текст показан обычным полем с HTML-кодом под предупреждением, и форма не сохранится, пока разметку не упростят. Так же поступает форма с текстом длиннее 4 000 000 знаков (санитайзер читает не больше и отрезал бы хвост). У обязательного поля с таким текстом можно не присылать значение (так делает форма), но присланное пустое значение отклоняется. Старый неряшливый HTML вида `<p><b>текст</p>` в количестве больше примерно 450 блоков отклоняется, хотя разбор его осилил бы: оценка незакрытого форматирования осторожная.

**Удаляется:**

- вместе с содержимым: `script`, `style`, `form` и поля ввода, `object`, `embed`, `svg`, `math`, `meta`, `link`;
- все обработчики (`onclick`, `onerror`), адреса `javascript:` и `data:`;
- цвета и шрифты (если сайт не включил `rich_text.styles`);
- прочие теги (`div`, `span`, `h1`, `h5`) — сам тег убирается, текст внутри остаётся.

**Особые случаи:**

- теги, которые сайт разрешил в `rich_text.tags`, остаются; такой тег без текста (например, `<div data-widget="1"></div>`) не считается пустым текстом;
- пустой текст (`<p><br></p>`, `<p>&nbsp;</p>`) сохраняется как `NULL`, а у поля с `required()` не проходит проверку; для колонки `text NOT NULL` — `emptyValue('')`;
- видео (`iframe`) не получает атрибут `allow`: полный экран работает через `allowfullscreen`, а камера, микрофон и геопозиция плееру недоступны.

### Свои теги и атрибуты на весь сайт

Ключ `rich_text` в `config/fastleo.php` (подробнее — [конфигурация](../configuration.md#чистка-html-редактора)):

```php
'rich_text' => [
    'tags' => ['div', 'span'],
    'attributes' => ['class', 'role', 'align', 'data-widget'],
    'iframe_hosts' => ['https://widget.example.com/'],
    'styles' => true,
],
```

Скрипты, обработчики `on*`, директивы JS-фреймворков (`x-init`, `hx-get`, `v-html`, `ng-click`), `srcdoc` и `javascript:` разрешить нельзя: такая настройка вызывает ошибку, `php artisan fastleo:doctor` её показывает.

### Свой профиль у одного поля

Если дополнительные теги нужны только одному полю:

```php
use Symfony\Component\HtmlSanitizer\HtmlSanitizerConfig;

RichText::make('content')
    ->sanitizeUsing(fn (HtmlSanitizerConfig $config) => $config->allowElement('span', ['class']));
```

Для HTML из других источников (импорт, API) — тот же профиль: `Fastleo\Support\HtmlSanitizer::clean($html)`.

### Что изменится в старых записях

Первое сохранение записи пропускает текст через чистку HTML. **Перед первым сохранением старых записей запустите `fastleo:doctor`:** он найдёт записи, у которых чистка вырежет теги, атрибуты и плееры (например, `class` и виджет с чужого сайта), и подскажет, что разрешить.

Чтобы увидеть, какие записи изменятся и как, выполните `php artisan fastleo:doctor --sanitize-diff` ([подробнее](../claude.md#fastleodoctor)): команда ничего не меняет и показывает «было → станет» по каждой записи. Лишнее разрешите в `fastleo.rich_text` или в `sanitizeUsing()` до сохранения.

Для текста без визуального редактора — [Markdown](markdown.md) или [Textarea](textarea.md).
