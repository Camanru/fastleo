# Готовые модули сайта

Команда `fastleo:module` копирует в сайт готовый раздел панели (модель, миграцию, ресурс, виджеты) и, если вы ответите «да», **публичную часть сайта**: маршруты, контроллеры и Blade-шаблоны без оформления. Остаётся подключить свой дизайн: общий макет `resources/views/layouts/site.blade.php` и шаблоны разделов. Заявки с сайта и по API — не модуль, а встроенная часть пакета: [leads.md](leads.md). С этого момента код принадлежит сайту: его правят под себя, обновление fastleo его не трогает.

```bash
php artisan fastleo:module            # список с галочками, затем вопрос про публичную часть
php artisan fastleo:module contacts   # модуль назван сразу; вопрос про публичную часть задаётся, если есть терминал
```

После выбора модулей и до записи файлов команда спрашивает: «Поставить и публичную часть сайта (маршруты, контроллеры, шаблоны)?» Ответ «нет» — модуль добавит только разделы в панели (так делают сайты, у которых уже есть своя публичная часть). Без терминала (CI, Claude, `--no-interaction`) вопроса нет, и публичная часть ставится. Флагов у команды нет: ответ даёте вы или умолчание.

## Что делает команда

- Сначала проверяет всё: файлы, таблицы и адреса разделов панели (свой раздел сайта с адресом `news` помешает модулю `news`). Если что-то из **панельной** части занято, **не записывается ничего**; команда печатает список занятого. Чужой код не перезаписывается, ключа `--force` нет — снимите модуль с выбора или освободите место.
- **Публичная часть проверяется отдельно и по модулям.** Модуль остаётся без неё, если: у сайта есть маршрут с таким адресом или под ним (`news` и `news/{id}`) либо с таким именем (`site.news.index`); занят PHP-файл публичной части (контроллер, запрос, корзина `ShopCart`, тест); в `routes/web.php` уже есть блок маршрутов этого модуля (такая запись уже есть: второй раз её не дописывают); у сайта уже есть запасной маршрут `Route::fallback` (нужен модулю «Страницы»). Модули с маршрутами (все, кроме `menu`) остаются без публичной части ещё и тогда, когда панель открыта на корне домена (`'path' => ''` без `domain` в `config/fastleo.php`: шаблон разделов панели перехватил бы маршруты сайта) или файл `routes/web.php` недоступен для записи. Остальные модули ставятся с публичной частью; команда печатает, что именно занято, и завершается успешно. Если публичная часть занята у всех выбранных модулей, вопрос о ней не задаётся.
- **Своё перекрывает чужое — команда предупреждает.** Маршруты модулей дописываются в конец `routes/web.php`, и побеждает тот маршрут, что зарегистрирован раньше. Если у сайта есть маршрут с параметром без ограничения (`Route::get('/{slug}', …)`), он заберёт `/news`, `/faq` и другие адреса модулей: команда печатает, какой маршрут перекроет какой адрес (сузьте свой маршрут через `->where(…)` или перенесите блок модуля выше). Так же, если у сайта остался свой маршрут для «/» (свой лендинг, `Route::view('/', …)`), а ставится «Страницы» или «Лендинг»: их главная не откроется, пока вы его не уберёте. Если «/» забирают сразу два модуля («Страницы» и «Лендинг»), открывается лендинг с адресом «/», а главная «Страниц» нет — команда предупреждает и об этом. Маршрут лендинга подходит под любой адрес из одного сегмента, поэтому установка держит его в конце `routes/web.php`: маршруты модулей, поставленных позже (`/news`), вставляются выше него.
- **Ваши шаблоны не перезаписываются.** Если шаблон модуля (`resources/views/news/index.blade.php`, `resources/views/blocks/text.blade.php`) у сайта уже есть, остаётся ваш, и команда пишет об этом предупреждение. Общий макет `layouts/site.blade.php`, если он у вас есть, тоже остаётся вашим (предупреждение о нём — только если в нём нет `@yield('content')`: шаблоны модулей наследуют макет через `@extends('layouts.site')` и выводят страницу в секцию `content`, а макет-компонент с `{{ $slot }}` её не покажет).
- Миграции получают текущую метку времени в имени; ресурсы и другой код панели получают пространство имён разделов (`fastleo.resources.namespace`, обычно `App\Fastleo`), остальные классы — пространство имён приложения (`App`).
- **Код модулей лежит в обычных папках Laravel, как будто вы написали его сами, без подпапки `Fastleo`.** Модели — `app/Models` (`App\Models\Page`), enum — `app/Enums`, исключения — `app/Exceptions`, фабрики — `database/factories` (`Database\Factories\…`), сидеры — `database/seeders` (`Database\Seeders\…`). Публичная часть устроена так же: контроллеры `app/Http/Controllers`, запросы `app/Http/Requests`, корзина магазина `app/Http/ShopCart.php`; маршруты — блок модуля в конце `routes/web.php`; шаблоны — `resources/views/<модуль>/…`. Отдельно лежит только то, что относится к самой панели: в папке разделов (`app/Fastleo`) — ресурсы, страница настроек «Контакты», действия (`ChangeShopOrderStatus`) и `Dashboard`, а тесты модулей — в `tests/Feature/Fastleo`. Чужой код модуль не перезаписывает: если на сайте уже есть файл с таким именем (свои `App\Models\Page`, `PageController`, `PageFactory`), панельная часть не ставится вовсе, команда печатает занятые файлы и ничего не пишет; из публичной части пропускается модуль, у которого занят файл (причина печатается). Переименуйте свой файл или уберите модуль из выбора. Так же останавливает установку занятая таблица (`pages`, `news`, …). Если вы меняли `fastleo.resources.namespace`, `App\Fastleo` в примерах (ресурсы, действия) замените на своё пространство.
- Маршруты публичной части модуль дописывает в конец `routes/web.php`: обычными вызовами `Route::…` с полными именами классов, без `use` и без комментариев: ваши импорты в файле им не мешают, а сам файл остаётся вашим. Маршруты модуля узнают по именам `site.<модуль>.*` и по контроллерам модуля. Блок «Страниц» (запасной маршрут `Route::fallback`, он отвечает на «/» и любой адрес страницы) и блок «Лендинга» (`/{landing?}`, подходит под любой адрес из одного сегмента) остаются в конце файла: модули, которые вы добавляете позже, вставляются выше них (ваш код, дописанный после этих блоков, остаётся ниже; запасной маршрут Laravel всегда сопоставляет последним, а вот ваш маршрут ниже блока лендинга, подходящий под один сегмент, лендинг перекроет). Блок узнаётся, даже если Pint сократил имена классов до `use`; закомментированный блок считается отсутствующим; блок внутри вашей группы (`Route::middleware('auth')->group(…)`) считается всей группой, и новые маршруты встают выше неё. Перед записью команда проверяет, нет ли уже такой записи (тот же код маршрутов, маршрут с тем же адресом или с тем же именем): если есть, публичная часть этого модуля не добавляется, причина печатается. Команда предупреждает, если свой маршрут сайта перекроет адрес модуля (`/{slug}` забирает `/news`, `/{category}/{slug}` — страницы записей `/news/{slug}`), и если в `bootstrap/app.php` не подключён `routes/web.php` (сайт только с API). Нетронутый пример главной страницы Laravel (`Route::get('/', function () { return view('welcome'); })`, пока шаблон `welcome` стандартный) модуль «Страницы» убирает сам: из `routes/web.php` исчезает только маршрут, файл `resources/views/welcome.blade.php` остаётся; закомментированный пример, пример внутри группы маршрутов и маршрут, шаблон которого вы переписали под свой сайт (в нём нет ссылки на документацию Laravel), остаются вашими: тогда «/» отвечает ваш маршрут, а не страница «Главная». Если маршруты закешированы (`route:cache`), команда напомнит выполнить `php artisan route:clear`.
- **Модулям нужен Pest.** Вместе с модулем на сайт копируются его тесты, они написаны на Pest, поэтому без Pest (`pestphp/pest` в `composer.json` и файл `tests/Pest.php`) команда `fastleo:module` и установка с модулями отказываются работать и ничего не записывают. Поставьте его: `composer require --dev pestphp/pest pestphp/pest-plugin-laravel --with-all-dependencies`, затем `vendor/bin/pest --init` (создаёт `tests/Pest.php`) — и запустите команду снова. Тест панели — `tests/Feature/Fastleo/<Модуль>Test.php` (у модуля «Контакты» его нет: у него только страница настроек), тест публичной части — `…SiteTest.php` (только при ответе «да»).
- Виджеты модуля дописываются в `widgets()` класса `Dashboard` (`app/Fastleo/Dashboard.php`); если класса нет, он создаётся (как `fastleo:make-dashboard`). Повторная установка не дублирует виджеты. Если `Dashboard` устроен необычно и конец списка не найден, команда ничего не меняет и печатает строки, которые нужно дописать самим.
- В конце печатает список созданных файлов, предупреждения и заметки (у «Страниц» и «Магазина» есть заметки, которые печатаются, когда записана публичная часть).

## Публичная часть

Шаблоны — голая разметка без CSS и JavaScript: оформляйте их сами (исключения: встроенный `style` у скрытого поля-ловушки в форме оформления заказа — его не убирайте, иначе поле станет видно людям, — и короткий `<style>` в макете лендинга для якорей и ширины картинок). Переделывая форму оформления заказа, сохраните скрытые поля `form_token`, `shown_total` и `leave_empty`: без `form_token` заказ молча не создаётся (запрос считается ботом), без `shown_total` не работает проверка «цена изменилась», а `leave_empty` — ловушка для ботов. Шаблоны всех модулей, кроме лендинга, наследуют общий макет; у лендинга свой (см. «Лендинг»).

- **`resources/views/layouts/site.blade.php`** создаётся один раз, если такого файла нет, и общий для всех модулей. В `<head>` он выводит `<x-fastleo::seo>` (шаблоны модулей передают ему запись через `@section('seo')`, [SEO](seo.md)), в шапке — меню (`menu/header` модуля «Меню сайта», а если его нет — `pages/menu` модуля «Страницы»), затем `@yield('content')` и подвал с `menu/footer` и контактами из [настроек](settings.md). Подключите в него свой CSS и JavaScript и поменяйте разметку: оформление применится ко всем разделам сразу.
- **Шаблоны разделов** (`news/index`, `portfolio/show`, `shop/cart` …) правьте под свой дизайн: повторная установка модуля их не перезапишет.

| Модуль | Адреса сайта | Шаблоны |
|---|---|---|
| `contacts` | `/contacts` | `contacts/show` |
| `pages` | `/` и любой адрес страницы (запасной маршрут) | `pages/show`, `pages/menu`, `blocks/{text,image,gallery,cta}` |
| `landing` | `/` и адрес из одного сегмента (`/promo`) | `landing/show`, `landing/layout`, `landing/partials/{open,close,heading,button,icon}`, `landing/sections/{тип}` (19 типов блоков) |
| `news` | `/news`, `/news/{адрес}` | `news/index`, `news/show` |
| `menu` | — (меню в макете) | `menu/header`, `menu/footer`, `menu/list` |
| `reviews` | `/reviews` | `reviews/index` |
| `portfolio` | `/portfolio`, `/portfolio/{адрес}` | `portfolio/index`, `portfolio/show` |
| `faq` | `/faq` | `faq/index` |
| `services` | `/services`, `/services/{адрес}` | `services/index`, `services/show` |
| `prices` | `/prices` | `prices/index` |
| `team` | `/team`, `/team/{адрес}` | `team/index`, `team/show` |
| `branches` | `/branches` | `branches/index` |
| `certificates` | `/certificates` | `certificates/index` |
| `partners` | `/partners` | `partners/index` |
| `shop` | `/shop`, `/shop/categories/{адрес}`, `/shop/{адрес}`, `/cart`, `/checkout`, `/checkout/thanks` | `shop/index`, `shop/category`, `shop/product`, `shop/cart`, `shop/checkout`, `shop/thanks`, `shop/products` (список товаров, общая часть витрины и категории) |

Правила, общие для всех шаблонов:

- Скрытое и неопубликованное отвечает 404; адрес в маршруте — только слаг (`a-z`, цифры и дефис), остальное — 404 без запроса к базе.
- Весь вывод экранирован; как HTML выводятся только поля RichText (они очищены при сохранении). Ссылки, которые вводит пользователь панели (блок «Призыв», пункты меню), печатаются как ссылки, только если это адрес сайта (`/…`) или `http(s)://…`: `javascript:` и `//чужой-сайт` отбрасываются; у партнёров принимается только `http(s)://…`.
- Списки идут страницами: новости по 10, отзывы по 20, работы, услуги и сотрудники по 12, документы и товары по 24, партнёры по 48; ссылки «Назад» и «Дальше» — простая разметка (стандартная с иконками без CSS выглядит крупно). «Вопросы и ответы» выводят не больше 200 вопросов, «Прайс-лист» — не больше 500 позиций, «Филиалы и адреса» — не больше 200 адресов.
- Дата публикации в будущем откладывает показ только у новостей (скоуп `News::published()`), у остальных модулей показ решает галочка «Опубликована».
- Лендинг занимает адрес «/» (если у какого-то лендинга адрес «/»): главная страница «Страниц» при нём не откроется ([ниже](#лендинг)).
- Слаги разделов (`news`, `contacts`, `shop`, `services`, `prices`, `team`, `branches`, `certificates`, `partners`, …) заняты адресами модулей: страница «Страниц» с таким слагом не откроется — маршрут модуля выигрывает у запасного. Если на сайте уже есть страница `services` или `team`, не ставьте публичную часть такого модуля (ответ «нет») или переименуйте адрес страницы.

## Модули

| Имя | Что получит сайт |
|---|---|
| `contacts` | Страница настроек «Контакты» (`app/Fastleo/ContactsSettings.php`): телефон, почта, адрес, часы работы. На сайте — страница `/contacts`; значения — `fastleo_setting('contacts.phone')` и другие ключи |
| `pages` | Раздел «Страницы» (`PageResource`, адрес в панели `site-pages`): дерево с ручным порядком, заголовок, адрес, «Опубликована», «В меню сайта», «Главная», содержимое из блоков (текст, картинка, галерея, призыв), SEO. Модель `Page` со скоупом `published()`; на сайте — главная и любой адрес страницы. Подробнее — [ниже](#страницы) |
| `landing` | Раздел «Лендинг» (`LandingPageResource`, адрес `landing`): длинные страницы сайта из блоков, у каждой свой адрес («/» или «/promo») (19 типов: первый экран, преимущества, этапы, тарифы, отзывы, вопросы, форма заявки…), SEO, «Показывать на сайте». Модель `LandingPage` (`findByUrl()`, `visibleBlocks()`, `menu()`); на сайте — по адресу лендинга. Подробнее — [ниже](#лендинг) |
| `menu` | Раздел «Меню сайта» (`MenuItemResource`, адрес в панели `menu-items`): дерево пунктов с ручным порядком, название, адрес, «Шапка» или «Подвал», «Открывать в новой вкладке», «Показывать». Модель `MenuItem`: `MenuItem::tree('header')` отдаёт готовое дерево; на сайте — меню шапки и подвала в макете. Подробнее — [ниже](#меню-сайта) |
| `reviews` | Раздел «Отзывы» (`ReviewResource`, адрес `reviews`): автор, должность или компания, оценка 1–5, текст, фото, дата, «Опубликован»; порядок — перетаскиванием. Модель `Review` со скоупом `published()` |
| `portfolio` | Раздел «Портфолио» (`PortfolioResource`, адрес `portfolio`): название, адрес, категория, заказчик, дата, обложка, галерея, кратко, описание (RichText), SEO, «Опубликована»; порядок — перетаскиванием. Модель `PortfolioItem` со скоупом `published()` |
| `faq` | Раздел «Вопросы и ответы» (`FaqResource`, адрес `faq`): вопрос, ответ (RichText), необязательная группа, «Опубликован»; порядок — перетаскиванием. Модель `FaqItem` со скоупом `published()` |
| `services` | Раздел «Услуги» (`ServiceResource`, адрес `services`, группа меню «Компания»): название, адрес, категория, цена (текстом: «от 1 500 ₽»), обложка, кратко, описание (RichText), SEO, «Опубликована»; порядок — перетаскиванием. Модель `Service` со скоупом `published()`; на сайте — список и страница услуги. Подробнее — [ниже](#услуги-команда-прайс-лист-филиалы-сертификаты-партнёры) |
| `prices` | Раздел «Прайс-лист» (`PriceItemResource`, адрес `prices`, группа «Компания»): название, цена (текстом), единица («за час»), группа, примечание, «Показывать»; порядок — перетаскиванием. Модель `PriceItem` со скоупом `published()`; на сайте — таблицы по группам |
| `team` | Раздел «Команда» (`TeamMemberResource`, адрес `team`, группа «Компания»): имя, адрес, должность, стаж, фото, кратко, текст (RichText), SEO, «Опубликован»; порядок — перетаскиванием. Модель `TeamMember` со скоупом `published()`; на сайте — список и страница сотрудника |
| `branches` | Раздел «Филиалы и адреса» (`BranchResource`, адрес `branches`, группа «Компания»): название, город, адрес, телефоны (по одному в строке), почта, часы работы, широта и долгота, фото, «Показывать»; порядок — перетаскиванием. Модель `Branch`: `phoneLinks()` и `mapUrl()`; на сайте — список со ссылкой «Показать на карте» |
| `certificates` | Раздел «Документы» (лицензии и сертификаты; `CertificateResource`, адрес `certificates`, группа «Компания»): название, скан, файл PDF, дата выдачи, кем выдан, «Опубликован»; порядок — перетаскиванием. Модель `Certificate` со скоупом `published()`; на сайте — список сканов со ссылками на PDF |
| `partners` | Раздел «Партнёры и клиенты» (`PartnerResource`, адрес `partners`, группа «Компания»): название, логотип, ссылка, описание, «Показывать»; порядок — перетаскиванием. Модель `Partner` со скоупом `published()`; на сайте — логотипы со ссылками |
| `shop` | Каталог и заказы в панели: «Категории» (дерево), «Товары» (цена, остаток, фото, характеристики, SEO) и «Заказы» (статусы, «Оплачен», позиции). Модели `ShopCategory`, `ShopProduct`, `ShopOrder`, `ShopOrderItem`; `ShopOrder::place()` создаёт заказ; на сайте — каталог, корзина и оформление. Подробнее — [ниже](#интернет-магазин) |
| `news` | Раздел «Новости» (`NewsResource`, адрес `news`): заголовок, адрес, дата публикации, «Опубликована», обложка, анонс, текст (RichText), SEO; виджет «Последние новости». Модель `News` со скоупом `published()`. Дата публикации в будущем откладывает показ до этой даты (в `published()`), пустая дата — показывать сразу |

## Страницы

Модуль даёт данные, раздел панели и публичную часть: запасной маршрут `Route::fallback` отдаёт главную страницу («/») и страницу по любому адресу, который не занят другими маршрутами сайта (`PageController`, шаблон `pages/show`).

- Слаг уникален во всей таблице; адрес вложенной страницы — слаги родителей и её собственный (`about/team`): `Page::findByPath('about/team')`. Если страница или любой её родитель не опубликованы, страницы нет.
- Главная — опубликованная страница с отметкой «Главная» (`Page::home()`; родитель не важен, если отмеченных несколько — первая по номеру); по своему слагу она не открывается, только по «/». Без такой страницы адрес «/» отвечает 404. Нетронутый пример главной страницы Laravel модуль убирает из `routes/web.php` сам; **свой маршрут «/» у сайта остаётся и главную страницу модуля не показывает**.
- Шаблоны блоков (`text`, `image`, `gallery`, `cta`) лежат в `resources/views/blocks/{тип}.blade.php` ([блоки](blocks.md)): ваш шаблон блока с тем же именем остаётся вашим, новый тип блока — ещё один файл. Ссылка блока «Призыв» (`url`) проверяется при выводе: печатается адрес сайта или `http(s)://`, остальное отбрасывается.
- Меню страниц — `pages/menu` (`Page::menu()`: опубликованные страницы верхнего уровня с отметкой «В меню сайта»; блоки страниц для меню не читаются); макет показывает его, пока нет меню модуля «Меню сайта».
- Запасной маршрут отвечает только на GET и HEAD: POST на неизвестный адрес получит 405, а не 404. Путь, который не может быть страницей (`/.env`, `/wp-login.php`, не слаги), отвечает 404 без запроса к базе, но запасной маршрут в группе `web` стартует сессию на каждый несуществующий адрес: на сайте с большим посещением храните сессии в Redis (`SESSION_DRIVER=redis`) и задайте небольшой `SESSION_LIFETIME`.
- До `php artisan migrate` адрес `/` и любой адрес, похожий на страницу (`/about`), закончатся ошибкой: таблицы `pages` ещё нет (пути, которые не могут быть страницей, вроде `/favicon.ico`, отвечают 404 и без таблицы). По той же причине стандартный `tests/Feature/ExampleTest.php` нового Laravel (он открывает «/» без базы) после установки падает: добавьте в него `RefreshDatabase` и страницу с отметкой «Главная» или удалите тест.
- **Примеры.** `php artisan db:seed --class='Database\Seeders\PageSeeder'` создаёт «Главную», «О компании» и «Политику конфиденциальности» (на неё ведёт ссылка из примеров меню). Фабрика — `Page::factory()`.

## Лендинг

Раздел «Лендинг» собирает длинную страницу сайта из блоков: первый экран, преимущества, этапы работы, тарифы, отзывы, вопросы, форма заявки, контакты. Лендингов может быть несколько, у каждого своё поле **«Адрес»**: «/» — главная страница сайта, «/promo» — своя страница. Публичная часть (`LandingController`, шаблоны `resources/views/landing`) показывает лендинг по адресу запроса. Пока лендинга с таким адресом нет или он не опубликован (галочка «Показывать на сайте»), отвечает запасной маршрут сайта (например, «Страницы»), а если его нет — 404. Пример на «/» — `php artisan db:seed --class='Database\Seeders\LandingPageSeeder'`.

- **Адрес лендинга:** «/» или «/сегмент» — латиница в нижнем регистре, цифры и дефис (`/promo`, `/spring-sale`); у каждого лендинга он свой. Панель не даст сохранить повтор и адрес, который уже занят: маршрутом другого раздела сайта (`/news`, `/shop`, вход в панель: такие маршруты открываются раньше лендинга), корневой страницей «Страниц» (не главной: её адрес «/») или файлом и папкой в `public/` (`/storage`, `/build`). Если панель открыта на корне домена (`fastleo.path` пустой), её адреса (`/`, `/login`) тоже заняты. Маршруты других разделов сайта (`/news`, `/shop`) проверяются, только когда публичная часть лендинга уже поставлена: без неё панель их не знает, и проверяются файлы в `public/`, корневая страница «Страниц» и адреса панели. Слэш в конце (`/promo/`) постоянным редиректом (301) ведёт на `/promo`. Проверка идёт при создании и при смене адреса: уже сохранённый адрес не проверяется, чтобы запись не перестала сохраняться, если сайт позже получил такой маршрут. Вложенные адреса вида `/promo/spring` не поддерживаются.

**Блоки** (`app/Fastleo/LandingBlocks.php`, у каждого шаблон `resources/views/landing/sections/{тип}.blade.php`):

| Блок | Что в нём |
|---|---|
| `header` | логотип, название, телефон, кнопка; меню шапки собирается само из блоков с «Пунктом меню в шапке» |
| `hero` | надпись над заголовком, заголовок, подзаголовок, акцентная строка, короткие пункты, две кнопки, мелкий текст под кнопкой, картинка |
| `text`, `about` | заголовок и текст (RichText); `about` — ещё картинка слева или справа |
| `benefits` | карточки (иконка из списка, название, текст, кнопка) и итоговая фраза; подходит и для «болей клиента», и для списка услуг |
| `steps` | «Этапы работы» с кнопкой после них |
| `numbers`, `highlight` | цифры и факты; одна очень крупная цифра («99,9 %») с карточками |
| `pricing` | тарифы: название, цена строкой, «что входит» (пункт в строке), «Выделить», кнопка |
| `gallery`, `logos` | галерея и логотипы клиентов, партнёров, лицензий |
| `reviews`, `team` | отзывы с оценкой и фото; сотрудники |
| `faq` | вопросы и ответы (`<details>`, без JavaScript) |
| `video` | плеер по ссылке YouTube, Rutube или VK Видео |
| `cta`, `form`, `contacts`, `footer` | призыв с кнопкой; форма заявки; контакты со ссылкой «Показать на карте»; подвал со ссылками |

- **Общие поля блока** («Оформление блока», свёрнуто): `anchor` — якорь (`id` секции; ссылка `#pricing` ведёт на неё), «Пункт меню в шапке» (заполните вместе с якорем — пункт появится в меню `header`), «Фон» (светлый, серый, тёмный, акцентный → класс `landing-tone-…`) и «Скрыть блок» (блок остаётся в панели, но не выводится). Якорь — латиница в нижнем регистре, цифры и дефис, начинается с буквы, до 40 знаков; повтор якоря на странице очищается (второму блоку `id` не достаётся), у блока «Форма заявки» без якоря он `form` (у второй формы `form-2` и так далее), а «Шапка» и «Подвал» якорей и пунктов меню не имеют. Шапка и подвал выводятся по одной (первые на странице).
- **Кнопки и тема заявки.** У кнопки три поля: подпись, ссылка и «Тема заявки». Пустая ссылка ведёт к форме этого же лендинга (`/promo?topic=Тариф%20Бизнес#form`, у лендинга на «/» — `/?topic=…`), а над первой формой страницы показывается «Тема: Тариф Бизнес», и она попадает в поле **«Форма»** заявки (в списке заявок оно теперь видно): так видно, на какой тариф или услугу пришла заявка. Над формой показывается только тема, которую задаёт кнопка этой страницы (кнопка с подписью, ведущая к форме или на якорь; до 100 знаков, без невидимых символов, текст экранирован): произвольный текст из чужой ссылки (`?topic=что угодно`) не показывается и в заявку не попадает, форма запишет своё название. Тема по умолчанию: у карточки преимущества — её название, у тарифа — `Тариф «Название»`. Ссылка-якорь с темой (`#pricing`) превращается в `{адрес лендинга}?topic=…#pricing`. Ссылка в кнопке — только якорь (`#pricing`), адрес сайта (`/contacts`) или `http(s)://`: `javascript:` и `//чужой-сайт` не проходят.
- **Форма заявки** — встроенная `<x-fastleo::lead-form>` ([заявки](leads.md#форма-на-сайте)): она работает, когда заявки включены в `config/fastleo.php` (`leads.resource`); без них блок «Форма заявки» показывает только заголовок и текст. Каждая форма получает якорь блока (`id="form-{якорь}"`): после отправки посетитель остаётся у неё, а «Спасибо!» и ошибки видны только у неё. Страницу с формой не кешируйте целиком (метка формы привязана к сессии).
- **Общий макет `layouts/site`** установка кладёт и для одного лендинга (он нужен остальным модулям), но лендинг его не использует: можно удалить, если других публичных частей нет.
- **Макет** — свой, `resources/views/landing/layout.blade.php` (у лендинга обычно нет общей шапки сайта: шапка — блок). В нём только то, что нужно якорям: плавная прокрутка и отступ под шапкой (`--landing-offset`); подключите сюда свой CSS и JavaScript. Хотите общий макет сайта — замените `@extends('landing.layout')` в `landing/show.blade.php` на `layouts.site`. В макете есть и `img, iframe { max-width: 100% }`: без него широкие картинки растягивают страницу на телефоне. Классы для оформления: `landing-section`, `landing-section--{тип}`, `landing-tone-{фон}`, `landing-heading`, `landing-cards`, `landing-card`, `landing-btn`, `landing-header`, `landing-nav`.
- **Свой тип блока:** допишите `Block::make('имя', 'Подпись')->fields([...])` в `LandingBlocks::all()` и положите шаблон `landing/sections/имя.blade.php` (поля блока приходят переменными, пишите `?? ''`). Общие поля, заголовок и кнопка собирают методы `common()`, `heading()` и `button()`.
- **Число полей формы.** Блок отправляет много полей, а PHP принимает не больше `max_input_vars` (по умолчанию 1000). Поэтому на странице не больше 16 блоков, а в повторителях — до 3–10 строк; `fastleo:doctor` предупредит, если вы подняли лимиты слишком высоко. На сервере с меньшим `max_input_vars` форма раздела не сохранится: поднимите значение (хорошо — 5000).
- **Вместе со «Страницами».** Лендинг с адресом «/» занимает главную, а «Страницы» остаются для остальных адресов (`/about`, `/contacts`): главная страница «Страниц» при нём не откроется, и установщик об этом предупреждает. Нужна главная «Страниц» — не создавайте лендинг с адресом «/»: тогда «/» откроют «Страницы», а лендинги будут только на своих адресах (`/promo`). Адреса из одного сегмента, на которых нет лендинга, лендинг передаёт «Страницам» сам (запасной маршрут выполняется без своих middleware: не вешайте на него `auth`). Панель не даст занять адрес корневой страницы «Страниц» (`/about`). Обратное не проверяется: если страницу «Страниц» с адресом уже существующего лендинга создать позже, показывается лендинг.
- **Маршруты из других файлов и запасной маршрут.** Лендинг стоит в конце `routes/web.php` и забирает адреса из одного сегмента (латиница в нижнем регистре, цифры, дефис), которые сайт регистрирует в файлах, грузящихся после него (`then:` в `bootstrap/app.php`, файлы вроде `routes/admin.php`, пакеты, регистрирующие маршруты в `booted()`): такие `/blog` и `/catalog` перестанут открываться. Установщик предупреждает, если в `routes/` есть файл, не подключённый из самого `web.php` (подключённые через `require`, как `auth.php` стартовых наборов, не считаются), или в `bootstrap/app.php` есть `then:`; перенесите такие маршруты в `routes/web.php` выше блока лендинга. Тест сайта `LandingSiteTest` («does not shadow…») ловит литеральные адреса из одного сегмента, зарегистрированные после лендинга, в том числе пакетами. Если у запасного маршрута сайта (`Route::fallback`) есть middleware сверх группы `web` (`auth`, `can:…`), лендинг выполняет его без них, и любой адрес из одного сегмента откроется без этих проверок: установщик об этом предупреждает.
- **До `php artisan migrate`** таблицы `landing_pages` нет, а лендинг отвечает на адреса из одного сегмента (`/wp-login`, `/robots`): вместо 404 будет ошибка. Выполните миграцию сразу после установки.
- **Стандартный `tests/Feature/ExampleTest.php` нового Laravel** (он открывает «/» без базы) после установки падает: таблицы `landing_pages` в тестовой базе нет. Добавьте в него `RefreshDatabase` и лендинг (`LandingPage::factory()->create()`) или удалите тест.
- **Язык.** Лендинг на языке сайта: блоки не переводятся ([переводы](translations.md)), `hreflang` модуль не ставит. Двуязычному сайту нужна отдельная установка на второй язык.
- В шаблонах блоков весь вывод экранирован (как HTML выводится только RichText), `tel:` строится только из цифр (не короче 5), `mailto:` — только из настоящего адреса почты; ссылки на чужие сайты получают `rel="noopener noreferrer nofollow"`. Блок с испорченными данными пропускается, а не роняет страницу.

## Меню сайта

Модуль даёт данные, раздел панели и шаблоны меню. В списке пункты — дерево, как у «Страниц»: порядок среди соседей меняют перетаскиванием, а в другую ветку пункт переносят полем «Родитель». Пункт видит сайт, только если он и все его родители «Показываются». Общий макет подключает `menu/header` (шапка) и `menu/footer` (подвал): оба печатают дерево пунктов вложенным списком (`menu/list`). Свою разметку собирайте из того же дерева:

```blade
{{-- шапка сайта --}}
<nav>
    @foreach (\App\Models\MenuItem::tree('header') as $item)
        <a href="{{ $item->url }}" @if ($item->new_tab) target="_blank" rel="noopener" @endif>{{ $item->title }}</a>

        @foreach ($item->children as $child)
            <a href="{{ $child->url }}">{{ $child->title }}</a>
        @endforeach
    @endforeach
</nav>
```

- В шаблонах адрес пункта проверяется при выводе ещё раз: если это не адрес сайта и не `http(s)://` (запись добавили мимо формы), печатается название без ссылки; при «Открывать в новой вкладке» ставится `rel="noopener"`.
- `tree('footer')` — меню подвала. Один запрос на всё меню, `children` заполнены на любую глубину.
- Адрес в форме принимает только путь сайта (`/contacts`) или `http(s)://…`: `javascript:` и `//чужой-сайт` отклоняются. Свой адрес `/` выводите как есть.
- Родителя пункта выбирают только среди пунктов того же места («Шапка» или «Подвал»): панель не даст сохранить вложенный пункт подвала под пунктом шапки (при смене места выбор родителя сбрасывается). Если вы сами записали такой пункт в базу, на сайте он не показывается ни в шапке, ни в подвале.
- **Примеры.** `php artisan db:seed --class='Database\Seeders\MenuItemSeeder'`. Фабрика — `MenuItem::factory()`.

## Отзывы, портфолио, вопросы и ответы

Если вы ответили «да» на вопрос о публичной части, на сайте они уже подключены: `/reviews`, `/portfolio` и `/portfolio/{адрес}`, `/faq` (контроллеры `ReviewController`, `PortfolioController`, `FaqController`, шаблоны `reviews/index`, `portfolio/index`, `portfolio/show`, `faq/index`). Данные — `Review`, `PortfolioItem`, `FaqItem`, у каждого скоуп `published()` (опубликованные в порядке, заданном перетаскиванием в списке). Свой вывод собирайте так:

```php
\App\Models\Review::query()->published()->get();
\App\Models\PortfolioItem::query()->published()->paginate(12);
\App\Models\PortfolioItem::query()->published()->where('slug', $slug)->firstOrFail();
\App\Models\FaqItem::query()->published()->get()->groupBy('category'); // вопросы по группам
```

- **Отзывы:** оценка — целое число от 1 до 5; фото лежит в `storage/app/public/uploads/reviews` (`php artisan storage:link`). Выводите картинку через `<x-fastleo::picture>` ([файлы](faq/files.md)).
- **Портфолио:** обложка и галерея лежат в `storage/app/public/uploads/portfolio`; категория — обычная строка (`where('category', 'Сайты')`); `photos` — список путей галереи (`$item->photos`); SEO — `<x-fastleo::seo :model="$item" />`.
- **Вопросы и ответы:** сначала вопросы без группы (без заголовка), затем группы в порядке первого вопроса; ответ — RichText (чистый HTML, выводите `{!! $item->answer !!}`); для разметки Schema.org соберите JSON-LD из `FaqItem::query()->published()->get()`.
- **Примеры.** `php artisan db:seed --class='Database\Seeders\ReviewSeeder'` (и `PortfolioItemSeeder`, `FaqItemSeeder` в том же пространстве имён). Фабрики — `Review::factory()` и т. д.

## Услуги, команда, прайс-лист, филиалы, сертификаты, партнёры

Шесть разделов для сайта компании. Все шесть стоят в группе меню панели «Компания» (`$group` в классе ресурса: смените или уберите, если нужно). Если вы ответили «да» на вопрос о публичной части, на сайте уже подключены `/services` и `/services/{адрес}`, `/prices`, `/team` и `/team/{адрес}`, `/branches`, `/certificates`, `/partners` (контроллеры `ServiceController`, `PriceController`, `TeamController`, `BranchController`, `CertificateController`, `PartnerController`). Данные — `Service`, `PriceItem`, `TeamMember`, `Branch`, `Certificate`, `Partner`, у каждого скоуп `published()` (опубликованные в порядке, заданном перетаскиванием в списке). Свой вывод собирайте так:

```php
\App\Models\Service::query()->published()->paginate(12);
\App\Models\Service::query()->published()->where('slug', $slug)->firstOrFail();
\App\Models\PriceItem::query()->published()->get()->groupBy('category'); // позиции по группам
\App\Models\TeamMember::query()->published()->get();
\App\Models\Branch::query()->published()->get();
\App\Models\Certificate::query()->published()->get();
\App\Models\Partner::query()->published()->get();
```

- **Услуги и команда:** у записи есть адрес, кратко, описание (RichText, чистый HTML — выводите `{!! $item->body !!}`) и SEO (`<x-fastleo::seo :model="$item" />`); обложка и фото лежат в `storage/app/public/uploads/services` и `uploads/team`. Цена услуги и стаж сотрудника — обычные строки: пишите их так, как их должны увидеть посетители («от 1 500 ₽», «Стаж 12 лет»), поэтому по цене нельзя сортировать и фильтровать. Нужна числовая цена — добавьте колонку своей миграцией: код модуля принадлежит сайту.
- **Прайс-лист:** одна таблица, группа — обычная строка (как у «Вопросов и ответов»): позиции без группы идут первыми без заголовка, затем группы в порядке первой позиции. Цена и единица — строки («от 2 000 ₽», «за час»).
- **Филиалы и адреса:** телефоны — по одному в строке (на сайте не больше десяти); `$branch->phoneLinks()` отдаёт список `['text' => …, 'tel' => …]` для ссылок `tel:`; в `tel` идёт только первый номер строки, поэтому подпись («Бухгалтерия:») и добавочный («доб. 12») в звонок не попадают. Почта печатается ссылкой `mailto:` только обычным адресом, без `?`, `&`, `=`, `#` и `%` (иначе в письмо добавились бы лишние получатели и тема). Ссылка «Показать на карте» — `$branch->mapUrl()`: Яндекс.Карты по широте и долготе, если заданы обе, иначе поиск по городу и адресу; ни iframe, ни чужих скриптов в шаблоне нет. В Яндекс.Картах порядок «долгота, широта», а поля в панели — «широта» и «долгота» отдельно.
- **Лицензии и сертификаты** (в панели раздел называется «Документы»: так подпись помещается в боковое меню): скан (картинка) и, по желанию, файл PDF в `storage/app/public/uploads/certificates`. Снятая с публикации запись пропадает со страницы, но её файлы лежат на публичном диске и открываются по прямому адресу тем, кто его знает: закрытые документы в этот раздел не кладите. На сайте миниатюра ведёт на PDF, а если его нет — на сам скан. Скан сохраняется с качеством и размером по `fastleo.images`, текст на документе остаётся читаемым.
- **Партнёры и клиенты:** ссылка необязательна; в панели принимается только `http(s)://`, а шаблон дополнительно печатает ссылкой только такой адрес. Ссылки идут с `rel="noopener nofollow"`: уберите `nofollow` в `resources/views/partners/index.blade.php`, если обмениваетесь ссылками с партнёрами.
- **Примеры.** `php artisan db:seed --class='Database\Seeders\ServiceSeeder'` (и `PriceItemSeeder`, `TeamMemberSeeder`, `BranchSeeder`, `CertificateSeeder`, `PartnerSeeder` в том же пространстве имён). Фабрики — `Service::factory()` и т. д.

## Интернет-магазин

Модуль `shop` даёт каталог и заказы в панели и, если вы согласились на публичную часть, весь путь покупателя: витрину, корзину, оформление заказа и страницу «Спасибо». Оплата, личные кабинеты и доставка со стоимостью в модуль не входят.

```bash
php artisan fastleo:module shop
php artisan migrate
php artisan db:seed --class='Database\Seeders\ShopSeeder'   # по желанию: категория, три товара и заказ
```

Разделы стоят в одной группе меню «Магазин»: «Заказы» (число новых — в меню), «Товары», «Категории». Таблицы — `shop_categories`, `shop_products`, `shop_orders`, `shop_order_items` (одна миграция); имена с префиксом, чтобы не пересекаться с таблицами сайта.

- **Товары.** Название, адрес, категория (одна), артикул, цена, остаток, фото, галерея, описание, характеристики («параметр — значение»), SEO. Цена — `decimal(12,2)`, в модели — строка с копейками (`'1500.00'`). **Остаток необязателен:** пусто — не учитывается (услуга, товар под заказ), число — заказ списывает его сам. Порядок на сайте — перетаскиванием в списке.
- **Категории.** Дерево; порядок среди соседей — перетаскиванием, вложенность — полем «Родитель». Категорию с товарами или подкатегориями удалить нельзя (панель скажет об этом): товар без категории виден покупателям, и удаление скрытой категории открыло бы её товары — сначала перенесите или удалите их.
- **Заказы.** Покупатель хранится снимком в самом заказе (имя, телефон, почта, адрес, комментарий): таблицы клиентов и личных кабинетов нет. Позиции — снимок названия, артикула и цены на момент заказа, они видны таблицей под формой и не правятся (ошибся покупатель — заказ отменяют и создают новый). Менеджер меняет **статус** (действие «Сменить статус», в том числе для выбранных), галочку «Оплачен» (дата оплаты ставится сама), контакты и заметку. Заказ вручную в панели не создаётся: только кодом сайта.
- **Статусы:** «Новый», «В работе», «Отправлен», «Выполнен», «Отменён» (`App\Enums\ShopOrderStatus`, подписи и цвета меток — в нём). «Отменён» — конечный: заказ из него не выходит, а при отмене остаток, списанный этим заказом, возвращается на склад (один раз; товарам, у которых при заказе остаток не вёлся, ничего не добавляется). Удалить можно только отменённый заказ.

### Витрина, корзина и оформление

| Адрес | Что делает |
|---|---|
| `GET /shop`, `/shop/categories/{адрес}`, `/shop/{адрес}` | каталог, категория, страница товара |
| `GET /cart` | корзина |
| `POST /cart`, `PATCH /cart/{id}`, `DELETE /cart/{id}` | добавить товар, изменить количество (0 убирает), убрать |
| `GET /checkout`, `POST /checkout`, `GET /checkout/thanks` | форма оформления, создание заказа, страница «Спасибо» |

- **Что видит покупатель.** Каталог показывает только доступные товары (`ShopProduct::available()`): опубликованные и не лежащие в скрытой категории — ни в самой, ни в родительской; товар без категории доступен. Скрытая категория скрывает и свои товары, прямая ссылка на них отвечает 404. Остаток покупателю не показывается: только «Нет в наличии».
- **Корзина** хранится в сессии (`fastleo.shop.cart`): только «номер товара → количество», цены и названия берутся из базы при каждом показе. Не больше 50 позиций и 99 штук одной позиции. Если товар скрыли, удалили или он закончился, он убирается из корзины с сообщением, а количество уменьшается до остатка, и корзина с оформлением пишут об этом покупателю; нажатие «В корзину» на товаре, которого уже нет, возвращает покупателя на ту же страницу с сообщением (страница 404 не показывается), так же видно и сообщение о лимите в 50 позиций. Изменяют корзину только запросами POST, PATCH и DELETE (ссылка «в корзину» открывалась бы предпросмотром и ботами); на них лимит 60 запросов в минуту.
- **Оформление заказа** защищено без внешних сервисов, как заявки: скрытая метка времени формы (быстрее 3 секунд и старше суток форма не принимается, чужая сессия тоже) и поле-ловушка, которое человек не заполняет (бот получает тихий переход в каталог без заказа). **Метка одноразовая**: один показ формы — один заказ, повторная или параллельная отправка той же формы заказ не создаёт (после ошибки покупателя или нехватки остатка метка освобождается). Если пока покупатель заполнял форму, товар закончился, скрыт или подорожал, заказ не оформляется: покупатель возвращается на форму с сообщением и отправляет её ещё раз уже с тем, что осталось и по новой сумме. Телефон — не меньше пяти цифр. Лимит — 5 отправок формы за 10 минут с одного адреса (считаются и отправки с ошибкой проверки). **Нужен рабочий кеш:** метка формы и лимит хранятся в кеше сайта (`CACHE_STORE`). С драйвером `null` каждый заказ отклоняется как «форма уже отправлена», с `array` одноразовость метки и лимит не держатся между запросами; для `database` нужна таблица кеша (в новом Laravel её создают миграции). `php artisan fastleo:doctor` проверяет это: `null` — ошибка, `array` — предупреждение.
- **Страница «Спасибо»** показывает только номер заказа (без имени, телефона и адреса) и открывается один раз сразу после заказа; при обновлении покупатель попадает в каталог.
- Корзина, оформление и «Спасибо» закрыты от поисковиков (`noindex`). Заказы закрыты для ИИ-агентов (MCP) и выгрузки в файл: в них имена, телефоны и адреса покупателей.

### Создание заказа: `ShopOrder::place()`

Форма оформления вызывает его сама; свой код (заказ по телефону, импорт, своя корзина) создавайте **только** так: цены и названия берутся из базы (а не из запроса покупателя), остаток списывается атомарно (два заказа одновременно не уведут его в минус), всё в одной транзакции, а пользователям панели уходит уведомление во включённых [каналах](notifications.md) (в тексте только номер и сумма; не больше 20 в минуту, сверх этого заказы лежат в разделе без уведомления; если заказ создан внутри внешней транзакции, уведомление уходит после её фиксации).

```php
use App\Models\ShopOrder;

$order = ShopOrder::place(
    ['name' => 'Иван', 'phone' => '+7 900 000-00-00', 'email' => 'ivan@example.com', 'address' => 'Тюмень, ул. Ленина, 1', 'delivery' => 'Курьер', 'comment' => 'Позвоните заранее'],
    [12 => 2, 15 => 1], // id товара => количество
);
```

Метод бросает: `App\Exceptions\OutOfStockException` (товара нет в нужном количестве; `getMessage()` можно показать покупателю: «Лампа»: в наличии 1 шт.), `ProductUnavailableException` (товар не найден, скрыт или лежит в скрытой категории; `$e->productId` — какой убрать из корзины), `OrderLimitException` (больше 100 позиций, больше 9999 штук одного товара или сумма за пределом колонки `decimal(12,2)`; `getMessage()` тоже можно показать) и `InvalidArgumentException` (пустая корзина, количество не целое или меньше 1, нет имени или телефона; `ProductUnavailableException` и `OrderLimitException` — его наследники). При любой ошибке заказ не создаётся, остаток не меняется. Телефон в заказе обрезается до 32 знаков (как поле в панели).

Свой вывод (если витрина нужна не такая):

```php
\App\Models\ShopCategory::query()->visible()->whereNull('parent_id')->get();   // видимые категории: скрытая родитель скрывает и вложенные
\App\Models\ShopProduct::query()->available()->inStock()->where('category_id', $category->id)->paginate(24);
\App\Models\ShopProduct::query()->available()->where('slug', $slug)->firstOrFail(); // $product->specs — массив «параметр => значение»
```

- **Не входит:** варианты товара (размер, цвет), клиенты и личные кабинеты, оплата через платёжные системы (сайт подключает сам и ставит «Оплачен»), скидки и промокоды, стоимость доставки, несколько валют и налоги. Валюта — подпись «₽» в ресурсах, в тексте уведомления и в шаблонах витрины, корзины и оформления (`resources/views/shop`); поменяйте в коде сайта.
- **Фото товаров** лежат в `storage/app/public/uploads/shop` (`php artisan storage:link`); выводите через `<x-fastleo::picture>` ([файлы](faq/files.md)).
- **Примеры.** `ShopSeeder`; фабрики — `ShopCategory::factory()`, `ShopProduct::factory()`, `ShopOrder::factory()` (заказ без позиций; настоящий создаёт `place()`).

## Подогнать модуль под сайт

Модуль — **стартовый код сайта**, а не зависимость: файлы копируются в ваш `app/`, `resources/` и `routes/` один раз, обновлений и точек расширения у них нет, правьте их как свои. Что менять чаще всего:

- **Другая модель данных** (новости со статусами вместо «Опубликована»): модуль даёт 10 минут экономии на каркасе. Сделайте новую миграцию `alter`, перепишите ресурс, модель и фабрику, удалите сидер модуля (`NewsSeeder`) и строку виджета в `app/Fastleo/Dashboard.php`.
- **Группа в меню панели.** Разделы модулей (`pages`, `landing`, `news`, `menu`, `reviews`, `portfolio`, `faq`) стоят без группы — в верхней части меню под «Дашбордом»; три раздела «Интернет-магазина» собраны в группу «Магазин», шесть разделов для компании (`services`, `prices`, `team`, `branches`, `certificates`, `partners`) — в группу «Компания». Порядок групп — `menu.groups` в `config/fastleo.php`. Чтобы поместить раздел в группу (существующую или новую), добавьте в его класс свойство, например `protected static ?string $group = 'Содержимое';`; порядок пунктов внутри — `$position` ([ресурсы](resources.md)).
- **Страница настроек «Контакты»**: если на сайте уже есть своя страница настроек, модуль `contacts` не ставьте — две страницы с телефоном запутают редакторов.
- **Публичная часть нужна не всем.** Сайт со своей публичной частью отвечает на вопрос «нет» и получает только разделы панели. Добавить публичную часть позже повторной командой нельзя: файлы панели уже есть, и команда остановится. Удалите модуль ([как убрать](#как-убрать-модуль)) и поставьте заново с ответом «да» либо возьмите код из `vendor/camanru/fastleo/stubs/modules/<имя>/site` и общий макет `vendor/camanru/fastleo/stubs/modules/_site` (подставьте пространства имён вместо `{{ namespace }}` и `{{ appNamespace }}`, уберите `.stub` из имён) и добавьте маршруты: содержимое `site/routes/web.php.stub` (с подставленным `{{ appNamespace }}`) допишите в конец `routes/web.php` (блок «Страниц» с `Route::fallback` держите последним), как это делает команда.
- **Оформление.** Менять нужно прежде всего общий макет `resources/views/layouts/site.blade.php`, затем шаблоны разделов. Классы CSS и скрипты в заготовки не входят.

## Сайты с модулями из 4.10.0

Версия 4.10.0 клала код модулей в подпапки `Fastleo`: модели `app/Fastleo/Models` (`App\Fastleo\Models\Page`), enum `app/Fastleo/Enums`, исключения `app/Fastleo/Exceptions`, фабрики `database/factories/Fastleo` (`Database\Factories\Fastleo`), сидеры `database/seeders/Fastleo` (`Database\Seeders\Fastleo`). Новые установки кладут всё в обычные папки, а у сайта, поставившего модули раньше, файлы остаются на старых местах и работают. Поэтому для такого сайта:

- пути в таблице «[Как убрать модуль](#как-убрать-модуль)» берите со вставкой `Fastleo` (`app/Fastleo/Models/Page.php`, `database/factories/Fastleo/PageFactory.php`);
- сидер запускайте с полным именем: `php artisan db:seed --class='Database\Seeders\Fastleo\PageSeeder'`;
- заготовки публичной части (`stubs/modules/<имя>/site`) ссылаются на `App\Models\*`, `App\Enums\*` и `App\Exceptions\*`: чтобы взять их вручную, замените эти пространства имён на `App\Fastleo\Models\*` и так далее либо перенесите файлы моделей, enum и исключений в обычные папки и поменяйте их `namespace` и `use` (для модуля с моделью `Page` — также во всех файлах, которые на неё ссылаются).

## Миграции

Модули (`pages`, `landing`, `news`, `menu`, `reviews`, `portfolio`, `faq`, `services`, `prices`, `team`, `branches`, `certificates`, `partners`, `shop`) кладут в `database/migrations` свои миграции (метка времени в имени — момент установки). Таблиц ещё нет, пока вы не выполните `php artisan migrate`; `fastleo:install` делает это за вас по вашему «да» или с `--setup`, а `fastleo:module` в конце печатает «Дальше»: выполнить `php artisan migrate` и, по желанию, добавить примеры данных (`php artisan db:seed --class='Database\Seeders\MenuItemSeeder'` — по сидеру на каждый добавленный модуль с таблицей). Миграции модулей не зависят друг от друга. Если в базе уже есть таблица с таким именем (`pages`, `landing_pages`, `news`, `menu_items`, `reviews`, `portfolio_items`, `faq_items`, `services`, `price_items`, `team_members`, `branches`, `certificates`, `partners`, `shop_categories`, `shop_products`, `shop_orders`, `shop_order_items`), модуль не ставится.

## Как убрать модуль

Модуль — обычные файлы сайта: удалите те, что перечислила команда при установке (список также виден в `git status`), и таблицу, если модуль её создавал (`php artisan migrate:rollback` для миграции модуля или `Schema::drop`). Кроме файлов, модуль оставляет следы в трёх местах:

- **`app/Fastleo/Dashboard.php`** — строки виджетов в `widgets()`: `news` — «Последние новости» (`Table`). Удалите их, иначе главная страница панели упадёт без модели.
- **`routes/web.php`** — маршруты модуля (комментариев команда не пишет): найдите их по контроллерам модуля или по именам `site.<модуль>.*` (`php artisan route:list --name=site.<модуль>`) и удалите. Пример главной страницы Laravel, который убрал модуль «Страницы» или «Лендинг», сам не возвращается.
- **`resources/views/layouts/site.blade.php`** — общий макет публичной части; уберите, когда не осталось ни одного модуля с публичной частью.

| Модуль | Файлы |
|---|---|
