# Журнал изменений

Журнал записывает, **кто, когда и что изменил в админке**: «было → стало» по каждому полю, копию удалённой записи. Из журнала можно вернуть прежние значения или восстановить удалённое.

## Что попадает в журнал

- Всё, что сделано в админке: форма, действия над записями, удаление и корзина, ручной порядок, перенос по дереву.
- **Не** попадает код сайта (счётчики просмотров, заявки с сайта, cron, консоль, очередь): запись включается только на время запроса администратора. Изменения моделей, не описанных ресурсом, тоже не пишутся.
- Импорт из файла — **одна сводная запись** (создано / обновлено / пропущено, имя файла), а не по записи на строку.
- Общий журнал и история показывают только то, что администратор видит в самом разделе: запись вне выборки `query()` или закрытая Policy `view` отображается как «запись вам недоступна» (без названия и значений), её история — 404. Значения колонок, которых нет среди полей раздела, и полей, скрытых для администратора, не выводятся («изменено (значение скрыто)»). Записи, удалённые насовсем, проверить нечем — их журнал виден всем, кто открывает раздел.
- Связи «многие ко многим» и вложенные HasMany-блоки в журнале как изменения родителя не видны (изменения самих вложенных записей — видны, если у их модели есть свой раздел).

Записи хранятся 30 дней, потом их удаляет команда `fastleo:prune` ([настройки](#настройки)).

## Где смотреть

- **Общий журнал** — пункт «Журнал» в меню (`/fastleo/activity`): фильтры по разделу и автору, по 50 записей на странице. В нём видны только разделы, которые администратору можно открывать по Policy (`viewAny`).
- **История записи** — кнопка «История» на странице просмотра и редактирования. Работает и для уже удалённой записи.

Общий журнал можно закрыть для части администраторов Gate `viewFastleoActivity`:

```php
// AppServiceProvider::boot()
Gate::define('viewFastleoActivity', fn (User $user) => $user->is_owner);
```

Пока Gate не описан, журнал виден всем администраторам. На историю записи Gate не влияет: ей нужно только право просмотра записи.

## Откат

Кнопка «Вернуть» (или «Восстановить») у записи журнала:

| Событие | Что делает откат | Нужное право |
|---|---|---|
| Изменено | Возвращает прежние значения изменённых полей | `update` |
| Удалено (корзина) | Возвращает запись из корзины | `restore` |
| Удалено навсегда / удалено без корзины | Создаёт запись заново из копии, с прежним номером | `create` |
| Возврат прежних значений | Откат отката: возвращает значения, которые были до него | `update` |
| Создано, импорт, восстановлено | Откатить нельзя (запись можно удалить обычным способом). Так же пишется возврат удалённой записи: «Создано» или «Восстановлено из корзины» | — |

Откат — обычное сохранение через Eloquent (observers сайта работают), а в журнале он отмечается событием «Возврат прежних значений». Что важно знать:

- Возвращаются **только поля, которые в разделе можно редактировать сейчас** (не `readonly`, не скрытые, колонки самой модели). Откат не обходит описание ресурса.
- Правила проверки значений при откате не повторяются: они прошли при исходном сохранении. Нарушение ограничения базы (например, уникальный ключ занят) откат не выполнит, а покажет понятную причину.
- Поля `Password` ресурса (любое имя колонки) и атрибуты `$hidden` модели в журнал не пишутся: вместо значения — «значение скрыто».
- Копия удалённой записи **не содержит скрытых атрибутов модели** (`$hidden`: пароль, токены) — такая запись создаётся без них. Для пользователей откат удаления поэтому может не сработать.
- Если запись изменялась после записи журнала и значение поля уже совпадает с прежним, откат сообщит «Значения уже такие, как были».

## Пароли и скрытые поля

Значения атрибутов из `$hidden` модели (пароли, `remember_token`) в журнал **не записываются**: видно только, что поле изменилось («изменено (значение скрыто)»). Хеш пароля нигде не сохраняется и не откатывается — если колонка называется `password` или внесена в `$hidden` модели. Поле `Password` с другим именем (например, `pin`) внесите в `$hidden` — иначе его хеш попадёт в журнал.

## Отключить журнал для раздела

```php
final class AuditLogResource extends Resource
{
    protected static bool $activity = false; // этот раздел журнал не ведёт
}
```

Раздел без журнала не имеет кнопки «История» и не показывается в общем журнале.

## Настройки

```php
// config/fastleo.php
'activity' => [
    'enabled' => true,   // false — журнал выключен совсем (страницы закрыты, записи не пишутся)
    'keep_days' => 30,   // сколько дней хранятся записи
],
```

Чистку выполняет `php artisan fastleo:prune` — пакет сам ставит её в расписание раз в сутки, поэтому на сайте должен работать `php artisan schedule:run` (cron раз в минуту). Таблица `fastleo_activity` создаётся обычным `php artisan migrate`.

## Как это устроено

Пакет слушает события Eloquent `created`, `updated`, `deleted`, `restored`, `forceDeleted` моделей разделов и пишет строку журнала в той же транзакции: если сохранение откатилось, откатилась и запись. Название записи в списке берётся из первого заполненного атрибута `title`, `name`, `heading`, `label` или `email`, иначе это `#номер`.
