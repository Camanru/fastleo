# Публикации в Telegram и Max

Записи сайта (новости, статьи, акции) можно публиковать в каналы Telegram и Max прямо из админки: боты пакета отправляют пост с текстом, картинками и кнопкой-ссылкой.

## Как включить

По умолчанию разделов «Каналы» и «Публикации» нет. Включаются в `config/fastleo.php`, оба ключа вместе:

```php
'publishing' => [
    'channels' => Fastleo\Publishing\ChannelResource::class,
    'publications' => Fastleo\Publishing\PublicationResource::class,
],
```

После этого в меню появляется **Система → Каналы**; пункт «Публикации» появляется, когда есть хотя бы один включённый канал. Кнопку «Опубликовать в каналы» в разделы сайта добавляет действие `Publish` ([ниже](#кнопка-в-разделе-сайта)) — без включённых «Публикаций» оно не показывается. Таблицы `fastleo_channels`, `fastleo_publications`, `fastleo_publication_deliveries` уже есть после `php artisan migrate`. Если конфиг закеширован, выполните `php artisan optimize`.

Нужны оба раздела: каналы без «Публикаций» некуда отправлять, а «Публикации» без каналов отправить некуда.

**Свой вариант раздела** (группа меню, подписи, права) — наследник в папке разделов сайта и его класс в ключе:

```php
// app/Fastleo/PostingChannelResource.php
namespace App\Fastleo;

use Fastleo\Publishing\ChannelResource;

final class PostingChannelResource extends ChannelResource
{
    protected static ?string $group = 'Контент';
}
```

```php
// config/fastleo.php
'publishing' => [
    'channels' => App\Fastleo\PostingChannelResource::class,
    'publications' => Fastleo\Publishing\PublicationResource::class,
],
```

Выключить — `null` в обоих ключах: встроенные разделы и кнопка `Publish` пропадут, каналы и посты останутся в таблицах. Свой класс-наследник из папки разделов сайта (`app/Fastleo`) находится и без ключа — чтобы убрать его, удалите класс или вынесите из этой папки.

## Каналы

Раздел **Система → Каналы** — куда публиковать. У канала: название, мессенджер, токен бота, номер канала и галочка «Публиковать в этот канал».

1. Создайте бота: в Telegram — у [@BotFather](https://t.me/BotFather), в Max — в разделе «Чат-боты» кабинета Max для партнёров (бота и канал в Max заводит проверенная организация). Скопируйте токен.
2. Добавьте бота в **администраторы канала** с правами публиковать, редактировать и удалять сообщения — без правки и удаления не будут работать «Обновить в каналах» и «Удалить из каналов».
3. В админке: **Каналы → Создать**, выберите мессенджер, вставьте токен и нажмите **«Найти чаты бота»** (бот должен был недавно появиться в канале: его добавили или в канале вышел пост). Номер можно вписать вручную: в Telegram — `-100…` или `@имя` канала, в Max — только число.
4. Сохраните. Пакет спросит мессенджер, что бот в канале — администратор с нужными правами; если нет, канал не сохранится, а ошибка скажет, чего не хватает. Сохраняется постоянный номер канала (вместо `@имени`, которое владелец может сменить), а пустое название берётся из мессенджера.

Повторная проверка идёт, только когда меняются мессенджер, токен или номер либо канал включают; выключить канал можно и без связи с мессенджером. Токен хранится зашифрованным и после сохранения нигде не показывается (пустое поле оставляет прежний). Раздел недоступен ИИ-агентам через MCP.

Если у канала уже есть отправленные посты, **мессенджер и номер канала менять нельзя** — иначе «Обновить» и «Удалить из каналов» попали бы в чужие сообщения. Выключите старый канал и создайте новый. Если сменить мессенджер у канала без отправленных постов, токен вводится заново.

**Адреса разделов.** «Каналы» и «Публикации» открываются по адресам `channels` и `publications`. Если у сайта уже есть свой раздел с таким адресом (например, научные публикации), встроенный не появится — молча, без ошибки, а вместе с «Публикациями» пропадёт и кнопка `Publish`. Задайте своему разделу другой `$slug` или отключите встроенный (ключи `publishing.channels` и `publishing.publications`, `null`). `php artisan fastleo:doctor` предупреждает об этом.

Это каналы для подписчиков. Служебные чаты администраторов — в разделе [«Уведомления»](notifications.md#боты-telegram-и-max).

**Max и сертификат Минцифры.** API Max подписан корневым сертификатом Минцифры, которого нет в обычных хранилищах; пакет доверяет ему только в запросах к Max (подробнее — в [уведомлениях](notifications.md#боты-telegram-и-max)).

## Публикации

Раздел **Публикации** (появляется в меню, когда есть включённый канал) — посты и журнал их отправки. Пост состоит из:

- **текста** в Markdown: `**жирный**`, `*курсив*`, `~~зачёркнутый~~`, `` `код` ``, `[ссылка](https://…)`, списки, цитаты, заголовки (станут жирными). Картинки и таблицы внутри текста в мессенджер не попадают (картинка — подписью, таблица — строками). Ссылки — только `http(s)`;
- **картинок** — до 10, из [файлового менеджера](files.md);
- **кнопки-ссылки** — текст и адрес (`http(s)`), оба или ни одного;
- **каналов**, куда отправить.

«Создать» — свободный пост; затем действие **«Отправить»**. Сохранение формы ничего не отправляет.

## Кнопка в разделе сайта

Чтобы публиковать записи раздела (новости, акции), добавьте в его ресурс действие `Publish` — замыкание собирает черновик поста из записи:

```php
use App\Models\News;
use Fastleo\Publishing\Post;
use Fastleo\Publishing\Publish;

public function actions(): array
{
    return [
        Publish::make(fn (News $news): Post => Post::make("**{$news->title}**\n\n{$news->lead}")
            ->images([$news->photo])
            ->button('Читать на сайте', route('news.show', $news))),
    ];
}
```

У записи появляется кнопка **«Опубликовать в каналы»** (в строке списка, на просмотре и в форме). Она ничего не отправляет: создаёт черновик в «Публикациях» и открывает его — админ правит текст, выбирает каналы (по умолчанию отмечены все включённые) и нажимает «Отправить». На странице публикации есть ссылка на исходную запись.

| Метод `Post` | Что задаёт |
|---|---|
| `make($markdown)` | Текст в Markdown |
| `images($paths, $disk = null)` | Картинки: пути на диске файлов админки (`fastleo.files.disk`) или на указанном диске. Пустые значения пропускаются, берутся первые 10 картинок `jpg`, `jpeg`, `png`, `webp`; пути с `..` и отсутствующие файлы пропускаются |
| `button($label, $url)` | Кнопка-ссылка под постом |

Картинки **копируются** в папку публикации `publications/{номер}` внутри корневой папки файлов (`fastleo.files.root`, диск `fastleo.files.disk`): если запись потом изменят или удалят, отложенная или повторная отправка не сломается. Папка удаляется вместе с публикацией; файлы, добавленные в галерею публикации из менеджера файлов, остаются на месте.

Кнопка видна, когда есть включённый канал, раздел «Публикации» включён и Policy модели `Fastleo\Publishing\Publication` разрешает `create` (нет Policy — разрешено всем администраторам). Для самой записи проверяется `view`. Адрес в `route()` строится от текущего запроса; если админка открыта через другой домен или прокси, задайте `APP_URL` и используйте `url()`/`URL::forceRootUrl()`, чтобы в кнопке был адрес сайта.

## Как пост выглядит в мессенджере

В Max — одно сообщение: текст, картинки и кнопка. В Telegram к альбому нельзя прикрепить кнопку, а подпись к фото — не длиннее 1024 символов, поэтому:

| Картинки и текст | Что уходит в Telegram |
|---|---|
| без картинок | одно сообщение с кнопкой |
| одна картинка, текст до 1024 символов | фото с подписью и кнопкой |
| одна картинка, текст длиннее | фото, затем текст с кнопкой |
| 2–10 картинок | альбом, затем текст с кнопкой |

Текст должен поместиться в оба лимита сразу, какие бы каналы ни были выбраны: до 4096 видимых символов для Telegram и до 4000 символов вместе с разметкой для Max — форма проверяет это при сохранении.

## Отправка и журнал

По каждому каналу — своя доставка и своя задача: в фоне, если на сайте настроена очередь, иначе сразу (тогда страница ждёт ответа мессенджеров). На странице публикации — статус каждого канала, время и ошибка. Статусы публикации: черновик, ждёт времени отправки, отправляется, опубликовано, опубликовано не во все каналы, не отправлено, «связь оборвалась — проверьте канал», удалено из каналов.

- **Повторить** — отправляет заново в каналы с ошибкой, а также в каналы, где отправка зависла (идёт дольше 10 минут: например, упал рабочий процесс очереди). Номера уже отправленных сообщений сохраняются после каждого шага, поэтому повтор продолжает с места сбоя: альбом, который уже в канале, второй раз не уходит.
- **«Связь оборвалась»** — запрос ушёл, а ответа нет: пост мог появиться. Такая доставка сама не повторяется (иначе в канале оказались бы два одинаковых поста) — проверьте канал и при необходимости нажмите «Повторить».
- Если мессенджер просит подождать (слишком часто), задача ждёт сколько сказано и повторяет.
- Что-то не дошло — автор получает [уведомление](notifications.md) в колокольчик.

## Отложенная отправка

В окне «Отправить» есть поле «Отправить в» (время — по часовому поясу админки); пусто — сразу.

- **Когда поле есть.** Только если на сайте настроена очередь, которая умеет откладывать задачи (`database`, `redis`, `sqs`…), и запущен `php artisan queue:work`. С очередью `sync` отложить нельзя — пост ушёл бы сразу. При `QUEUE_CONNECTION=null` (задачи выбрасываются) «Отправить» отказывает с объяснением.
- **Отменить.** Отложенная публикация снова станет черновиком: её можно поправить и отправить в другое время, старое ожидание ничего не отправит.
- **Правка до отправки.** Текст можно править — уйдёт последняя версия; картинки и каналы — только после отмены.
- **«Отправить сейчас».** Появляется, если время прошло больше 5 минут назад, а публикация всё ждёт (задачи очереди потерялись: очередь очистили, сервер перезапустили без сохранения очереди).
- Ожидание идёт отрезками не длиннее 15 минут (у SQS задержка больше не бывает).

## Правка и удаление в каналах

После отправки меняются только текст и кнопка; картинки и каналы — только у черновика и после неудачной отправки (Telegram не даёт пересобрать альбом).

- **Обновить в каналах** — сохранённые текст и кнопка уходят в уже опубликованные посты сразу, по каждому каналу виден результат. Если в Telegram пост ушёл фото с подписью, новый текст должен уместиться в 1024 символа подписи.
- **Удалить из каналов** — пост удаляется из всех каналов (все его сообщения: альбом и текст), публикация остаётся в журнале со статусом «Удалено из каналов». Telegram удаляет только посты моложе 48 часов — для более старых будет ошибка по каналу, удалите их в Telegram вручную.

Отправленную публикацию нельзя удалить из журнала, пока пост есть в каналах (сначала «Удалить из каналов»), а канал с публикациями — из раздела «Каналы» (его выключают).

## ИИ-агенты

Через [MCP](claude.md#mcp-сервер) агент может создать и поправить черновик, но не отправить его: «Отправить», «Повторить», «Отменить отправку», «Отправить сейчас», «Обновить в каналах» и «Удалить из каналов» запускает только человек в админке. Разделы «Каналы» и «Уведомления» агенту не видны.

## Настройки

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `publishing.channels` | `null` | Раздел «Каналы»; `null` — раздела нет. Включить — `Fastleo\Publishing\ChannelResource::class` или свой наследник |
| `publishing.publications` | `null` | Раздел «Публикации»; `null` — раздела нет. Включить — `Fastleo\Publishing\PublicationResource::class` или свой наследник |
