# Вход, профиль и восстановление пароля

Вход в панель — отдельный guard `fastleo` поверх таблицы пользователей сайта. Доступ решает метод `canAccessFastleo()` модели (см. [установку](installation.md#2-модель-пользователя)). Защита самой формы входа (лимиты, одинаковый ответ, новая сессия) — в [безопасности](security.md#вход).

## Профиль

Адрес `/fastleo/profile`, ссылка — в шапке (иконка и имя). На странице:

| Раздел | Что делает |
|---|---|
| Данные | Имя и email. Для смены email нужен текущий пароль. Email хранится в нижнем регистре — вход идёт по нему |
| Пароль | Текущий пароль + новый (правила `Password::defaults()` сайта, по умолчанию не короче 8 символов). Остальные устройства выходят, текущее остаётся |
| Где вы вошли | Устройства и адреса, с которых заходили. Кнопка «Выйти на других устройствах» (нужен пароль) завершает все остальные сеансы |

Запросы с проверкой текущего пароля ограничены: 5 в минуту на пользователя. Из-за этого перебор пароля с украденной сессией невозможен.

Профиль меняет только `name`, `email` и `password` пользователя — через явный список, поэтому поле `fastleo_admin` или любая другая колонка из формы не пишется. Модель пользователя должна иметь колонки `name` и `email`.

### Выйти на других устройствах

Работает через смену хеша пароля (его проверяет middleware `AuthenticateSession`): сеансы других устройств перестают подходить и ведут на форму входа. Это работает при любом драйвере сессий (`file`, `redis`, `database`).

## Двухфакторная защита (2FA)

Включается в профиле, раздел «Двухфакторная защита»: понадобится любое приложение-аутентификатор (Google Authenticator, 1Password, Яндекс Ключ, Aegis…).

1. Нажать «Включить» (нужен текущий пароль) — появится QR-код и ключ для ручного ввода.
2. Отсканировать QR-код, ввести шестизначный код из приложения — защита включена.
3. Сохранить **8 резервных кодов**: они показаны один раз. Каждый подходит один раз, если телефон недоступен. Новые коды выдаются в профиле (с паролем), старые при этом перестают работать.

После включения вход идёт в два шага: пароль → страница «Код подтверждения» (код из приложения или резервный код). Пока код не введён, пользователь не вошёл; состояние «пароль верен» живёт в сессии 10 минут.

Что защищает:

- **код принимается один раз**: тот же код (и код, которым подтверждали настройку) повторно не подойдёт; допуск по времени — ±30 секунд;
- **своё ограничение попыток** для кода: 5 в минуту на пару «аккаунт + IP» и 50 в час на аккаунт. Верный пароль эти счётчики не сбрасывает — только полный вход. Попытки кода входят и в общий предел входа — 20 в минуту с одного IP, общий с попытками пароля;
- **секрет шифруется** (`APP_KEY`) и лежит в отдельной таблице `fastleo_two_factor`, а не в `users`: он не попадёт в `toArray()`/JSON модели пользователя и не требует `encrypted`-каста в модели сайта. Резервные коды хранятся только как хеши;
- **сброс пароля не отключает 2FA**: после новой установки пароля код всё равно потребуется;
- вход по cookie «Запомнить меня» второй шаг не повторяет: устройство считается доверенным до конца срока cookie или смены пароля;
- включить защиту (и подтвердить настройку кодом из приложения), получить новые резервные коды и отключить её можно только с текущим паролем;
- отключить защиту можно только с текущим паролем. Потерявшему телефон и резервные коды защиту сбрасывает команда на сервере: `php artisan fastleo:user admin@site.ru --reset-two-factor` (для существующего пользователя она спросит только новый пароль — оставьте пустым, чтобы не менять; если пользователя с таким email нет, команда ничего не создаёт и сообщает об ошибке).

### Обязательная 2FA

```php
// config/fastleo.php
'auth' => [
    'two_factor_required' => true,
],
```

Пользователь без включённой защиты после входа попадает в профиль и не может открыть другие страницы, пока не настроит приложение (профиль и выход остаются доступны).

## История входов

Каждый вход пишется в таблицу `fastleo_logins`: адрес (IP), строка браузера, время первого и последнего входа. «Устройство» — это пара «IP + браузер»; повторный вход с него обновляет время, а не добавляет строку.

Если пользователь уже входил раньше, а теперь вошёл с нового устройства, ему приходит письмо «Вход в панель с нового устройства» с временем, адресом и ссылкой на профиль. Первый вход письма не вызывает. Чтобы письма работали, на сайте должна быть настроена почта (`MAIL_*`), сбой почты вход не ломает. Письмо уходит через очередь: с `QUEUE_CONNECTION=sync` — сразу.

```php
// config/fastleo.php
'auth' => [
    'new_login_mail' => true,   // false — не писать о новых устройствах
    'logins_keep_days' => 90,   // сколько дней хранится запись об устройстве
],
```

Старые записи удаляет команда `fastleo:prune`. Пакет сам ставит её в расписание раз в сутки — для этого в cron сайта должен работать `php artisan schedule:run` (так устроено расписание Laravel).

## Пользователи

Свой класс-наследник подключайте **настройкой** `fastleo.users.resource` (пример ниже), а не просто кладите его в папку разделов: иначе панель ответит ошибкой о повторном адресе `users`. Колонка роли (`role`) должна быть в `#[Fillable]` модели, иначе она не сохранится; закройте раздел Policy: [права](authorization.md#сайт-с-ролями-что-закрыть).

При включённых [ролях](roles.md) или заданном [`Fastleo::resolveOwnerUsing()`](authorization.md#владелец-и-owneronly) раздел открыт только владельцу, в форме есть поле «Роли», а последнего владельца нельзя лишить роли.

Встроенный раздел «Пользователи» (`/fastleo/users`, группа «Система») показывает только пользователей с колонкой `fastleo_admin = true` — обычные пользователи сайта в нём не видны. Раздел работает по этой колонке: если доступ в панель на сайте определён по-своему (роль в `canAccessFastleo()`), отключите раздел (`'users' => ['resource' => null]`) или наследуйте `UserResource` со своим `query()` и полями. Поля: имя, email, пароль, галочка «Доступ в панель».

- Email хранится в нижнем регистре и должен быть уникален без учёта регистра. Если пользователь с таким адресом уже есть на сайте, выдайте ему доступ командой `php artisan fastleo:user admin@site.ru`.
- Нового пользователя нельзя создать без галочки «Доступ в панель». Свой email в этом разделе менять нельзя — смените его в [профиле](#профиль): там нужен текущий пароль.
- Пароль при редактировании можно оставить пустым — он не изменится. Собственный пароль меняется в [профиле](#профиль) (в разделе поле скрыто).
- **«Удалить» удаляет пользователя сайта целиком** (строку таблицы пользователей), а не только доступ; вместе с ним удаляются его секрет 2FA, история входов, раскладка дашборда, уведомления в колокольчике и отчёты его импортов с файлами (при мягком удалении они остаются до окончательного). Публикации остаются, но без автора. Чтобы человек остался пользователем сайта, снимите галочку «Доступ в панель».
- Нельзя: удалить себя, снять доступ у себя, удалить последнего пользователя или снять с него доступ. Остальные ограничения — Policy модели пользователей ([права](authorization.md)): например, «менять может только суперадмин».
- Действие «Сбросить 2FA» у чужой записи с включённой защитой (свою защиту отключают в профиле, с паролем).
- `fastleo_admin` записывается в обход `$fillable` (доступ нельзя получить массовым присваиванием); без включённых [ролей](roles.md) и `resolveOwnerUsing()` любой пользователь, которому открыт раздел, может выдать доступ в панель кому угодно, поэтому для чувствительных сайтов закройте раздел Policy; при включённых ролях или заданном резолвере владельца раздел открыт только ему.

Настройка в `config/fastleo.php`:

```php
'users' => [
    // Fastleo\Resources\UserResource::class — встроенный раздел (по умолчанию);
    // свой класс-наследник (поменять группу, поля, подписи) или null — раздела нет.
    'resource' => Fastleo\Resources\UserResource::class,
],
```

Если на сайте уже есть свой ресурс пользователей с адресом `users`, выключите встроенный (`null`) — иначе панель сообщит о повторном адресе. После изменения на боевом сайте выполните `php artisan fastleo:cache`.

## Войти как

Владелец может временно войти в панель под другим пользователем — например, под менеджером, чтобы увидеть ровно то, что видит он, и проверить его права, — и вернуться одной кнопкой. По умолчанию выключено.

### Как включить

1. Сайт должен знать, кто владелец. Либо включите [роли](roles.md) (`php artisan fastleo:roles --owner=email`), либо назовите владельца в `AppServiceProvider::boot()` ([права](authorization.md#владелец-и-owneronly)):

    ```php
    Fastleo::resolveOwnerUsing(fn ($user): bool => $user->is_owner);
    ```

    Без этого «Войти как» не работает, а `php artisan fastleo:doctor` покажет ошибку: без понятия «владелец» войти под кем угодно мог бы любой.
2. Включите ключ в `config/fastleo.php` (при закешированном конфиге — `php artisan config:cache`):

    ```php
    'users' => [
        'impersonate' => true,
    ],
    ```

3. Проверьте: войдите владельцем → «Система» → «Пользователи» → меню строки менеджера → **«Войти как»**. Вверху должна появиться плашка «Вы вошли как …». Если кнопки нет, запустите `php artisan fastleo:doctor`.

Что нужно, чтобы кнопка была:

- Раздел «Пользователи» включён (`users.resource` не `null`). Если вы подключили свой наследник `UserResource` и переопределили `actions()`, верните оттуда `parent::actions()` или добавьте `new \Fastleo\Resources\Users\ImpersonateUser()` — иначе действия не будет (Doctor предупредит).
- Владелец может менять пользователей по [Policy](authorization.md) модели: действие, как и «Сбросить 2FA», проверяет способность `update`.

Выключить — вернуть `false` (и `php artisan config:cache`): подмены, начатые раньше, при следующем запросе завершатся.

Если сайт переопределил шаблон панели `resources/views/vendor/fastleo/components/layouts/app.blade.php`, в нём нет плашки «Вы вошли как …» с кнопкой «Вернуться»: перенесите плашку из шаблона пакета, иначе вернуться можно только через «Выйти».

### Как это работает

- Войти можно под пользователем с доступом в панель, который сам не владелец (под собой и под другим владельцем — нет). Начинает подмену только владелец.
- Вверху страницы висит плашка «Вы вошли как …» с кнопкой **«Вернуться»**; ссылка на профиль на время подмены убрана.
- Под подменой закрыто то, что записало бы данные от имени пользователя или отдало бы его учётную запись: профиль (почта, пароль, двухфакторная защита, «выйти на других устройствах»), прочтение уведомлений и сохранение раскладки главной страницы. Всё остальное работает с правами этого пользователя. Отметка «просмотрено» у записи (`$readColumn`) под подменой не ставится: открытая заявка остаётся новой для пользователя.
- Двухфакторную защиту владелец уже прошёл при входе, поэтому страницы не требуют её от пользователя, у которого она не настроена, даже при `auth.two_factor_required`.
- Входов под чужим именем — не больше 10 в минуту на владельца, дальше ответ 429.
- Подмена длится не больше часа. На каждом запросе панели пакет проверяет, что владелец на месте, всё ещё владелец и не менял пароль; если нет — выход из панели. Страницы сайта вне панели (свои проверки guard `fastleo`) видят пользователя до следующего открытия панели. Если пользователь потерял доступ в панель во время подмены, владелец не возвращается к себе, а выходит целиком — войдите заново. Выход (`Выйти`) во время подмены завершает сессию на этом устройстве и не затрагивает «запомнить меня» пользователя на его настоящих устройствах.
- Вход под пользователем не попадает в [историю входов](#история-входов), письмо «вход с нового устройства» не отправляется. Но слушатели события `Illuminate\Auth\Events\Login` самого сайта (`last_login_at` и т. п.) сработают, потому что для Laravel это обычный вход: `Login` придёт и при старте (для пользователя), и при возврате (для владельца). События `Logout` не будет; кнопка «Выйти» под подменой вызывает `logoutCurrentDevice()`, и сайт получит `Illuminate\Auth\Events\CurrentDeviceLogout`.
- Изменения записываются **от имени пользователя**: `created_by`, observers и журнал сайта увидят его. Кто на самом деле работает, скажет `Fastleo::impersonator()`: владелец или `null`, если подмены нет или она уже недействительна (вне запроса с сессией — консоль, очередь — всегда `null`). Пакет пишет в лог только начало и конец подмены (`Log::warning`, номера владельца и пользователя), не каждое действие.

```php
// В observer или Policy сайта: настоящий автор правки
$author = Fastleo::impersonator() ?? Fastleo::guard()->user();
```

В MCP «Войти как» недоступно.

## Забыли пароль

На форме входа есть ссылка «Забыли пароль?» (`/fastleo/forgot-password`).

1. Пользователь вводит email. Ответ всегда один: «Если такой пользователь есть, мы отправили ему письмо…» — по ответу нельзя узнать, есть ли такая учётная запись.
2. Письмо уходит только тем, у кого есть доступ в панель (`canAccessFastleo()`) и чья модель умеет сбрасывать пароль (`CanResetPassword`, как у стандартной `User`). Оно отправляется сразу после ответа, а не через очередь: токен ссылки не попадает в таблицу `jobs`. Обычному пользователю сайта письмо не придёт, а токен, выданный ему, не примет и форма нового пароля.
3. Ссылка действует 60 минут (`fastleo.auth.reset_minutes`), одноразовая. Новую можно запросить не чаще раза в минуту.
4. После сохранения нового пароля вход в панель не выполняется — нужно войти. Все остальные сеансы и «запомнить меня» завершаются, а часовая блокировка ввода пароля (если её заполнил посторонний) снимается; счётчик попыток кода 2FA остаётся.

Запросы ссылки ограничены: 5 в минуту с одного IP и 10 в час на один email. Ввод нового пароля по ссылке считается отдельно: 5 в минуту с одного IP (длинный случайный токен подобрать нельзя, поэтому часового лимита по email здесь нет).

Для работы нужна таблица `password_reset_tokens` (есть в стандартной миграции пользователей Laravel) и настроенная почта. Пакет регистрирует брокер паролей `fastleo` на том же провайдере пользователей, что и guard; описать свой можно в `config/auth.php`:

```php
'passwords' => [
    'fastleo' => ['provider' => 'admins', 'table' => 'password_reset_tokens', 'expire' => 30, 'throttle' => 60],
],
```

Свой брокер целиком заменяет брокер пакета: `fastleo.auth.reset_minutes` тогда не действует, срок задаёт `expire`.

**Старый сайт без `password_reset_tokens`.** В проектах на Laravel 5–9 вместо неё лежит `password_resets` (те же колонки `email`, `token`, `created_at`), а в части проектов таблицы нет вовсе. Без таблицы «Забыли пароль?» падает с ошибкой — `php artisan fastleo:doctor` показывает это ошибкой.

- Если `password_resets` пользуется сброс пароля самого сайта (`'table' => 'password_resets'` у брокера `users`), не переименовывайте её — опишите брокер панели на неё же: `'fastleo' => ['provider' => 'users', 'table' => 'password_resets', 'expire' => 60, 'throttle' => 60]` (провайдер — тот же, что у guard `fastleo`, `fastleo.auth.provider`).
- Если сайт ею не пользуется — переименуйте миграцией (`Schema::rename('password_resets', 'password_reset_tokens')`) или опишите тот же брокер.
- Если таблицы нет — создайте миграцией:

```bash
php artisan make:migration create_password_reset_tokens_table
```

```php
Schema::create('password_reset_tokens', function (Blueprint $table) {
    $table->string('email')->primary();
    $table->string('token');
    $table->timestamp('created_at')->nullable();
});
```

## Настройки

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `auth.reset_minutes` | `60` | Сколько минут действует ссылка из письма |
| `auth.two_factor_required` | `false` | Требовать двухфакторную защиту от всех пользователей |
| `auth.new_login_mail` | `true` | Писать о входе с нового устройства |
| `auth.logins_keep_days` | `90` | Сколько дней хранится история входов |
