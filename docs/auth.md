# Вход, профиль и восстановление пароля

Вход в админку — отдельный guard `fastleo` поверх таблицы пользователей сайта. Доступ решает метод `canAccessFastleo()` модели (см. [установку](installation.md#2-модель-пользователя)). Защита самой формы входа (лимиты, одинаковый ответ, новая сессия) — в [безопасности](security.md#вход).

## Профиль

Адрес `/fastleo/profile`, ссылка — в шапке (иконка и имя). На странице:

| Раздел | Что делает |
|---|---|
| Данные | Имя и email. Для смены email нужен текущий пароль. Email хранится в нижнем регистре — вход идёт по нему |
| Пароль | Текущий пароль + новый (правила `Password::defaults()` сайта, по умолчанию не короче 8 символов). Остальные устройства выходят, текущее остаётся |
| Где вы вошли | Устройства и адреса, с которых заходили. Кнопка «Выйти на других устройствах» (нужен пароль) завершает все остальные сеансы |

Запросы с проверкой текущего пароля ограничены: 5 в минуту на администратора. Из-за этого перебор пароля с украденной сессией невозможен.

Профиль меняет только `name`, `email` и `password` пользователя — через явный список, поэтому поле `fastleo_admin` или любая другая колонка из формы не пишется. Модель пользователя должна иметь колонки `name` и `email`.

### Выйти на других устройствах

Работает через смену хеша пароля (его проверяет middleware `AuthenticateSession`): сеансы других устройств перестают подходить и ведут на форму входа. Это работает при любом драйвере сессий (`file`, `redis`, `database`).

## Двухфакторная защита (2FA)

Включается в профиле, раздел «Двухфакторная защита»: понадобится любое приложение-аутентификатор (Google Authenticator, 1Password, Яндекс Ключ, Aegis…).

1. Нажать «Включить» (нужен текущий пароль) — появится QR-код и ключ для ручного ввода.
2. Отсканировать QR-код, ввести шестизначный код из приложения — защита включена.
3. Сохранить **8 резервных кодов**: они показаны один раз. Каждый подходит один раз, если телефон недоступен. Новые коды выдаются в профиле (с паролем), старые при этом перестают работать.

После включения вход идёт в два шага: пароль → страница «Код подтверждения» (код из приложения или резервный код). Пока код не введён, администратор не вошёл; состояние «пароль верен» живёт в сессии 10 минут.

Что защищает:

- **код принимается один раз**: тот же код (и код, которым подтверждали настройку) повторно не подойдёт; допуск по времени — ±30 секунд;
- **своё ограничение попыток** для кода: 5 в минуту на пару «аккаунт + IP» и 50 в час на аккаунт. Верный пароль эти счётчики не сбрасывает — только полный вход;
- **секрет шифруется** (`APP_KEY`) и лежит в отдельной таблице `fastleo_two_factor`, а не в `users`: он не попадёт в `toArray()`/JSON модели пользователя и не требует `encrypted`-каста в модели сайта. Резервные коды хранятся только как хеши;
- **сброс пароля не отключает 2FA**: после новой установки пароля код всё равно потребуется;
- вход по cookie «Запомнить меня» второй шаг не повторяет: устройство считается доверенным до конца срока cookie или смены пароля;
- включить защиту (и подтвердить настройку кодом из приложения), получить новые резервные коды и отключить её можно только с текущим паролем;
- отключить защиту можно только с текущим паролем. Потерявшему телефон и резервные коды защиту сбрасывает команда на сервере: `php artisan fastleo:user admin@site.ru --reset-two-factor` (для существующего пользователя она спросит только новый пароль — оставьте пустым, чтобы не менять; если пользователя с таким email нет, команда ничего не создаёт и сообщает об ошибке).

### Обязательная 2FA

```php
// config/fastleo.php
'auth' => [
    'two_factor_required' => true,
],
```

Администратор без включённой защиты после входа попадает в профиль и не может открыть другие страницы, пока не настроит приложение (профиль и выход остаются доступны).

## История входов

Каждый вход пишется в таблицу `fastleo_logins`: адрес (IP), строка браузера, время первого и последнего входа. «Устройство» — это пара «IP + браузер»; повторный вход с него обновляет время, а не добавляет строку.

Если администратор уже входил раньше, а теперь вошёл с нового устройства, ему приходит письмо «Вход в админку с нового устройства» с временем, адресом и ссылкой на профиль. Первый вход письма не вызывает. Чтобы письма работали, на сайте должна быть настроена почта (`MAIL_*`), сбой почты вход не ломает. Письмо уходит через очередь: с `QUEUE_CONNECTION=sync` — сразу.

```php
// config/fastleo.php
'auth' => [
    'new_login_mail' => true,   // false — не писать о новых устройствах
    'logins_keep_days' => 90,   // сколько дней хранится запись об устройстве
],
```

Старые записи удаляет команда `fastleo:prune`. Пакет сам ставит её в расписание раз в сутки — для этого в cron сайта должен работать `php artisan schedule:run` (так устроено расписание Laravel).

## Администраторы

Встроенный раздел «Администраторы» (`/fastleo/users`, группа «Система») показывает только пользователей с колонкой `fastleo_admin = true` — обычные пользователи сайта в нём не видны. Раздел работает по этой колонке: если доступ в админку на сайте определён по-своему (роль в `canAccessFastleo()`), отключите раздел (`'users' => ['resource' => null]`) или наследуйте `UserResource` со своим `query()` и полями. Поля: имя, email, пароль, галочка «Доступ в админку».

- Email хранится в нижнем регистре и должен быть уникален без учёта регистра. Если пользователь с таким адресом уже есть на сайте, выдайте ему доступ командой `php artisan fastleo:user admin@site.ru`.
- Нового администратора нельзя создать без галочки «Доступ в админку». Свой email в этом разделе менять нельзя — смените его в [профиле](#профиль): там нужен текущий пароль.
- Пароль при редактировании можно оставить пустым — он не изменится. Собственный пароль меняется в [профиле](#профиль) (в разделе поле скрыто).
- **«Удалить» удаляет пользователя сайта целиком** (строку таблицы пользователей), а не только доступ. Чтобы человек остался пользователем сайта, снимите галочку «Доступ в админку».
- Нельзя: удалить себя, снять доступ у себя, удалить последнего администратора или снять с него доступ. Остальные ограничения — Policy модели пользователей ([права](authorization.md)): например, «менять может только суперадмин».
- Действие «Сбросить 2FA» у чужой записи с включённой защитой (свою защиту отключают в профиле, с паролем).
- `fastleo_admin` записывается в обход `$fillable` (доступ нельзя получить массовым присваиванием); админ с ролью может выдать доступ любому, поэтому для чувствительных сайтов закройте раздел Policy.

Настройка в `config/fastleo.php`:

```php
'users' => [
    // Fastleo\Resources\UserResource::class — встроенный раздел (по умолчанию);
    // свой класс-наследник (поменять группу, поля, подписи) или null — раздела нет.
    'resource' => Fastleo\Resources\UserResource::class,
],
```

Если на сайте уже есть свой ресурс пользователей с адресом `users`, выключите встроенный (`null`) — иначе админка сообщит о повторном адресе. После изменения на боевом сайте выполните `php artisan fastleo:cache`.

## Забыли пароль

На форме входа есть ссылка «Забыли пароль?» (`/fastleo/forgot-password`).

1. Администратор вводит email. Ответ всегда один: «Если такой администратор есть, мы отправили ему письмо…» — по ответу нельзя узнать, есть ли такая учётная запись.
2. Письмо уходит только тем, у кого есть доступ в админку (`canAccessFastleo()`). Обычному пользователю сайта письмо не придёт, а токен, выданный ему, не примет и форма нового пароля.
3. Ссылка действует 60 минут (`fastleo.auth.reset_minutes`), одноразовая. Новую можно запросить не чаще раза в минуту.
4. После сохранения нового пароля вход в админку не выполняется — нужно войти. Все остальные сеансы и «запомнить меня» завершаются.

Запросы ограничены: 5 в минуту с одного IP и 10 в час на один email.

Для работы нужна таблица `password_reset_tokens` (есть в стандартной миграции пользователей Laravel) и настроенная почта. Пакет регистрирует брокер паролей `fastleo` на том же провайдере пользователей, что и guard; описать свой можно в `config/auth.php`:

```php
'passwords' => [
    'fastleo' => ['provider' => 'admins', 'table' => 'password_reset_tokens', 'expire' => 30, 'throttle' => 60],
],
```

Свой брокер целиком заменяет брокер пакета: `fastleo.auth.reset_minutes` тогда не действует, срок задаёт `expire`.

**Старый сайт без `password_reset_tokens`.** В проектах на Laravel 5–9 вместо неё лежит `password_resets` (те же колонки `email`, `token`, `created_at`), а в части проектов таблицы нет вовсе. Без таблицы «Забыли пароль?» падает с ошибкой — `php artisan fastleo:doctor` показывает это ошибкой.

- Если `password_resets` пользуется сброс пароля самого сайта (`'table' => 'password_resets'` у брокера `users`), не переименовывайте её — опишите брокер админки на неё же: `'fastleo' => ['provider' => 'users', 'table' => 'password_resets', 'expire' => 60, 'throttle' => 60]` (провайдер — тот же, что у guard `fastleo`, `fastleo.auth.provider`).
- Если сайт ею не пользуется — переименуйте миграцией (`Schema::rename('password_resets', 'password_reset_tokens')`) или опишите тот же брокер.
- Если таблицы нет — создайте:

```php
Schema::create('password_reset_tokens', function (Blueprint $table) {
    $table->string('email')->primary();
    $table->string('token');
    $table->timestamp('created_at')->nullable();
});
```

## Настройки

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `auth.reset_minutes` | `60` | Сколько минут действует ссылка из письма |
| `auth.two_factor_required` | `false` | Требовать двухфакторную защиту от всех администраторов |
| `auth.new_login_mail` | `true` | Писать о входе с нового устройства |
| `auth.logins_keep_days` | `90` | Сколько дней хранится история входов |
