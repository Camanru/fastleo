# Установка и обновление

## Требования

| Что | Версия |
|---|---|
| PHP | 8.4 или новее |
| Laravel | 13.32 или новее |
| База данных | MySQL, MariaDB, PostgreSQL или SQLite; тесты пакета идут на MySQL 8.4, MariaDB 11, PostgreSQL 17 и SQLite |
| PHP-расширение GD | **обязательно**, с поддержкой WebP и JPEG (картинки, миниатюры, варианты для сайта); без него любая загруженная картинка отклоняется как «не открывается»; проверка: `php -r 'var_dump(gd_info());'` или `php artisan fastleo:doctor` |
| PHP-расширение exif | рекомендуется: поворачивает фото с телефона; без него снимки остаются лежать на боку (`fastleo:doctor` предупредит) |
| PHP-расширение XMLWriter | входит в стандартную сборку PHP; рисует QR-код двухфакторной защиты |
| Очередь | не обязательна; рекомендуется любой драйвер, кроме `sync`, и запущенный `php artisan queue:work` |

Файлы, загруженные в панели, лежат на диске `public` (`storage/app/public`) — сайту нужна ссылка `php artisan storage:link`, иначе картинки не откроются. Другой диск (S3, R2) — в [настройках](configuration.md#файлы), подробно — в [docs/files.md](files.md).

Тяжёлые задачи (варианты картинок, импорт, уведомления) fastleo отправляет в очередь Laravel. С работающей очередью они выполняются в фоне. Без неё (драйвер `sync`) — прямо во время запроса: всё работает, но такие действия идут медленнее. Чтобы включить очередь, задайте `QUEUE_CONNECTION=database` (или `redis`) и держите запущенным `php artisan queue:work` (через Supervisor или systemd). С драйвером `sync` команда `fastleo:install` напомнит об этом, но завершится успешно.

## 1. Пакет

```bash
composer require camanru/fastleo
php artisan fastleo:install
```

`fastleo:install`:

- публикует `config/fastleo.php` (существующий файл не перезаписывает);
- публикует CSS/JS в `public/vendor/fastleo`;
- кладёт skill для Claude Code в `.claude/skills/fastleo` ([работа с Claude](claude.md));
- подключает модель пользователя к панели (шаг 2);
- напоминает, если очередь работает в режиме `sync`;
- спрашивает вид установки (базовая — без модулей, кастомная — с выбором) и какие [готовые модули](modules.md) добавить (контакты, страницы, лендинг, новости, меню сайта, отзывы, портфолио, вопросы и ответы, услуги, прайс-лист, команда, филиалы и адреса, лицензии и сертификаты, партнёры и клиенты, интернет-магазин), и, спросив, ставить ли [публичную часть сайта](modules.md#публичная-часть) (маршруты, контроллеры и простые шаблоны без оформления), копирует их код в сайт;
- с вашего «да» выполняет `migrate` и `storage:link`, предлагает заполнить модули примерами (кроме боевого окружения) и создать пользователя, затем запускает `fastleo:doctor`;
- показывает оставшиеся шаги.

### Опрос при установке

```
Какая установка?
 › Базовая установка: только панель, без готовых модулей
   Кастомная установка: выберу модули сам
Что будет на сайте? (пробел — отметить, Enter — дальше)     ← только при кастомной; ничего не отмечено — модулей не будет
 ◻ Контакты   ◻ Страницы   ◻ Лендинг   ◻ Новости   ◻ Меню сайта   ◻ Отзывы   ◻ Портфолио   ◻ Вопросы и ответы   ◻ Услуги   ◻ Прайс-лист   ◻ Команда   ◻ Филиалы и адреса
 ◻ Лицензии и сертификаты   ◻ Партнёры и клиенты   ◻ Интернет-магазин
Поставить и публичную часть сайта (маршруты, контроллеры, шаблоны)? Без неё модули добавят только разделы в панели.   ← после выбора модулей, до записи файлов
```

Базовая установка ставит только панель: дальше вы описываете разделы сами (под лендинг, CRM или что угодно). Кастомная показывает список готовых разделов. Если у модуля занято место в панели (файл, таблица или адрес раздела), установщик покажет, что именно мешает, и спросит список ещё раз без этого модуля — ничего не записывается, пока всё не свободно.

Вопрос про публичную часть флага не имеет: в терминале его задаёт `fastleo:module` (ответ «нет» — только разделы панели), без терминала публичная часть ставится. Остальные ответы можно передать флагами; вместе с `--no-interaction` вопросов не будет вовсе (для Claude и CI):

```bash
php artisan fastleo:install --no-interaction --type=basic
php artisan fastleo:install --no-interaction --modules=pages,news --setup --seed \
    --admin-email=admin@site.ru --admin-password=secret-pass-1
```

| Флаг | Что делает |
|---|---|
| `--type=basic` / `--type=custom` | Вид установки: без модулей или с выбором модулей (с `--type=custom` без вопросов модули задаёт `--modules`) |
| `--modules=pages,news` | Конкретные модули через запятую (имена — в [модулях](modules.md)) |
| `--no-modules` | Не добавлять модули |
| `--skill-path=…` | Папка для skill Claude (по умолчанию `.claude/skills/fastleo`) |
| `--setup` | Без вопросов выполнить `storage:link` и `migrate` (все ожидающие миграции сайта, не только модулей), но `migrate` запускается только если выбраны модули или не выполнены миграции пакета |
| `--seed` | Заполнить модули примерами (кроме боевого окружения) |
| `--admin-email`, `--admin-password` | Создать пользователя; если пользователь с таким email уже есть, ему выдаётся доступ в панель (и меняется пароль, если вы его указали) — установщик об этом предупредит |

Без вопросов (`--no-interaction`) установщик не выполняет миграции и не создаёт пользователя, пока вы не укажете флаги; модули без `--type`, `--modules` не добавляются, а выбранные ставятся вместе с публичной частью. Модуль можно добавить и позже: `php artisan fastleo:module news`.

Код выхода `1` значит одно из:

- модель пользователя подключить автоматически не получилось — подключите её вручную (шаг 2);
- неверный `--type` или `--modules` (в том числе список без единого названия, `--modules=,`), противоречащие друг другу флаги (`--type=basic` или `--no-modules` вместе с `--modules`; `--no-modules` с `--type=custom`), место под модуль занято либо на сайте нет Pest (модули копируют свои тесты на Pest: `composer require --dev pestphp/pest pestphp/pest-plugin-laravel --with-all-dependencies`, затем `vendor/bin/pest --init`; без модулей Pest не нужен);
- выполнение шага, который вы просили флагами или подтвердили, не удалось: `migrate` упал, пользователь не создан (например, пароль короче 8 знаков, или `--admin-email` указан, а миграции не выполнялись — добавьте `--setup`) или `fastleo:doctor` нашёл ошибки.

На боевом сервере (`production`) вопрос «Выполнить миграции сейчас?» по умолчанию «нет»: миграции запускаются только после явного «да» (или `--setup`), потому что `migrate` выполняет все отложенные миграции сайта, не только пакета. Вопрос «Создать пользователя сейчас?» не задаётся, если в таблице пользователей уже есть пользователь (`fastleo_admin`).

Флаг `--seed` в боевом окружении (`production`) не действует: установщик об этом предупреждает.

Если `fastleo:install` только что сам подключил модель пользователя, создание пользователя и `fastleo:doctor` выполняются отдельным процессом `php artisan`: класс модели в самом установщике уже загружен в прежнем виде, а новый процесс читает файл заново. Поэтому и на чистом сайте хватает одного запуска; вопросы пользователю задаются в вашем терминале как обычно.

Если ассеты (готовые CSS и JS панели) не опубликованы, панель открывается без стилей. При `APP_DEBUG=true` на странице появляется заметная плашка с командой `php artisan vendor:publish --tag=fastleo-assets`; на боевом сайте плашки нет. После обновления пакета публикуйте ассеты заново.

## 2. Модель пользователя

Вход в панель работает поверх обычной таблицы `users` сайта, через отдельный guard `fastleo` (guard — способ входа в `config/auth.php`; пакет добавляет свой сам, описывать его не нужно). Вход на сайте и вход в панель независимы: пользователь, вошедший на сайт, не попадает в панель, пока не войдёт в неё сам.

Кто может входить, решает метод `canAccessFastleo()` из интерфейса `Fastleo\Auth\FastleoUser`. Готовая реализация — трейт `HasFastleoAccess`: доступ есть, если в колонке `fastleo_admin` истина. Каст этой колонки к `bool` трейт задаёт сам; свой каст в модели (`$casts` или `casts()`) главнее.

`fastleo:install` подключает модель сам и пишет об этом:

```
INFO  Модель App\Models\User подключена к панели: добавлены интерфейс Fastleo\Auth\FastleoUser и трейт Fastleo\Auth\HasFastleoAccess (app/Models/User.php).
```

В файле модели появляются три правки, остальное не меняется. Так выглядит модель нового сайта на Laravel 13 после `fastleo:install` (добавленное помечено `// fastleo`):

```php
<?php

namespace App\Models;

// use Illuminate\Contracts\Auth\MustVerifyEmail;
use Database\Factories\UserFactory;
use Fastleo\Auth\FastleoUser; // fastleo
use Fastleo\Auth\HasFastleoAccess; // fastleo
use Illuminate\Database\Eloquent\Attributes\Fillable;
use Illuminate\Database\Eloquent\Attributes\Hidden;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Foundation\Auth\User as Authenticatable;
use Illuminate\Notifications\Notifiable;

#[Fillable(['name', 'email', 'password'])]
#[Hidden(['password', 'remember_token'])]
class User extends Authenticatable implements FastleoUser // fastleo: implements FastleoUser
{
    /** @use HasFactory<UserFactory> */
    use HasFactory, HasFastleoAccess, Notifiable; // fastleo: HasFastleoAccess

    /**
     * Get the attributes that should be cast.
     *
     * @return array<string, string>
     */
    protected function casts(): array
    {
        return [
            'email_verified_at' => 'datetime',
            'password' => 'hashed',
        ];
    }
}
```

Файл не трогается, если модель лежит не в папке `app` сайта (модель из пакета), файл недоступен для записи, в нём уже упоминается `FastleoUser` или `HasFastleoAccess` (модель начали подключать вручную) или класс объявлен необычно. Тогда `fastleo:install` пишет `ERROR … не подключена к панели` и завершается с кодом `1` — внесите эти три правки сами, как в примере выше. Частые ошибки при ручной правке:

- `Cannot use Illuminate\Foundation\Auth\User as Authenticatable because the name is already in use` — строку `use … as Authenticatable` добавили второй раз; оставьте одну.
- `Interface "App\Models\FastleoUser" not found` — нет строк `use Fastleo\Auth\…` вверху файла.

**Не добавляйте `fastleo_admin` в `$fillable`** и не используйте `$guarded = []` у модели пользователя: иначе форма регистрации или профиля сайта сможет дать доступ в панель. Флаг ставит команда `fastleo:user`; `fastleo:doctor` сообщает об ошибке, если `fastleo_admin` доступен для массового присваивания.

Своё правило доступа — переопределите метод:

```php
public function canAccessFastleo(): bool
{
    return $this->role === 'admin';
}
```

> **Если у вас свои роли.** Встроенный раздел «Пользователи» и уведомления `Fastleo::notifyAdmins()` по-прежнему смотрят на колонку `fastleo_admin`. Отключите раздел (`'users' => ['resource' => null]`) и задайте получателей через `Fastleo::resolveAdminsUsing()` ([уведомления](notifications.md#кто-получает-уведомления)).

Метод проверяется при входе и на каждом запросе: если доступ сняли, пользователя выкинет из панели на следующем же запросе.

Если пользователи хранятся не в провайдере `users` из `config/auth.php`, укажите свой в `fastleo.auth.provider` ([настройки](configuration.md)).

## 3. Миграция и ссылка на файлы

```bash
php artisan migrate
php artisan storage:link
```

`storage:link` создаёт ссылку `public/storage` на `storage/app/public`, где лежат загруженные в панели файлы: без неё картинки и файлы не откроются на сайте. Если ссылка уже есть (сайт её делал), повторять не нужно; `fastleo:install` напоминает о ней, только пока ссылки нет. Файлам на другом диске (S3, R2) ссылка не нужна.

**`APP_URL`.** Адреса файлов (`/storage/...`) строит диск `public` от `APP_URL`, поэтому задайте в `.env` настоящий адрес сайта. Скелет Laravel ставит `http://localhost:8000`: на другом порту или домене миниатюры в панели не откроются (если отличается только `www`, файлы открываются, но лучше настроить переадресацию на один адрес). На локальной машине с несколькими сайтами на `127.0.0.1` задайте каждому свой `SESSION_COOKIE`, иначе сайты выбивают друг у друга вход.

На сайте, где раньше стояла другая админка, `migrate` и «Забыли пароль?» могут упасть из-за старых таблиц и колонок — см. [переезд с другой панели](migrating.md).

Миграции пакета добавляют в таблицу пользователей колонку `fastleo_admin` (по умолчанию `false`) и создают служебные таблицы `fastleo_*`.

<details>
<summary>Какие таблицы создаются</summary>

- `fastleo_admin` — булева колонка с индексом в таблице модели провайдера guard `fastleo` (обычно `users`);
- `fastleo_imports` — отчёты об [импорте](import-export.md#импорт);
- `fastleo_logins` — входы и устройства;
- `fastleo_two_factor` — [2FA](auth.md);
- `fastleo_settings` — [настройки сайта](settings.md);
- `fastleo_notifications` — [уведомления](notifications.md);
- `fastleo_dashboard_layouts` — [раскладка дашборда](dashboard.md#настройка-в-панели) каждого пользователя;
- `fastleo_notification_bots`, `fastleo_channels`, `fastleo_publications`, `fastleo_publication_deliveries` — [боты уведомлений](notifications.md) и [публикации](publishing.md).

</details>

Для «Забыли пароль?» нужна таблица `password_reset_tokens` — её создаёт стандартная миграция пользователей Laravel 10+. На старом сайте её может не быть ([что делать](auth.md#забыли-пароль)).

Миграции пакета запускаются обычным `php artisan migrate`, публиковать их не нужно.

## 4. Первый пользователь панели

```bash
php artisan fastleo:user admin@site.ru
```

Команда спросит имя и пароль: действуют те же правила `Password::defaults()` сайта, что в профиле (по умолчанию не короче 8 символов), слабый пароль команда не примет. Если пользователь с таким email уже есть, ему выдаётся доступ; пароль меняется, только если ввести новый.

Без вопросов, например в скрипте развёртывания:

```bash
php artisan fastleo:user admin@site.ru --name="Иван" --password="длинный-пароль" --no-interaction
```

Пароль в опции попадает в историю команд оболочки и в список процессов — в обычной работе вводите его по запросу.

**В сидере.** `migrate:fresh --seed` стирает пользователя, поэтому на время разработки добавьте его в `DatabaseSeeder`. Пароль `password` из примера — только для разработки: на боевом сайте такой сидер не запускайте. Флаг доступа вне `$fillable`, поэтому `User::create(['fastleo_admin' => true])` его молча не запишет:

```php
User::factory()->create(['name' => 'Пользователь', 'email' => 'admin@site.ru', 'password' => 'password'])
    ->forceFill(['fastleo_admin' => true])
    ->save();
```

В тестах то же делает `$admin = tap(User::factory()->create(), fn (User $user) => $user->forceFill(['fastleo_admin' => true])->save());` (`tap` с функцией возвращает пользователя, а не результат `save()`). Состояния `admin()` у фабрики нового сайта нет: `fastleo:install` его не создаёт, добавьте сами ([testing.md](testing.md#пользователь-в-тесте)).

Вход в панель приводит email к нижнему регистру, поэтому email пользователя тоже хранится в нижнем регистре. `fastleo:user` ищет пользователя без учёта регистра и исправляет его email: если на сайте есть `Admin@Site.ru`, команда `fastleo:user admin@site.ru` выдаст доступ ему, а не создаст второго пользователя. Если в базе несколько адресов, различающихся только регистром, команда остановится с ошибкой — оставьте одного.

## 5. Вход

Откройте `https://site.ru/fastleo` — адрес по умолчанию. Панель можно перенести на свой путь, поддомен или на корень домена, если fastleo — всё приложение (CRM, бэк-офис): [где разместить](configuration.md#адрес).

Вход защищён без настройки: лимиты попыток, одинаковый ответ на любую ошибку, новая сессия после входа, заголовки безопасности. Подробно — в [безопасности](security.md#вход).

- Выход — кнопкой; он завершает и вход на сайте (сессия сбрасывается целиком).
- «Запомнить меня» держит вход 30 дней (`fastleo.auth.remember_days`).
- Лимиты попыток хранятся в кеше приложения: на нескольких серверах нужен общий кеш (Redis, база).
- Для боевого сайта включите `SESSION_SECURE_COOKIE=true` (cookie только по HTTPS) и пройдите [список для сервера](security.md#что-сделать-на-сайте).

Профиль, восстановление пароля и письма о новых устройствах — в [отдельной странице](auth.md). Для них нужны настроенная почта (`MAIL_*`) и запущенный `schedule:run` (чистка истории входов): в cron `* * * * * cd /путь/к/сайту && php artisan schedule:run >> /dev/null 2>&1`. Работает ли планировщик, показывают строка «Планировщик» в виджете «Состояние сервера» и `fastleo:doctor` (на боевом сайте).

Интерфейс панели всегда на русском, даже если у сайта другая локаль.

## Очередь `database` и `retry_after`

Скелет Laravel 13 ставит очередь `database` с `retry_after` в 90 секунд, а импорт из файла идёт задачей до часа: пока он работает, очередь выдаст ту же задачу второму обработчику, и импорт упадёт. Если в разделах есть импорт, добавьте в `.env` `DB_QUEUE_RETRY_AFTER=3700`; `fastleo:doctor` предупреждает об этом.

При разработке пакета через `path`-репозиторий (`symlink: true`) собранные ассеты в `public/vendor/fastleo` не обновляются сами: после изменений в пакете выполните `php artisan vendor:publish --tag=fastleo-assets --force`, иначе `fastleo:doctor` сообщит, что ассеты устарели.

## Очередь на хостинге с одним cron

Обычный хостинг не даёт держать `queue:work` постоянно, но cron там есть (он нужен и для `schedule:run`). Тогда очередь разбирает сам планировщик — в `routes/console.php`:

```php
use Illuminate\Support\Facades\Schedule;

Schedule::command('queue:work --stop-when-empty --max-time=3600 --tries=1 --timeout=3600')
    ->everyMinute()
    ->withoutOverlapping(65)
    ->runInBackground();
```

- `--stop-when-empty` — обработчик берёт накопившиеся задачи и завершается, следующий запуск будет через минуту; `--max-time=3600` — не дольше часа, даже если задачи всё идут;
- `withoutOverlapping(65)` — пока предыдущий обработчик работает, второй не стартует (65 минут — чуть дольше самого долгого импорта);
- `runInBackground()` — минутная задача не задерживает остальные задачи планировщика.

Драйвер очереди — `database` (`QUEUE_CONNECTION=database`, таблица `jobs`: `php artisan make:queue-table && php artisan migrate`). **`retry_after` соединения должен быть больше самой долгой задачи.** Импорт из файла идёт до часа (`3600` с), а у соединения `database` по умолчанию `retry_after` — 90 с: через полторы минуты очередь решит, что обработчик завис, выдаст ту же задачу второй раз, и долгий импорт упадёт. Поставьте в `config/queue.php` (или `DB_QUEUE_RETRY_AFTER` в `.env`; у redis — `REDIS_QUEUE_RETRY_AFTER`) значение больше `3600`, например `3700`. `fastleo:doctor` предупреждает, если на сайте есть импорт, а `retry_after` не больше часа.

## Обновление

```bash
composer update camanru/fastleo
php artisan migrate
```

CSS/JS панели обновляются сами: в `composer.json` сайта на Laravel уже есть

```json
"post-update-cmd": [
    "@php artisan vendor:publish --tag=laravel-assets --ansi --force"
]
```

и fastleo публикует свои файлы под этим тегом. Если строки нет, добавьте её или выполняйте вручную:

```bash
php artisan vendor:publish --tag=fastleo-assets --force
```

Браузер не держит старые файлы: к адресу CSS/JS добавляется время изменения файла.

На боевом сайте после обновления или добавления разделов выполните `php artisan optimize` — он, кроме прочего, кеширует список разделов панели (`fastleo:cache`).
