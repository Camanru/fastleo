# Установка и обновление

## Требования

| Что | Версия |
|---|---|
| PHP | 8.4 или новее |
| Laravel | 13 |
| База данных | MySQL 8, PostgreSQL 16+ или SQLite |
| PHP-расширение GD | с поддержкой WebP и JPEG (картинки, миниатюры, варианты для сайта); проверка: `php -r 'var_dump(gd_info());'` |
| PHP-расширение XMLWriter | входит в стандартную сборку PHP; рисует QR-код двухфакторной защиты |
| Очередь | не обязательна; рекомендуется любой драйвер, кроме `sync`, и запущенный `php artisan queue:work` |

Файлы, загруженные в админке, лежат на диске `public` (`storage/app/public`) — сайту нужна ссылка `php artisan storage:link`, иначе картинки не откроются. Другой диск (S3, R2) — в [настройках](configuration.md#файлы), подробно — в [docs/files.md](files.md).

Тяжёлые задачи (варианты картинок, импорт, уведомления) fastleo отправляет в очередь Laravel. С работающей очередью они выполняются в фоне. Без неё (драйвер `sync`) — прямо во время запроса: всё работает, но такие действия идут медленнее. Чтобы включить очередь, задайте `QUEUE_CONNECTION=database` (или `redis`) и держите запущенным `php artisan queue:work` (через Supervisor или systemd). С драйвером `sync` команда `fastleo:install` напомнит об этом, но завершится успешно.

## 1. Пакет

```bash
composer require camanru/fastleo
php artisan fastleo:install
```

`fastleo:install`:

- публикует `config/fastleo.php` (существующий файл не перезаписывает);
- публикует CSS/JS в `public/vendor/fastleo`;
- проверяет, что модель пользователя готова к входу в админку;
- напоминает, если очередь работает в режиме `sync`;
- показывает следующие шаги.

Код выхода `1` значит, что модель пользователя ещё не подключена (шаг 2).

Если ассеты не опубликованы, админка открывается без стилей. При `APP_DEBUG=true` на странице появляется заметная плашка с командой `php artisan vendor:publish --tag=fastleo-assets`; на боевом сайте плашки нет. После обновления пакета публикуйте ассеты заново.

## 2. Модель пользователя

Вход в админку работает поверх обычной таблицы `users` сайта, через отдельный guard `fastleo`. Вход на сайте и вход в админку независимы: пользователь, вошедший на сайт, не попадает в админку, пока не войдёт в неё сам.

Кто может входить, решает метод `canAccessFastleo()` из интерфейса `Fastleo\Auth\FastleoUser`. Готовая реализация — трейт `HasFastleoAccess`: доступ есть, если в колонке `fastleo_admin` истина.

```php
namespace App\Models;

use Fastleo\Auth\FastleoUser;
use Fastleo\Auth\HasFastleoAccess;
use Illuminate\Foundation\Auth\User as Authenticatable;

class User extends Authenticatable implements FastleoUser
{
    use HasFastleoAccess;

    protected function casts(): array
    {
        return [
            'password' => 'hashed',
            'fastleo_admin' => 'boolean',
        ];
    }
}
```

**Не добавляйте `fastleo_admin` в `$fillable`** и не используйте `$guarded = []` у модели пользователя: иначе форма регистрации или профиля сайта сможет выдать права администратора. Флаг ставит команда `fastleo:user`.

Своё правило доступа — переопределите метод:

```php
public function canAccessFastleo(): bool
{
    return $this->role === 'admin';
}
```

При своём правиле встроенный раздел «Администраторы» и уведомления `Fastleo::notifyAdmins()` продолжают смотреть на колонку `fastleo_admin`: отключите раздел (`'users' => ['resource' => null]`) и задайте получателей через `Fastleo::resolveAdminsUsing()` ([уведомления](notifications.md#кто-получает-уведомления)).

Метод проверяется при входе и на каждом запросе: если доступ сняли, администратора выкинет из админки на следующем же запросе.

Если пользователи хранятся не в провайдере `users` из `config/auth.php`, укажите свой в `fastleo.auth.provider` ([настройки](configuration.md)).

## 3. Миграция

```bash
php artisan migrate
```

На сайте, где раньше стояла другая админка, `migrate` и «Забыли пароль?» могут упасть из-за старых таблиц и колонок — см. [переезд с другой админки](migrating.md).

Миграции пакета добавляют в таблицу пользователей булеву колонку `fastleo_admin` (по умолчанию `false`, с индексом; таблица берётся из модели провайдера guard `fastleo`) и создают таблицы: `fastleo_imports` (отчёты об [импорте](import-export.md#импорт)), `fastleo_logins` (входы и устройства), `fastleo_two_factor` ([2FA](auth.md)), `fastleo_activity` ([журнал изменений](activity.md)), `fastleo_settings` ([настройки сайта](settings.md)), `fastleo_notifications` ([уведомления](notifications.md)), `fastleo_dashboard_layouts` ([раскладка дашборда](dashboard.md#настройка-в-админке) каждого администратора), `fastleo_notification_bots`, `fastleo_channels`, `fastleo_publications` и `fastleo_publication_deliveries` ([боты уведомлений](notifications.md) и [публикации](publishing.md)).

Для «Забыли пароль?» нужна таблица `password_reset_tokens` — её создаёт стандартная миграция пользователей Laravel 10+. На старом сайте её может не быть ([что делать](auth.md#забыли-пароль)).

Миграции пакета запускаются обычным `php artisan migrate`, публиковать их не нужно.

## 4. Администратор

```bash
php artisan fastleo:user admin@site.ru
```

Команда спросит имя и пароль (минимум 8 символов). Если пользователь с таким email уже есть, ему выдаётся доступ; пароль меняется, только если ввести новый.

Без вопросов, например в скрипте развёртывания:

```bash
php artisan fastleo:user admin@site.ru --name="Иван" --password="длинный-пароль" --no-interaction
```

Пароль в опции попадает в историю команд оболочки — в обычной работе лучше вводить его по запросу.

Вход в админку приводит email к нижнему регистру, поэтому email администратора тоже хранится в нижнем регистре. `fastleo:user` ищет пользователя без учёта регистра и исправляет его email: если на сайте есть `Admin@Site.ru`, команда `fastleo:user admin@site.ru` выдаст доступ ему, а не создаст второго пользователя. Если в базе несколько адресов, различающихся только регистром, команда остановится с ошибкой — оставьте одного.

## 5. Вход

Откройте `https://site.ru/fastleo` (адрес меняется в [настройках](configuration.md)).

Что защищает вход:

- **лимиты попыток**: 5 в минуту на пару «аккаунт + IP», 20 в минуту с одного IP, 50 в час на аккаунт с любых IP. Попытка засчитывается до проверки пароля (одновременные запросы не проходят сверх лимита), успешный вход сбрасывает счётчики аккаунта, но не счётчик IP. Лимиты хранятся в кеше приложения — на нескольких серверах нужен общий кеш (Redis, база);
- **одинаковый ответ** «Неверный email или пароль» для неверного пароля, несуществующего email и пользователя без доступа; пароль хешируется и для несуществующего email, чтобы по времени ответа нельзя было узнать, есть ли учётная запись;
- **точное совпадение email**: варианты адреса, которые база считает равными («ádmin@» и «admin@» в MySQL), не входят и не получают свой счётчик попыток;
- **новая сессия** после входа; выход — только кнопкой (POST с CSRF-токеном), сессия при этом сбрасывается целиком — вход на сайте тоже завершится;
- **смена пароля** на любом устройстве завершает вход везде;
- **«Запомнить меня»** держит вход 30 дней (`fastleo.auth.remember_days`); выход и смена пароля отменяют его;
- **заголовки** на всех страницах админки: `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `X-Robots-Tag: noindex, nofollow`, `Cache-Control: no-store, private`.

Для боевого сайта также включите `SESSION_SECURE_COOKIE=true` (cookie только по HTTPS).

Профиль, восстановление пароля и письма о новых устройствах — в [отдельной странице](auth.md). Для них нужны настроенная почта (`MAIL_*`) и запущенный `schedule:run` (чистка истории входов): в cron `* * * * * cd /путь/к/сайту && php artisan schedule:run >> /dev/null 2>&1`. Работает ли планировщик, показывают строка «Планировщик» в виджете «Состояние сервера» и `fastleo:doctor` (на боевом сайте).

Интерфейс админки всегда на русском, даже если у сайта другая локаль.

## Очередь на хостинге с одним cron

Обычный хостинг не даёт держать `queue:work` постоянно, но cron там есть (он нужен и для `schedule:run`). Тогда очередь разбирает сам планировщик — в `routes/console.php`:

```php
use Illuminate\Support\Facades\Schedule;

Schedule::command('queue:work --stop-when-empty --max-time=3600 --tries=1 --timeout=3600')
    ->everyMinute()
    ->withoutOverlapping(65)
    ->runInBackground();
```

- `--stop-when-empty` — обработчик берёт накопившиеся задачи и завершается, следующий запуск будет через минуту; `--max-time=3600` — не дольше часа, даже если задачи всё идут;
- `withoutOverlapping(65)` — пока предыдущий обработчик работает, второй не стартует (65 минут — чуть дольше самого долгого импорта);
- `runInBackground()` — минутная задача не задерживает остальные задачи планировщика.

Драйвер очереди — `database` (`QUEUE_CONNECTION=database`, таблица `jobs`: `php artisan make:queue-table && php artisan migrate`). **`retry_after` соединения должен быть больше самой долгой задачи.** Импорт из файла идёт до часа (`3600` с), а у соединения `database` по умолчанию `retry_after` — 90 с: через полторы минуты очередь решит, что обработчик завис, выдаст ту же задачу второй раз, и долгий импорт упадёт. Поставьте в `config/queue.php` (или `DB_QUEUE_RETRY_AFTER` в `.env`; у redis — `REDIS_QUEUE_RETRY_AFTER`) значение больше `3600`, например `3700`. `fastleo:doctor` предупреждает, если на сайте есть импорт, а `retry_after` не больше часа.

## Обновление

```bash
composer update camanru/fastleo
php artisan migrate
```

CSS/JS админки обновляются сами: в `composer.json` сайта на Laravel уже есть

```json
"post-update-cmd": [
    "@php artisan vendor:publish --tag=laravel-assets --ansi --force"
]
```

и fastleo публикует свои файлы под этим тегом. Если строки нет, добавьте её или выполняйте вручную:

```bash
php artisan vendor:publish --tag=fastleo-assets --force
```

Браузер не держит старые файлы: к адресу CSS/JS добавляется время изменения файла.

На боевом сайте после обновления или добавления разделов выполните `php artisan optimize` — он, кроме прочего, кеширует список разделов админки (`fastleo:cache`).
